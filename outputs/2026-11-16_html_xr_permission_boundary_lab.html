XR Permission Boundary Lab

自作の最小試作。埋め込み許可、明示的なユーザー操作、session feature の可否を別々の gate として可視化し、失敗時に「端末非対応」と決めつけない XR 起動方針を検証します。

許可された top-level 文書で、ボタン操作を起点に immersive session を要求する正常ルートです。各 gate は違う回復策を持ちます。

launch receipt
policy: allowed
intent: explicit gesture
outcome: request immersive-ar
fallback: show enter button
実機では requestSession() の失敗名、埋め込みの allow、必要 feature を個別に記録します。拒否理由を一つの「非対応」に潰さず、inline または説明 UI へ縮退します。
