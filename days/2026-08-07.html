今日の重要トピックKey topics today

  1. WebXR Plane Detection Module は `plane-detection` feature descriptor、`XRFrame.detectedPlanes`、`XRPlane.orientation`、`XRPlane.polygon`、`XRPlane.semanticLabel` を定義している。 The WebXR Plane Detection Module defines the `plane-detection` feature descriptor, `XRFrame.detectedPlanes`, `XRPlane.orientation`, `XRPlane.polygon`, and `XRPlane.semanticLabel`.
  2. Plane Detection は flat surface の集合を native XR device から受け取るため、床、壁、机への配置や吸着を raw camera pixels なしで実装する候補になる。 Plane Detection receives flat surfaces from the native XR device, making floor, wall, and table placement possible without raw camera pixels.
  3. 仕様は privacy 対策として plane polygon の detail reduction、座標の rounding / quantization、小さすぎる plane の除外を挙げている。 The specification lists privacy mitigations such as reducing plane-polygon detail, rounding or quantizing coordinates, and suppressing planes that are too small or detailed.
  4. WebXR Anchors Module は `anchors` feature descriptor と `XRFrame.createAnchor()` / `XRHitTestResult.createAnchor()` を定義し、検出面に合わせた virtual object の姿勢追跡を支える。 The WebXR Anchors Module defines the `anchors` feature descriptor plus `XRFrame.createAnchor()` and `XRHitTestResult.createAnchor()` for tracking virtual-object poses against detected surfaces.
  5. Immersive Web proposal samples には AR Plane Detection と AR Mesh Detection があり、plane hit-test と anchors の組み合わせを確認できるが、公開アーカイブの中心は今日も自作サンプルにした。 Immersive Web proposal samples include AR Plane Detection and AR Mesh Detection, useful for checking plane hit-tests and anchors while today's archive entry remains an original sample.

注目事例と何が面白いかNotable example and why it matters

今日の注目は Plane Detection が `orientation`、`polygon`、`semanticLabel` という比較的低露出な環境情報で AR 配置の多くを成立させられる点です。Raw Camera Access は pixels を読むため強い同意設計が必要ですが、ポスターを壁に置く、家具を床に置く、机上に UI を吸着させるような体験なら、plane の分類と粗い形状だけで十分な場面があります。サンプルでは wall / floor / table / ceiling の plane を模し、semantic strictness と polygon confidence から `plane-detection + anchors`、`depth-sensing`、`mesh-detection`、`camera-access` のどれに進むかを切り替えます。

Today's notable point is that Plane Detection can support many AR placement flows with relatively low-exposure environment data: `orientation`, `polygon`, and `semanticLabel`. Raw Camera Access reads pixels and therefore needs a stronger consent design, but placing posters on walls, furniture on floors, or UI on tabletops can often work with plane classification and coarse geometry alone. The sample simulates wall / floor / table / ceiling planes and routes between `plane-detection + anchors`, `depth-sensing`, `mesh-detection`, and `camera-access` from semantic strictness and polygon confidence.

The sample is a small router where moving the canvas probe checks whether it is over a floor, wall, table, or ceiling plane. Switching the filter to Floor or Wall shows how orientation gating affects placement decisions.

制作に使えそうな技術メモProduction note

実装時は `navigator.xr.requestSession("immersive-ar", { optionalFeatures: ["plane-detection", "anchors"] })` のように plane と anchor を optional で試し、体験が plane 依存なら required に上げる判断を分けます。frame ごとの `detectedPlanes` から `orientation` と `semanticLabel` を読み、polygon は面積、頂点数、変化頻度だけを使うと露出を抑えやすいです。anchor は planeSpace から求めた pose または hit-test result から作り、plane の `lastChangedTime` が頻繁に変わる場合は drift budget を上げて再配置 UI に戻します。

In implementation, try plane and anchor support as optional features, for example `navigator.xr.requestSession("immersive-ar", { optionalFeatures: ["plane-detection", "anchors"] })`, then only promote them to required when the experience truly depends on them. Read `orientation` and `semanticLabel` from frame-level `detectedPlanes`, and keep polygon usage to area, vertex count, and change frequency to limit exposure. Create anchors from a pose derived from `planeSpace` or from a hit-test result, and if a plane's `lastChangedTime` changes often, raise the drift budget and return to a repositioning UI.

サンプルデータの可能性と組み合わせSample data potential and combinations

今日のサンプルからは、probe 座標、選ばれた plane、orientation filter、semantic strictness、polygon confidence、route、feature request、fallback、anchor 数、decision log が取れます。家具配置、店舗棚割り、壁面展示、倉庫ナビ、建築採寸、教育用ラベル、AI object detection の事前 gate、同意 UI の A/B テストと組み合わせると、どの体験が raw camera なしで成立するかを説明しやすくなります。実機版では plane の頂点数や lastChangedTime を保存せず、集計値だけにすれば privacy review に回しやすいデータになります。

Today's sample yields probe coordinates, selected plane, orientation filter, semantic strictness, polygon confidence, route, feature request, fallback, anchor count, and a decision log. Combined with furniture placement, retail shelf planning, wall exhibitions, warehouse navigation, architectural measuring, educational labels, an AI object-detection pre-gate, or permission-copy A/B testing, it clarifies which experiences work without raw camera access. In a hardware version, storing only aggregate values rather than plane vertices or `lastChangedTime` would make the data easier to review for privacy.
