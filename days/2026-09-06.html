今日の重要トピックKey topics today

  1. WebXR Anchors Module は 2026-04-27 Editor's Draft として、`anchors` feature、`XRAnchor.anchorSpace`、`requestPersistentHandle()`、`delete()` を定義しています。 The WebXR Anchors Module, Editor's Draft dated 2026-04-27, defines the `anchors` feature, `XRAnchor.anchorSpace`, `requestPersistentHandle()`, and `delete()`.
  2. 同モジュールは anchor 作成を `XRFrame.createAnchor(pose, space)` と `XRHitTestResult.createAnchor()` の2経路に分け、hit-test result から real-world object に attached した anchor を作れる設計です。 The module separates anchor creation into `XRFrame.createAnchor(pose, space)` and `XRHitTestResult.createAnchor()`, allowing anchors to be attached to real-world objects via hit-test results.
  3. persistent anchor は origin ごとの UUID map として扱われ、`persistentAnchors`、`restorePersistentAnchor(uuid)`、`deletePersistentAnchor(uuid)` により復元・削除できます。 Persistent anchors are modeled as an origin-scoped UUID map and can be listed, restored, and deleted through `persistentAnchors`, `restorePersistentAnchor(uuid)`, and `deletePersistentAnchor(uuid)`.
  4. WebXR Hit Test Module は `hit-test` feature が `xr-spatial-tracking` policy に依存すること、`XRTransientInputHitTestResult` が `inputSource` と `results` を束ねることを示しています。 The WebXR Hit Test Module shows that the `hit-test` feature depends on the `xr-spatial-tracking` policy and that `XRTransientInputHitTestResult` groups `inputSource` and `results`.
  5. 今日の公開カードは外部デモではなく、このワークスペース内の `Transient Hit Anchor Ledger` と `Anchor Restore Undo Queue` の2本です。 Today's public cards focus on the original workspace samples, `Transient Hit Anchor Ledger` and `Anchor Restore Undo Queue`, not external demos.

The derivative `Anchor Restore Undo Queue` chooses restore / retry / visual fallback / delete from UUID presence, session state, restore latency, tracking confidence, and undo depth.

制作に使えそうな技術メモProduction note

実機版では `requestSession("immersive-ar", { requiredFeatures: ["hit-test", "anchors"] })` の後に transient hit-test source を作り、`frame.getHitTestResultsForTransientInput(source)` の各 group から最有力 result を選びます。hit result が十分なら `result.createAnchor()`、pose drift が大きい場合は `frame.createAnchor(pose, referenceSpace)` へ回し、promise の settle 時刻、`frame.trackedAnchors` の出現、`requestPersistentHandle()` の UUID を同じ ledger row に保存します。不要になった hit-test source は `cancel()` し、削除時は `anchor.delete()` または `deletePersistentAnchor(uuid)` を明示的に記録します。

A device-backed version should call `requestSession("immersive-ar", { requiredFeatures: ["hit-test", "anchors"] })`, create a transient hit-test source, then select the best result from each group returned by `frame.getHitTestResultsForTransientInput(source)`. Use `result.createAnchor()` when the hit result is good enough, route to `frame.createAnchor(pose, referenceSpace)` when pose drift is high, and save promise settle time, `frame.trackedAnchors` appearance, and `requestPersistentHandle()` UUID in the same ledger row. Explicitly call `cancel()` for unused hit-test sources and record `anchor.delete()` or `deletePersistentAnchor(uuid)` on removal.
