今日の重要トピックKey topics today

  1. WebXR Device API は、spatial tracking を必要とする session や reference space が `xr-spatial-tracking` permissions policy と同意要件に関係することを明示しています。 The WebXR Device API makes spatial-tracking sessions and reference spaces depend on the `xr-spatial-tracking` permissions policy and consent requirements.
  2. Permissions Policy の `document.permissionsPolicy.allowsFeature()` は、起動 UI の前で `xr-spatial-tracking` や `camera` の可否を診断する足場になります。 Permissions Policy `document.permissionsPolicy.allowsFeature()` is a useful launch UI probe for `xr-spatial-tracking` and `camera` availability.
  3. WebXR Hit Test Module は active hit test source、frame ごとの results、`XRHitTestResult.getPose()` を定義し、配置 commit の直前に pose の有無を確認する設計に向いています。 The WebXR Hit Test Module defines active hit test sources, per-frame results, and `XRHitTestResult.getPose()`, which fits a pose check immediately before placement commit.
  4. Raw Camera Access は `camera-access` feature descriptor、`XRView.camera`、`XRWebGLBinding.getCameraImage()` を通じて pose 同期 camera texture を扱うため、hit-test と同じ frame window で gate すると説明しやすくなります。 Raw Camera Access uses the `camera-access` feature descriptor, `XRView.camera`, and `XRWebGLBinding.getCameraImage()` for pose-synchronized camera texture, making it natural to gate alongside hit-test in one frame window.
  5. 今日の公開カードは外部デモではなく、このワークスペース内の `Policy Hit Camera Commit Gate` と `Permissions Policy Probe Pad` の2本です。 Today's public cards focus on the original workspace samples, `Policy Hit Camera Commit Gate` and `Permissions Policy Probe Pad`, not external demos.

注目事例と何が面白いかNotable example and why it matters

注目したのは、WebXR の起動可否、Raw Camera Access の利用可否、Hit Test の配置可否が別々の API で見えるのに、実際の AR 体験では同じ瞬間の commit 条件として説明されるべき点です。Immersive Web Samples の hit-test は frame ごとの result から reticle を置きますが、camera texture を扱う体験では、その前に policy、consent、frame freshness を同じ表で見ると不意の session block や privacy fallback を減らせます。

The notable point is that WebXR launch availability, Raw Camera Access availability, and Hit Test placement availability show up through separate APIs, but an AR experience needs to explain them as one commit condition. The Immersive Web hit-test sample places a reticle from per-frame results; when camera textures are involved, putting policy, consent, and frame freshness into the same table first reduces surprise session blocks and privacy fallbacks.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Policy Hit Camera Commit Gate` は、session mode、camera-access の required / optional、`xr-spatial-tracking` policy、camera policy、hit-test result 数、pose age、camera frame age、view alignment を動かし、`COMMIT CAMERA HIT`、`PATCH WITH FALLBACK`、`HOLD PLACEMENT`、`BLOCK` の route を出します。派生サンプル `Permissions Policy Probe Pad` は、`document.permissionsPolicy` がある環境では実値を読み、ない環境では iframe allow 属性や fallback UI の checklist として扱います。

The main sample, `Policy Hit Camera Commit Gate`, lets you adjust session mode, camera-access required/optional choice, `xr-spatial-tracking` policy, camera policy, hit-test result count, pose age, camera frame age, and view alignment, then routes to `COMMIT CAMERA HIT`, `PATCH WITH FALLBACK`, `HOLD PLACEMENT`, or `BLOCK`. The derivative `Permissions Policy Probe Pad` reads real values when `document.permissionsPolicy` is available, and otherwise acts as a checklist for iframe allow attributes and fallback UI.

制作に使えそうな技術メモProduction note

実機版では `navigator.xr.requestSession("immersive-ar", { optionalFeatures: ["hit-test", "camera-access"] })` の前に、`document.permissionsPolicy?.allowsFeature("xr-spatial-tracking")` と `allowsFeature("camera")` を確認します。`camera-access` を required にすると欠落時に session 全体を止めるため、まず optional として texture path だけを縮退する設計が扱いやすいです。hit-test は source の cancel と result の `getPose(baseSpace)` null / stale を明示的にログ化し、camera texture の frame age と同じ commit window で比較します。

A device-backed version should check `document.permissionsPolicy?.allowsFeature("xr-spatial-tracking")` and `allowsFeature("camera")` before `navigator.xr.requestSession("immersive-ar", { optionalFeatures: ["hit-test", "camera-access"] })`. Making `camera-access` required blocks the whole session when missing, so starting with optional and only degrading the texture path is easier to operate. Explicitly log hit-test source cancellation and `getPose(baseSpace)` null/stale states, then compare them against camera texture frame age in the same commit window.
