注目事例と何が面白いかNotable example and why it matters

今日の注目は、昨日扱った Plane Detection を Anchors と Hit Test へ接続するところです。Plane Detection 仕様では `XRFrame.detectedPlanes` から平面集合を読み、`polygon` や `lastChangedTime` で surface の形状と更新を見られます。一方 Anchors 仕様では、`XRHitTestResult.createAnchor()` や `XRFrame.createAnchor()` が返す anchor は、native origin として実世界に固定されるか、端末側で emulated native anchor になる可能性があります。面白いのは、平面が見えたことと anchor に渡してよいことが同じではない点です。そこで今日は、plane、hit-test、depth、anchor feature の状態を queue に載せ、作成、補正、保留、停止に分ける自作サンプルにしました。

Today's focus is connecting yesterday's Plane Detection work to Anchors and Hit Test. The Plane Detection specification exposes plane sets through `XRFrame.detectedPlanes`, with `polygon` and `lastChangedTime` showing surface shape and updates. The Anchors specification, meanwhile, allows anchors from `XRHitTestResult.createAnchor()` or `XRFrame.createAnchor()`, which may be backed by native origins or emulated native anchors depending on device support. The interesting point is that seeing a plane is not the same as being ready to hand it to anchor creation. Today's original sample therefore queues plane, hit-test, depth, and anchor feature state, then routes to create, patch, hold, or block.

制作に使えそうな技術メモProduction note

実機版では `navigator.xr.requestSession('immersive-ar', { requiredFeatures: ['plane-detection', 'anchors'], optionalFeatures: ['hit-test', 'depth-sensing'] })` のように feature を交渉し、frame ごとに `frame.detectedPlanes`、`frame.getHitTestResults()`、`frame.trackedAnchors` を同じ ledger row に載せます。`XRPlane.lastChangedTime` が新しい平面は即 anchor 化せず、数 frame の polygon stability と depth agreement を待つ方が安全です。`XRHitTestResult.createAnchor()` は hit した native entity に付く意図を伝えられるため、平面の semantic label と hit result を照合してから渡すと、free-floating anchor へ落ちた時の fallback 説明もしやすくなります。

A device-backed version can negotiate features with a call like `navigator.xr.requestSession('immersive-ar', { requiredFeatures: ['plane-detection', 'anchors'], optionalFeatures: ['hit-test', 'depth-sensing'] })`, then write `frame.detectedPlanes`, `frame.getHitTestResults()`, and `frame.trackedAnchors` into the same ledger row each frame. A plane with a fresh `XRPlane.lastChangedTime` should usually wait for a few frames of polygon stability and depth agreement before anchor creation. Since `XRHitTestResult.createAnchor()` can communicate intent to attach to the hit native entity, matching the plane semantic label with the hit result before handoff also makes fallback to free-floating anchors easier to explain.

俯瞰メモBird's-eye memo

ここ数日は policy、hit-test、anchors、depth、plane を個別に扱ってきました。今日の handoff queue は、それらを「配置してよいか」の一本道に並べる小さな整理です。Plane Detection は面の文脈、Hit Test は一点の接地、Depth Sensing は現実との整合、Anchors は持続性を担当します。平面が大きく見えても polygon が揺れているなら保留し、hit と depth が一致してから anchor に渡す、という判断が AR 体験の落ち着きを作ります。

Recent work has treated policy, hit testing, anchors, depth, and planes separately. Today's handoff queue arranges those pieces into one placement decision path. Plane Detection provides surface context, Hit Test provides point contact, Depth Sensing provides real-world agreement, and Anchors provide persistence. Even a large detected plane should be held if its polygon is jittering, then handed to anchor creation only after hit and depth agree; that decision makes AR placement feel calmer.

今日のミニ試作候補Today's mini prototype candidate

本命として採用した候補は `Plane Anchor Handoff Queue` です。何が動くか: plane source、semantic label、anchor feature、plane age、polygon stability、hit-test agreement、depth agreement、tracking confidence、active frame を操作し、anchor 作成、補正、保留、停止を判定します。次に足すなら、実機の `frame.detectedPlanes` と `XRHitTestResult.createAnchor()` の promise resolution を IndexedDB に保存し、anchor が `trackedAnchors` に入るまでの latency を測ります。派生として `Plane Polygon Jitter Heatmap` も実装しました。何が動くか: 前 frame と現在 frame の polygon を重ね、頂点移動、normal drift、area change、privacy quantization、depth cross-check から anchor delay を出します。次に足すなら、heatmap の score を本命サンプルの polygon stability へ自動入力し、平面品質が anchor handoff をどう止めるかを連動させます。

The selected main prototype is `Plane Anchor Handoff Queue`. What it does: adjusts plane source, semantic label, anchor feature, plane age, polygon stability, hit-test agreement, depth agreement, tracking confidence, and active frame, then classifies anchor creation, patching, holding, or blocking. Next addition: save real `frame.detectedPlanes` rows and `XRHitTestResult.createAnchor()` promise resolution into IndexedDB, then measure latency until anchors appear in `trackedAnchors`. The derivative `Plane Polygon Jitter Heatmap` was also implemented. What it does: overlays previous and current frame polygons, then uses vertex movement, normal drift, area change, privacy quantization, and depth cross-check to produce anchor delay. Next addition: feed the heatmap score into the main sample's polygon stability control so plane quality directly controls anchor handoff.
