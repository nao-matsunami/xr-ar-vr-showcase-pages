今日の重要トピックKey topics today

  1. XRQuadLayer は 3D 空間に置く厚みのない矩形 layer で、layers feature が必要。 XRQuadLayer is a flat spatial layer requiring the layers feature.
  2. XRCompositionLayer の redraw は compositor が再投影できない時に次の XR frame で内容を描き直す合図。 redraw signals that content must be submitted again on an XR frame.
  3. head motion と application content の変更を混同せず、描画理由を receipt 化すると負荷の説明がしやすい。 Render receipts separate head motion from application content changes.
  4. Layers API は experimental かつ対応差があるため capability probe と fallback が必要。 Layers need probing and fallbacks due to uneven availability.

注目事例と何が面白いかNotable example and why it matters

Layers API は WebGL / media layer を compositor に渡します。XRQuadLayer の redraw event は、既存 texture を再投影できないと compositor が判断した際の明示的な合図です。公式 Samples の Layers 系を参照しつつ、本命ではこの合図を UI 上の evidence として可視化しました。

制作に使えそうな技術メモProduction note

実装では immersive-vr を requiredFeatures: ['layers'] で要求し、XRWebGLBinding.createQuadLayer() の結果を session.updateRenderState({layers}) に入れます。layer の redraw listener で dirty flag を立て、XR frame 中に binding.getSubImage() の framebuffer へ描画します。対応しない端末は XRWebGLLayer の通常描画へ落とします。

Negotiate layers, mark redraw as dirty, submit a subimage on an XR frame, and fall back to XRWebGLLayer.
