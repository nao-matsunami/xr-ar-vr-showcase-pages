今日の重要トピックKey topics today

  1. WebXR Device API は XRSystem を secure context の navigator.xr として公開し、session support は開始前に確認できます。 WebXR support can be probed without starting a session.
  2. WebXR Layers は rendering layer を projection layer と分け、静的 layer の redraw と resource lifecycle を扱います。 Layers separate composition lifecycle from projection rendering.
  3. WebXR-WebGPU Binding は WebGPU texture を XR compositor に結びますが、capability probe は texture の解放時刻を示しません。 WebGPU capability is not texture-release evidence.
  4. device capability、active session、GPU completion、compositor presentation は別の観測として保存する必要があります。 Capability, session, GPU completion, and presentation need distinct receipts.

注目事例と何が面白いかNotable example and why it matters

WebXR Device API の isSessionSupported() は没入 session を始めずに support を確認でき、Layers / WebGPU を含む起動前 UI に使えます。一方で Layers の texture lifetime は compositor 側の lifecycle なので、能力値だけで『再利用可能』と判断しないことが重要です。

Safe support probes are useful, but do not prove compositor resource release.

表現・インタラクションのアイデアExpression and interaction idea

capability、frame、GPU、presentation を4色の receipt として横に置き、古い観測は灰色、未観測の presentation は amber にします。ユーザーは『使える』と『今この frame で安全』の差を短い timeline で読めます。

Color-coded receipts distinguish capability from current-frame safety.

制作に使えそうな技術メモProduction note

起動前には secure context、navigator.xr、isSessionSupported、navigator.gpu を保存し、ユーザー操作で session を開始した後に XR rAF、layer の needsRedraw / redraw、最後の submit、queue completion、presentation 観察を別 timestamp で追います。

Record preflight probes separately from active-session lifecycle timestamps.
