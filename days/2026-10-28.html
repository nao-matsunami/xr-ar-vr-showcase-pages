今日の重要トピックKey topics today

  1. XRTransientInputHitTestResult は XRInputSource ごとに hit 結果をまとめる。 Transient hit results are grouped by XRInputSource.
  2. 短命 input source は操作中だけ存在し得るため、前 frame の source を placement 根拠にしない。 Transient sources must not leak across frames.
  3. hit は候補、select は意図、anchor は空間への commit として分離する。 Hit, intent, and spatial commitment are different receipts.
  4. hit test は secure context と feature negotiation が必要で、環境把握に関する privacy 制約もある。 Hit tests require secure, privacy-aware feature negotiation.

注目事例と何が面白いかNotable example and why it matters

Hit Test Module は transient input の結果を XRInputSource 単位に束ねます。公式 Samples の Hit Test は viewer 起点の最小例ですが、短命な touch / gaze intent を扱う UI では「どの source が出した hit か」も重要です。本命ではその帰属を receipt として前面に出しました。

The Hit Test Module groups transient results by source; this sample makes that provenance visible.

表現・インタラクションのアイデアExpression and interaction idea

Color and motion expose source, hit candidate, and spatial commitment.

制作に使えそうな技術メモProduction note

immersive-ar を requiredFeatures: ['local','hit-test'] で要求した後、session.requestHitTestSourceForTransientInput({ profile, offsetRay }) を作成します。各 frame の getHitTestResultsForTransientInput(source) は inputSource と results を含むので、select event.source と同一性を確認してから result.createAnchor() を呼びます。session 終了時は source.cancel() を明示します。

Request a transient source, pair its per-frame result with the same select source, then create an anchor and cancel on teardown.
