今日の重要トピックKey topics today

  1. xr-spatial-tracking の Permissions Policy は immersive session を許可する前提になる。 Permissions Policy gates immersive sessions.
  2. 埋め込み許可、明示的なユーザー操作、端末・feature の可否は別の判断軸である。 Policy, intent, and capability are separate gates.
  3. required feature が欠けると session は開始できず、optional feature は縮退体験へ分岐できる。 Required versus optional features lead to different fallbacks.
  4. policy に阻まれた場合も端末非対応と断定せず、説明と host 側の修正経路を示す。 Policy denial is not the same as hardware absence.
  5. inline は完全な失敗画面ではなく、意思やコンテンツを残す安全な代替面になれる。 Inline can remain a useful alternative surface.

注目事例と何が面白いかNotable example and why it matters

W3C WebXR Device API は xr-spatial-tracking policy の対象外では immersive session を阻止し、inline も viewer 空間へ制限し得ると定めます。MDN は policy で止まる isSessionSupported() / requestSession() が SecurityError になり得ることを明記します。本命はこれを「端末が無い」ではなく、policy・intent・session の三段 gate として操作できる自作実験にしました。

The main prototype distinguishes policy, intent, and session conditions rather than calling every failure unsupported.

  • WebXR Device API

表現・インタラクションのアイデアExpression and interaction idea

本命は三つの gate を緑・黄・赤で切り替え、iframe allow 不足、gesture 不足、required feature 不足にそれぞれ異なる回復策を出します。派生は full immersive / reduced XR / inline の三経路を一つずつ選び、失敗理由が体験の切替文言へ変換される様子を示します。

The derivative turns capability states into three explicit experience routes.

制作に使えそうな技術メモProduction note

埋め込みでは Permissions-Policy header と iframe の allow を確認します。起動は user gesture の handler から requestSession() を呼び、requiredFeatures は成立しない場合の停止条件、optionalFeatures は無ければ縮退できる追加条件として分けます。isSessionSupported() や requestSession() の例外名を記録し、SecurityError と単なる false を同じ表示にしないのが実装上の要点です。

Keep policy, gesture, required features, and probe outcomes as separate diagnostic signals.

サンプルデータの可能性と組み合わせSample data potential and combinations

再利用できるのは policy 状態、gesture の有無、要求 feature、縮退 route、選択時刻だけです。これを CMS の埋め込み設定、遠隔支援の接続前チェック、展示端末の案内、分析用の匿名化された失敗率と組み合わせると、カメラ映像や空間データを保存せずに起動体験を改善できます。

Policy and route receipts improve onboarding without retaining camera or spatial data.

試すならこれIf you try one thing

Compare policy, gesture, and required-feature failures, then contrast optional versus required absence.

俯瞰メモBird's-eye memo

XR の起動は一つの互換性チェックではなく、文書の権限、利用者の意思、端末能力、体験側の必須条件が重なる契約です。失敗を一色の非対応メッセージに畳まず、どの主体が何を変えられるかへ翻訳すると、埋め込み・企業配布・家庭用端末の差を穏やかに扱えます。

XR launch is a multi-party contract; actionable diagnostics make it resilient across contexts.
