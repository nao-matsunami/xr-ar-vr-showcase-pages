今日の重要トピックKey topics today

  1. WebXR Anchors は session 作成時に anchors feature を要求し、inline session は anchors capable と扱われません。 Anchors are a negotiated session feature.
  2. XRFrame.createAnchor() や XRHitTestResult.createAnchor() の Promise 解決は、次 frame の trackedAnchors 観測と同義ではありません。 Creation resolution and tracked observation are separate receipts.
  3. native anchor の pose は一時的に unlocatable になり得るため、古い pose を確定値として使わない hold route が必要です。 Anchor poses can temporarily become unlocatable.
  4. persistent handle は origin に閉じた UUID ですが、UA は保存済み entries を削除できるため restore を保証しません。 Persistent handles do not guarantee restoration.

注目事例と何が面白いかNotable example and why it matters

公式 Anchors sample と Hit Test with Anchors sample は、現実空間の位置に virtual object を留める基本を示します。仕様の重要な境界は createAnchor の Promise が解決しても、anchor が trackedAnchors に現れるまで属性が完全に使えるとは限らない点です。本命ではこの短い待ちを preview と commit に分けました。

Anchor creation and tracked observation are intentionally distinct UI states.

  • Anchors module

表現・インタラクションのアイデアExpression and interaction idea

置く前は半透明の preview、tracked receipt を得た後だけ色の濃い commit marker にします。tracking が途切れたら marker を消さず amber の hold にし、復帰か re-hit が起きるまで操作結果を増やさないことで、空間の理解が変わる瞬間を説明可能にします。

Use preview, committed, and hold states rather than one binary placed state.

制作に使えそうな技術メモProduction note

immersive-ar session で anchors を requiredFeatures に要求し、frame 内で createAnchor または hit result の createAnchor を呼びます。解決後は次の XR frame の trackedAnchors を確認し、anchorSpace を getPose へ渡します。pose が null の frame は既存 pose を新しい確定値として保存せず、保持または再取得へ送ります。

Request anchors, create in an XR frame, then commit only after a tracked frame and usable pose.
