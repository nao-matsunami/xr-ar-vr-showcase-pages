今日の重要トピックKey topics today

  1. WebXR Gamepads Module は `XRInputSource.gamepad` の制約と `xr-standard` mapping を定義し、buttons[0] trigger、buttons[1] squeeze、buttons[2] touchpad、buttons[3] thumbstick、axes[0-3] touchpad / thumbstick の予約位置を示します。 The WebXR Gamepads Module defines constraints on `XRInputSource.gamepad` and the `xr-standard` mapping, including reserved positions for buttons[0] trigger, buttons[1] squeeze, buttons[2] touchpad, buttons[3] thumbstick, and axes[0-3] touchpad/thumbstick.
  2. 同仕様では任意入力がない場合でも placeholder button / axis の位置を保つため、アプリ側は配列長だけで機能有無を判断せず、0 / false の slot を fallback として扱う必要があります。 Because the spec preserves placeholder button/axis positions when optional inputs are missing, apps should not infer capability from array length alone; zero/false slots need explicit fallback handling.
  3. Input Profiles Registry と motion-controllers の `fetchProfile()` は profile id から layout / components / selectComponentId を解決する入口で、前日の fetch probe から今日の mapping cache へ自然につながります。 The Input Profiles Registry and motion-controllers `fetchProfile()` resolve layout, components, and selectComponentId from profile ids, making a natural continuation from yesterday's fetch probe into today's mapping cache.
  4. Immersive Web Samples の Controller State は gamepad attribute の可視化例、Input Selection は select / squeeze events の応答例として、slot mapping と event semantics をつなぐ参考になります。 Immersive Web's Controller State sample is useful for gamepad-attribute visualization, while Input Selection shows select/squeeze event response, linking slot mapping with event semantics.
  5. 今日の公開対象は外部サンプルではなく、このワークスペース内で作った component mapping cache と xr-standard slot replay の2本です。 Today's public focus remains on the two original workspace samples: component mapping cache and xr-standard slot replay.

注目事例と何が面白いかNotable example and why it matters

今日の注目は W3C WebXR Gamepads Module の `xr-standard` mapping と、Immersive Web の Input Profiles / motion-controllers です。面白い点は、Registry が教える component layout と、Gamepads Module が定める button / axes slot を合わせると、controller 固有名ではなく `select`、`grab`、`move`、`cursor nudge` のような semantic action に変換できることです。さらに placeholder slot を失敗ではなく仕様上の状態として扱えば、未知 controller や簡易 controller でも説明可能に縮退できます。

Today's notable references are the `xr-standard` mapping in the W3C WebXR Gamepads Module and Immersive Web's Input Profiles/motion-controllers work. The interesting part is that combining Registry component layouts with Gamepads Module button/axes slots lets apps translate device-specific controllers into semantic actions such as `select`, `grab`, `move`, and `cursor nudge`. Treating placeholder slots as a specified state rather than a failure also makes unknown or simple controllers degrade explainably.

制作に使えそうな技術メモProduction note

`XRInputSource.gamepad.mapping === "xr-standard"` の場合でも、optional な squeeze / touchpad / thumbstick が欠けることがあります。buttons / axes の予約 index と placeholder を明示的に扱い、profile component と slot の対応を cache しておくと、ネットワークが落ちた日でも最低限の action route を維持できます。実装では、profile 解決、slot coverage、placeholder hit、deadzone 後の action を別々の metric に分けると、入力不具合の原因を追いやすくなります。

Even when `XRInputSource.gamepad.mapping === "xr-standard"`, optional squeeze, touchpad, or thumbstick inputs can be absent. Explicitly handling reserved button/axes indexes and placeholders, then caching the profile-component-to-slot mapping, preserves a minimum action route when the network is unavailable. In production, separate metrics for profile resolution, slot coverage, placeholder hits, and post-deadzone actions make input bugs easier to diagnose.
