今日の重要トピックKey topics today

  1. WebXR Device API は `navigator.xr.isSessionSupported()` を、XR 体験を提示してよいかを早期に判断する非侵襲的なチェックとして位置付けている。 The WebXR Device API frames `navigator.xr.isSessionSupported()` as an early, non-intrusive check for whether a page should advertise an XR experience.
  2. WebXR AR Module は `immersive-ar`、`environmentBlendMode`、`interactionMode` に加え、first-person observer view を受け取るには `secondary-views` feature descriptor への明示的 opt-in が必要だと定義している。 The WebXR AR Module defines `immersive-ar`, `environmentBlendMode`, `interactionMode`, and requires explicit opt-in to the `secondary-views` feature descriptor to receive first-person observer views.
  3. secondary view は常時出る前提ではなく、capture など必要な frame にだけ `views` 配列へ現れる可能性があるため、最初の 2 view 固定ではなく全 view を走査する実装が重要になる。 Secondary views should not be assumed to appear every frame; they may appear only during capture, so render code should iterate every view instead of hard-coding the first two.
  4. Raw Camera Access は `camera-access`、`XRView.camera`、`XRWebGLBinding.getCameraImage()` を定義するが、camera image の直接観測は高い privacy impact を持つため、probe と fallback の後段に置くべき機能として扱う。 Raw Camera Access defines `camera-access`, `XRView.camera`, and `XRWebGLBinding.getCameraImage()`, but direct camera observation carries high privacy impact and should sit behind probes and fallbacks.
  5. Immersive Web の WebGPU samples は、WebXR と WebGPU の両方があっても XRGPUBinding / projection layer 対応が別条件になることを示すため、`navigator.gpu` だけで XR 描画経路を確定しない設計が必要になる。 Immersive Web's WebGPU samples show that WebXR and WebGPU presence does not by itself guarantee XRGPUBinding / projection layer support, so `navigator.gpu` should not finalize the XR rendering path alone.

注目事例と何が面白いかNotable example and why it matters

今日の注目は AR Module の first-person observer view です。録画や配信用の視点はユーザーの左右眼 view と完全には一致しないため、`secondary-views` を optional feature として有効にし、`view.isFirstPersonObserver` を見て別扱いする設計が求められます。これは camera-access より軽い情報でも、capture 用の追加 view が frame budget を食うという実装上の論点を作ります。

Today's notable example is the AR Module's first-person observer view. A capture or streaming viewpoint may not match the user's eye views, so applications opt into `secondary-views` and treat `view.isFirstPersonObserver` separately. Even without raw camera access, this creates a concrete render-budget concern because capture views add work.

制作に使えそうな技術メモProduction note

実装では `navigator.xr` の存在確認、`isSessionSupported("immersive-ar")`、user activation 内の `requestSession()` を段階化し、`optionalFeatures` に `secondary-views` を入れても view 数を固定しないことが重要です。WebGPU 経路は `navigator.gpu` の有無だけでなく、XRGPUBinding と XRProjectionLayer の対応を別に判定します。camera-access は必要性が説明できる最後の経路として扱い、observer view の描画は overlay や安定化処理と同じ予算表に載せて管理します。

Implementation should stage `navigator.xr` presence checks, `isSessionSupported("immersive-ar")`, and `requestSession()` inside user activation, while never assuming a fixed view count when `secondary-views` is optional. WebGPU routing needs separate checks for XRGPUBinding and XRProjectionLayer rather than `navigator.gpu` alone. Treat camera-access as the final path that must justify its need, and track observer-view rendering in the same budget table as overlays and stabilization.

俯瞰メモBird's-eye memo

ここ数日の流れは camera pixel そのものから、同意、fallback、capability probe、capture view へ移っています。XR の公開サンプルでは派手な描画より、起動前に何を確認し、どの feature を optional にし、view 数が変わっても壊れないかを可視化する小さな道具が役に立ちます。今日のサンプルはその診断層を独立した体験として切り出しました。

The recent progression has moved from camera pixels themselves to consent, fallbacks, capability probes, and capture views. For XR samples, a small tool that visualizes what to check before launch, which features stay optional, and whether changing view counts breaks rendering can be more useful than flashy rendering. Today's sample isolates that diagnostic layer as its own experience.

今日のミニ試作候補Today's mini prototype candidate

採用した候補は `Capability Probe Secondary View Planner` です。権限を要求せずに `navigator.xr` / `navigator.gpu` の存在を確認し、phone / headset / capture の想定で primary view と first-person observer view の構成、optional features、描画予算、fallback route を可視化します。次に足すなら、実際の `isSessionSupported()` 結果、XRGPUBinding の段階的 probe、observer view だけに watermark / privacy indicator を載せる分岐を追加します。

The selected prototype is `Capability Probe Secondary View Planner`. Without requesting permissions, it checks `navigator.xr` / `navigator.gpu` presence and visualizes primary views, first-person observer views, optional features, render budgets, and fallback routes for phone, headset, and capture scenarios. Useful next additions are real `isSessionSupported()` results, staged XRGPUBinding probes, and branches that add watermark or privacy indicators only to observer views.
