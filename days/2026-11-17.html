今日の重要トピックKey topics today

  1. XRSession の終了はアプリ起点でも user agent 起点でも end event で受ける。 End handles application and user-agent shutdown.
  2. 終了済み session は不可逆で、再び XR を使うには新しい requestSession() が必要になる。 Ended sessions require a new requestSession.
  3. cleanup は end handler に集約し、描画 loop・layer・input listener を同じ経路で解放する。 Cleanup belongs in the end handler.
  4. アプリ下書きと pose・anchor・input source のような session 固有状態は別々に扱う。 App drafts differ from session-scoped spatial state.
  5. 再入場は自動再開でなく、現在の権限・能力・明示操作を改めて通す。 Re-entry requires fresh consent and capability checks.

制作に使えそうな技術メモProduction note

session 作成直後に end listener を登録し、listener 内で XR animation frame の取消、WebGL / layer の解放、session 参照の null 化、ページ UI の復帰をまとめます。終了済み session の XRFrame、XRSpace、input source を新 session へ移さず、必要ならアプリ固有の非空間下書きだけを復元候補にします。

Register end early, clean up there, and never carry old frame-bound state into a new session.

俯瞰メモBird's-eye memo

XR の終了は例外処理だけではなく、誰がいつ没入からページへ戻るかの体験設計です。再開を便利さだけで自動化すると、古い空間証拠や前回の意思を現在へ誤って持ち込みます。終了を共通 cleanup、再入場を新しい合意として分けると、XR の状態遷移が説明可能になります。

Treat shutdown as a shared cleanup boundary and re-entry as a new agreement.
