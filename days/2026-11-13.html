今日の重要トピックKey topics today

  1. secondary-views は optional feature として有効化し、任意数・可変数の XRView を扱う。 secondary-views is an optional feature for variable view sets.
  2. primary view は常に active だが、secondary view は capture 等に応じて現れたり消えたりする。 Primary views stay active while secondary views can appear with capture.
  3. first-person observer view は eye: none になり得て、alpha-blend の扱いと UI 方針を分ける。 First-person observers can use eye none and need distinct UI policy.
  4. secondary を描かない判断でも primary 体験を成立させ、描画省略を成功として偽装しない。 Skipping a secondary view must not compromise primary experience.
  5. 外部観察者へ渡す詳細度は capture の可否とは別の、可視で取り消せる共有判断にする。 Observer detail needs visible, revocable sharing policy.

注目事例と何が面白いかNotable example and why it matters

W3C WebXR Device API は primary と secondary を区別しつつ、view の数・順序・eye の重複をアプリが固定前提にしてはいけないとします。AR Module の first-person observer view は camera と目の位置差を扱う手掛かりで、capture 中だけ view に現れ得ます。本命はこの契約を、2 view / observer 追加 / 意図的省略 / 4 view に切り替えられる自作の判断実験にしました。

The main prototype exposes variable view-set handling rather than assuming a fixed stereo pair.

表現・インタラクションのアイデアExpression and interaction idea

本命は view を矩形として並べ、observer が現れた時だけ amber の第三面を出します。描画予算で observer を省略する場合も primary 2 view は残し、reprojection の可能性を結果として記録します。派生は capture off / silhouette / guided / full を操作し、同じ observer view でも共有粒度を変えられることを、常時見える disclosure cue で表現します。

The derivative makes disclosure and information granularity manipulable independent of observer availability.

制作に使えそうな技術メモProduction note

実装では requestSession の optionalFeatures に secondary-views を入れ、XRFrame ごとに pose.views を for...of で全走査します。index 0 と 1 を left/right と決め打ちせず、view.eye、isFirstPersonObserver、各 view の getViewport(view) を参照します。observer は必要なフレームだけ出るため、GPU target・UI・capture permission を view lifecycle に合わせて更新します。

Opt in optionally, iterate every frame's views, and inspect each view rather than array indices.

サンプルデータの可能性と組み合わせSample data potential and combinations

再利用する receipt は active view count、observer の有無、render plan、共有粒度、取り消し可能性です。GPU 時間、recording 状態、字幕、リモート支援の接続品質と組み合わせれば、配信のために本人の視界を丸ごと複製しない共同作業 UI にできます。生のカメラ映像や空間メッシュをログへ残す必要はありません。

Small policy receipts combine with capture and collaboration state without retaining raw camera or spatial data.

俯瞰メモBird's-eye memo

XR の視点は「左右の2枚」ではなく、端末・capture・性能に応じて変わる出力面です。view 数を柔軟に扱うことと、何を外部へ見せるかを本人に分かる形で扱うことは別の責務です。この二つを混ぜない設計ほど、AR 配信・遠隔支援・VR spectator の端末差を穏やかに吸収できます。

Variable rendering and sharing consent are separate responsibilities that make XR capture more resilient.
