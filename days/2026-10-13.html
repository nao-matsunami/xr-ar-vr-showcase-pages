  2. WebXR-WebGPU Binding draft は `XRGPUBinding`、`nativeProjectionScaleFactor`、`usesDepthValues`、projection / quad / cylinder / equirect / cube layer 作成、`getSubImage()` を定義しており、起動前診断 row に分解しやすいです。 The WebXR-WebGPU Binding draft defines `XRGPUBinding`, `nativeProjectionScaleFactor`, `usesDepthValues`, projection / quad / cylinder / equirect / cube layer creation, and `getSubImage()`, which map naturally into pre-launch triage rows.
  3. Binding explainer は `navigator.gpu.requestAdapter({ xrCompatible: true })` と WebGPU-compatible `XRSession` を強調しているため、adapter fault と binding fault を別々に扱う必要があります。 The binding explainer emphasizes `navigator.gpu.requestAdapter({ xrCompatible: true })` and a WebGPU-compatible `XRSession`, so adapter faults and binding faults should be separated.
  4. Immersive Web WebGPU samples は barebones VR / AR、input selection、benchmark、hands などを WebGPU XR の最小 smoke test として提供しており、自作サンプルの診断列を考える参考になります。 Immersive Web WebGPU samples provide minimal smoke tests for barebones VR / AR, input selection, benchmark scenes, and hands, helping shape the diagnostic columns in the original samples.
  5. W3C WebXR Layers API は composition layer と subimage の lifecycle を考える土台になり、projection layer を作れた後も resize、eye、texture lifetime、visibility の復帰設計が必要です。 The W3C WebXR Layers API is the base for composition layer and subimage lifecycle thinking, and recovery still matters after a projection layer exists: resize, eye selection, texture lifetime, and visibility can all fail.

Meta Browser release notes の experimental WebGPU composition layers と、WebXR-WebGPU Binding の `XRGPUBinding` / `XRGPUSubImage` は、WebGPU XR を `使えるか` だけでなく `どこで失敗して、何へ復帰するか` として見る段階に入ったことを示しています。今日の自作サンプルでは、起動前の adapter / binding / projection layer の失敗を row 化し、派生サンプルで subimage の resize、stale frame、wrong eye、texture lifetime を短い復帰シナリオにしました。

Meta Browser release notes around experimental WebGPU composition layers and the WebXR-WebGPU Binding's `XRGPUBinding` / `XRGPUSubImage` suggest that WebGPU XR should be treated not just as `supported or not`, but as `where can it fail and what route recovers`. Today's original samples turn adapter / binding / projection layer failures into pre-launch rows, then replay subimage resize, stale frame, wrong eye, and texture lifetime recovery scenarios.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `XRGPUBinding Fault Triage Console` は runtime / Meta 152.1 target / adapter fault / binding fault の profile を切り替え、secure context、XR policy、xrCompatible adapter、`XRGPUBinding`、projection layer、optional layers を gate として可視化します。派生サンプル `XRGPUSubImage Fault Recovery Replayer` は、その row を貼り付けて8 frame の subimage fault と復帰策を再生します。

The main sample, `XRGPUBinding Fault Triage Console`, switches among runtime, Meta 152.1 target, adapter fault, and binding fault profiles, visualizing secure context, XR policy, xrCompatible adapter, `XRGPUBinding`, projection layer, and optional layers as gates. The derivative sample, `XRGPUSubImage Fault Recovery Replayer`, accepts that row and replays eight frames of subimage faults and recovery actions.

制作に使えそうな技術メモProduction note

最小 row は `secureContext`、`webgpu`、`xr`、`xrSpatialPolicy`、`xrCompatibleAdapter`、`xrGpuBinding`、`projectionLayer`、`quadLayer`、`nativeScale`、`firstFault`、`route`、`recovery` です。実機では `requestAdapter({ xrCompatible: true })` の成否、`XRGPUBinding(session, device)` の例外名、`createProjectionLayer()` の init、`getSubImage()` の texture / viewport / eye、visibility state を同じ row に足すと、WebGL fallback と scale down の判断に使えます。

The minimal row is `secureContext`, `webgpu`, `xr`, `xrSpatialPolicy`, `xrCompatibleAdapter`, `xrGpuBinding`, `projectionLayer`, `quadLayer`, `nativeScale`, `firstFault`, `route`, and `recovery`. On a device, add the result of `requestAdapter({ xrCompatible: true })`, exception names from `XRGPUBinding(session, device)`, `createProjectionLayer()` init values, `getSubImage()` texture / viewport / eye data, and visibility state into the same row so it can drive WebGL fallback and scale-down decisions.
