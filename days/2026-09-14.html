注目事例と何が面白いかNotable example and why it matters

今日の注目は Plane Detection の次の段として、WebXR Mesh Detection を `placement に使える実世界形状` として扱うことです。Mesh Detection Module では、session が `mesh-detection` feature を有効にしたとき、`XRFrame.detectedMeshes` から `XRMeshSet` を読み、各 `XRMesh` には `meshSpace`、`vertices`、`indices`、`lastChangedTime`、`semanticLabel` が入ります。面白いのは、mesh は plane より細かい一方で、三角形数、更新頻度、privacy LOD、depth holes の影響を受けやすい点です。そこで今日は、mesh をただ表示するのではなく、collision、occlusion、decimation、hold、block へ振り分ける自作サンプルにしました。

Today's focus is treating WebXR Mesh Detection as the next step after Plane Detection: real-world geometry that can be used for placement decisions. The Mesh Detection Module exposes an `XRMeshSet` through `XRFrame.detectedMeshes` when a session enables the `mesh-detection` feature. Each `XRMesh` carries `meshSpace`, `vertices`, `indices`, `lastChangedTime`, and `semanticLabel`. The interesting tradeoff is that meshes can describe finer detail than planes, but they are sensitive to triangle count, update churn, privacy LOD, and depth holes. Today's original sample therefore routes meshes to collision, occlusion, decimation, hold, or block instead of merely visualizing them.

制作に使えそうな技術メモProduction note

実機版では `navigator.xr.requestSession('immersive-ar', { requiredFeatures: ['mesh-detection'], optionalFeatures: ['plane-detection', 'depth-sensing', 'anchors'] })` のように feature を交渉し、frame ごとに `frame.detectedMeshes`、`frame.detectedPlanes`、depth confidence、anchor promise state を同じ ledger row へ保存します。`XRMesh.lastChangedTime` は pose 変化ではなく mesh attribute 更新時刻なので、`meshSpace` の pose と `lastChangedTime` を別々に扱うのが大事です。三角形数が高い mesh は collision 用には decimate し、visual occlusion には depth holes と normal agreement を足して gate すると、AR の配置が落ち着きます。

A device-backed version can negotiate features with `navigator.xr.requestSession('immersive-ar', { requiredFeatures: ['mesh-detection'], optionalFeatures: ['plane-detection', 'depth-sensing', 'anchors'] })`, then save `frame.detectedMeshes`, `frame.detectedPlanes`, depth confidence, and anchor promise state into the same ledger row each frame. `XRMesh.lastChangedTime` represents mesh attribute updates, not pose changes, so the `meshSpace` pose and `lastChangedTime` should be tracked separately. Dense meshes should be decimated for collision, while visual occlusion should be gated with depth holes and normal agreement for calmer AR placement.

俯瞰メモBird's-eye memo

Plane Detection は面の意味と安定した配置に強く、Mesh Detection は実世界形状の細部に強いです。Depth Sensing はその2つが現実の奥行きと合っているかの横串になります。今日の整理では、anchor は plane に任せ、collision / occlusion は mesh に任せ、depth holes が多い時は preview や depth mask fallback へ落とす、という分業にしました。これで9月前半に作った policy、hit-test、anchor、depth、plane の流れに、real-world mesh の粒度が足されました。

Plane Detection is strong for surface meaning and stable placement, while Mesh Detection is strong for real-world shape detail. Depth Sensing cuts across both by checking whether the inferred geometry agrees with real-world depth. Today's organization gives anchors to planes, collision / occlusion to meshes, and falls back to preview or depth masks when depth holes are high. This adds real-world mesh granularity to the policy, hit-test, anchor, depth, and plane flow built in the first half of September.
