今日の重要トピックKey topics today

  1. WebXR DOM Overlays Module は `dom-overlay` feature descriptor と `domOverlay.root` を定義し、session 中に単一の DOM 要素を透明背景の overlay として表示します。 The WebXR DOM Overlays Module defines the `dom-overlay` feature descriptor and `domOverlay.root`, displaying a single DOM element as a transparent overlay during a session.
  2. `beforexrselect` は overlay に target ray が交差した primary action の前に dispatch され、`preventDefault()` で `selectstart` / `selectend` / `select` の発火を抑止できます。 `beforexrselect` is dispatched before primary actions that intersect the overlay with the target ray, and `preventDefault()` can suppress `selectstart`, `selectend`, and `select`.
  3. DOM event と `beforexrselect` / XR input event は同期されないため、pointer / click と XR select の順序が前後しても二重 commit しない replay window が必要です。 DOM events and `beforexrselect` / XR input events are not synchronized, so a replay window is needed to avoid duplicate commits when pointer / click and XR select arrive in different orders.
  4. cross-origin content 上の primary action では pose や gamepad data の観測が制限され、入力終了の扱いも通常の overlay button と分けて記録する価値があります。 For primary actions over cross-origin content, pose and gamepad observation are limited, and action-ending behavior should be recorded separately from normal overlay buttons.
  5. 今日の公開カードは外部デモではなく、自作の `DOM Overlay Frame Owner Guard` と `BeforeXRSelect Timeline Replayer` の2本です。 Today's public cards are the original workspace samples `DOM Overlay Frame Owner Guard` and `BeforeXRSelect Timeline Replayer`, not external demos.

Web Platform Tests have also been updated around detecting DOM Overlay frame owners, which makes iframe ownership a practical implementation and validation concern.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `DOM Overlay Frame Owner Guard` は overlay type、target 領域、input mode、DOM handler、frame policy を切り替え、`dom-only`、`pass-through`、`duplicate-risk`、`delay-input-source`、`cancel-on-exit` へ分類します。派生サンプル `BeforeXRSelect Timeline Replayer` は本命 row か preset を読み、DOM pointer / click、`beforexrselect`、XR selectstart / select / selectend の到着順を timeline に並べ、commit window 内の重複危険度を出します。

The main sample, `DOM Overlay Frame Owner Guard`, switches overlay type, target region, input mode, DOM handler, and frame policy, then classifies interactions as `dom-only`, `pass-through`, `duplicate-risk`, `delay-input-source`, or `cancel-on-exit`. The derivative `BeforeXRSelect Timeline Replayer` reads the main row or a preset, lays out DOM pointer / click, `beforexrselect`, and XR selectstart / select / selectend in a timeline, and reports duplicate risk inside a commit window.

制作に使えそうな技術メモProduction note

実装では overlay root の capture / bubble で `beforexrselect` を1行にまとめ、target element、owner frame、cross-origin 推定、`defaultPrevented`、近傍の pointer event id、XR input source id を保存します。DOM event と XR event は同期しないため、DOM handler 側で即 commit するのではなく、短い commit window に入れて二重実行を抑止するのが扱いやすいです。cross-origin content では pose / gamepad の制限を正常な privacy route として扱い、欠落やバグと混ぜないようにします。

In production, collect `beforexrselect` at the overlay root during capture / bubble and store the target element, owner frame, cross-origin estimate, `defaultPrevented`, nearby pointer event id, and XR input source id in one row. Because DOM and XR events are not synchronized, it is easier to place DOM actions into a short commit window instead of committing immediately. For cross-origin content, treat pose / gamepad limitations as a normal privacy route rather than mixing them with missing data or bugs.
