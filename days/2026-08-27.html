今日の重要トピックKey topics today

  1. WebXR Device API は `XRInputSource.profiles` を ordered array として扱い、アプリ側は先頭から対応 profile を探し、fallback を含めて入力表現を選ぶ必要があります。 The WebXR Device API treats `XRInputSource.profiles` as an ordered array, so applications need to search from the front and choose input presentation with fallback in mind.
  2. WebXR Input Profiles Registry は profile id、fallbackProfileIds、handedness layout、components、selectComponentId、gamepad button / axes mapping を定義し、デバイス差を吸収する基準になります。 The WebXR Input Profiles Registry defines profile ids, fallbackProfileIds, handedness layouts, components, selectComponentId, and gamepad button/axes mappings, making it the baseline for absorbing device differences.
  3. motion-controllers package は `inputsourceschange` で追加された `XRInputSource` から profile を fetch し、毎 frame `updateFromGamepad()` で component state を更新する流れを示しています。 The motion-controllers package shows a flow where `inputsourceschange` additions are used to fetch profiles and `updateFromGamepad()` refreshes component state every frame.
  4. MDN の `XRSession.inputsourceschange` は added / removed 配列を持つ `XRInputSourcesChangeEvent` として説明され、接続・切断・有効化の差分を扱う入口になります。 MDN describes `XRSession.inputsourceschange` as an `XRInputSourcesChangeEvent` with added and removed arrays, which is the entry point for connection, disconnection, and availability deltas.
  5. WebXR Gamepads Module は `XRInputSource.gamepad` が frame ごとに live update されることを明記しており、前 frame との比較には値の snapshot を別途持つ設計が必要です。 The WebXR Gamepads Module states that `XRInputSource.gamepad` is updated live each frame, so applications need separate value snapshots for frame-to-frame comparisons.

制作に使えそうな技術メモProduction note

`XRInputSource.profiles` は表示用の名前ではなく、利用可能な profile を順番に探すための候補列として扱うと実装が安定します。Registry の `selectComponentId` は primary action と `select` event の根拠になるので、trigger と同一視せず profile ごとに読みます。`inputsourceschange` では added で controller object と asset を作り、removed で frame poll、asset、haptic queue、pending select 候補をまとめて解放する必要があります。`gamepad` は live object なので、差分検出には buttons / axes の値だけを snapshot します。

Treat `XRInputSource.profiles` as an ordered list of lookup candidates rather than just display names. Registry `selectComponentId` is the basis for primary action and `select` events, so it should be read per profile instead of assuming it is always a trigger. On `inputsourceschange`, create controller objects and assets from added sources, then release frame polling, assets, haptic queues, and pending select candidates on removed sources. Because `gamepad` is a live object, diffing should snapshot button and axis values rather than object references.
