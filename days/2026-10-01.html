今日の重要トピックKey topics today

  1. Chrome 144 は `XRVisibilityMaskChange` を追加し、ユーザー viewport の可視部分を表す vertices と indices を渡せるようにしたと説明しています。 Chrome 144 describes `XRVisibilityMaskChange` as providing vertices and indices for the visible portion of the user's viewport.
  2. 同じ更新で `XRView` に unique identifier が与えられ、左右目や view ごとの mask と描画行を対応付けやすくなります。 The same update gives `XRView` objects unique identifiers, making it easier to pair masks with per-eye or per-view rendering rows.
  3. WebXR Device API は 2026-06-09 の Candidate Recommendation Draft が最新履歴にあり、XRSession / XRView / frame loop の基礎はここを参照します。 The WebXR Device API history lists the 2026-06-09 Candidate Recommendation Draft as the latest entry, which is the base reference for XRSession, XRView, and the frame loop.
  4. WebXR Layers API Editor's Draft は compositor 管理の layer が performance / judder 対策になることを説明しており、mask row は layer budget と相性が良いです。 The WebXR Layers API Editor's Draft explains compositor-managed layers as a performance and judder tool, which makes mask rows a good fit for layer budgeting.
  5. 今日の公開カードは外部デモではなく、自作の `Visibility Mask Change Ledger` と `Visibility Mask Tile Budget Replayer` の2本です。 Today's public cards are the original workspace samples `Visibility Mask Change Ledger` and `Visibility Mask Tile Budget Replayer`, not external demos.

注目事例と何が面白いかNotable example and why it matters

Chrome 144 の `XRVisibilityMaskChange` は、可視 viewport を mesh として受け取り、描画しなくてよい領域を減らすための手がかりになります。9月後半に扱った space warp、attachment、viewport crop、subimage row は texture / viewport の粒度でしたが、今日はさらに一段前の `そもそもどこを描くか` を viewId 単位の row にします。左右目で mask がずれる時にも、unique view identifier があれば再生・診断しやすくなります。

Chrome 144's `XRVisibilityMaskChange` gives a mesh for the visible viewport, providing a hint for reducing areas that do not need to be rendered. Late September covered space warp, attachments, viewport crop, and subimage rows at the texture / viewport level; today moves one step earlier and records `what should be drawn at all` as per-viewId rows. When masks differ between eyes, unique view identifiers make replay and diagnosis easier.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Visibility Mask Change Ledger` は mask shape、inset、jitter、mask age、view を動かし、coverage、triangle count、saved pixels、route を ledger row として出します。派生サンプル `Visibility Mask Tile Budget Replayer` はその JSON row を貼り付け、8 x 5 の tile を `native`、`patch`、`skip`、`fallback` に分けます。可視マスクが変わった瞬間に全画面を描き直すのではなく、境界だけ安全側に patch する UI の下地です。

The main sample, `Visibility Mask Change Ledger`, lets you adjust mask shape, inset, jitter, mask age, and view, then emits coverage, triangle count, saved pixels, and route as a ledger row. The derivative `Visibility Mask Tile Budget Replayer` accepts that JSON row and classifies an 8 x 5 tile grid into `native`, `patch`, `skip`, and `fallback`. It sketches a UI where visibility-mask changes do not force a full redraw, but patch only the border conservatively.

制作に使えそうな技術メモProduction note

実装では `XRVisibilityMaskChange` 相当の event から vertices / indices / viewId / timestamp を保存し、実 texture や framebuffer を保存対象にしません。後段では mask coverage、三角形数、mask age、head motion、layer redraw age をまとめて budget verdict に変換します。`mask が古い時は full viewport fallback`、`coverage が十分狭い時は visible tiles だけ submit`、`境界が怪しい時は patch band を太くする` という3段階にすると運用 UI にしやすいです。

In production, save vertices / indices / viewId / timestamp from an `XRVisibilityMaskChange`-like event, not textures or framebuffers. Downstream, combine mask coverage, triangle count, mask age, head motion, and layer redraw age into a budget verdict. A practical three-step policy is: use full-viewport fallback when the mask is stale, submit only visible tiles when coverage is narrow enough, and widen the patch band when the boundary is uncertain.

In remote assistance or installation UI, this can explain later how many milliseconds were saved by skipping outside-view tiles, or why the system returned to full viewport when the mask became stale. Combined with AI or operational logs, it can evolve into privacy-aware replay that summarizes only the region the user could see.

試すならこれIf you try one thing

In `Visibility Mask Change Ledger`, choose `notched passthrough`, low jitter, and mask age around the 20ms range to get `submit-mask-row`. Increase jitter or age and it falls into `hold-mask-row`. In the derivative sample, paste that JSON, switch policy to `strict`, and raise head motion to see border patches and full-viewport fallback increase.
