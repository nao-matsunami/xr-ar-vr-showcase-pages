今日の重要トピックKey topics today

  1. WebXR Raw Camera Access Module は `camera-access` feature descriptor、`XRView.camera`、`XRCamera.width` / `height`、`XRWebGLBinding.getCameraImage(camera)` を定義している。 The WebXR Raw Camera Access Module defines the `camera-access` feature descriptor, `XRView.camera`, `XRCamera.width` / `height`, and `XRWebGLBinding.getCameraImage(camera)`.
  2. Raw Camera Access は immersive-ar の背後にあるカメラ画像 pixels に触れるため、仕様の Privacy & Security Considerations でも最も privacy implication が大きい機能として扱われている。 Raw Camera Access touches camera-image pixels behind immersive-ar, so the specification's Privacy & Security Considerations treats it as the feature with the highest privacy implications.
  3. Raw Camera Access は `xr-spatial-tracking` と `camera` の Permissions Policy、ユーザー同意、privacy indicator を前提にするため、体験設計上は optional / required の分離が重要になる。 Raw Camera Access depends on `xr-spatial-tracking` and `camera` Permissions Policy, user consent, and privacy indicators, so separating optional and required feature requests matters for experience design.
  4. WebXR Depth Sensing や Mesh Detection は、画像そのものではなく距離や粗い面情報を使えるため、配置、occlusion、測定、近接 UI の多くを raw pixels なしで成立させられる。 WebXR Depth Sensing and Mesh Detection can use distance or coarse surfaces rather than the image itself, enabling many placement, occlusion, measurement, and proximity UI flows without raw pixels.
  5. Immersive Web Samples は API の使い方を確認する一次的な参照として有用だが、公開アーカイブでは外部デモを並べず、今日も自作の最小サンプルを中心にした。 Immersive Web Samples remain useful primary references for API usage, while the public archive keeps external demos as links and centers today's original minimal sample.

注目事例と何が面白いかNotable example and why it matters

今日の注目は Raw Camera Access の仕様が、`camera-access` を通じて XR frame と同期した camera image texture を返す一方で、強い同意 UX と privacy indicator を要求している点です。AR では背景画像を直接読むと object recognition や custom effect が作りやすくなりますが、配置や occlusion だけなら Depth Sensing、床や壁の吸着なら Plane / Mesh Detection で十分な場面があります。そこでサンプルでは、体験の必要条件を manual / plane / depth / mesh / camera の ladder として並べ、camera-access を最後の段に置きました。

Today's notable point is that Raw Camera Access can return camera-image textures synchronized with XR frames through `camera-access`, while also requiring strong consent UX and privacy indicators. Direct background image access makes object recognition and custom effects easier, but placement and occlusion can often use Depth Sensing, while floor or wall snapping can use Plane or Mesh Detection. The sample therefore arranges experience requirements as a manual / plane / depth / mesh / camera ladder and places camera-access as the final step.

表現・インタラクションのアイデアExpression and interaction idea

サンプルでは、縦方向の consent ladder に Manual、Plane、Depth、Mesh、Camera の 5 段を置き、utility、privacy、friction をリアルタイムに再計算します。Place / Measure / Inspect の preset と、task detail、scene motion、occlusion need、recognition need、consent threshold、derived data strength の slider を触ると、`optional: depth-sensing` で足りるのか、`required after consent: camera-access` まで進むのかが変わります。canvas 上の probe を動かすと、ユーザー操作が permission route の説明ログに反映されます。

The sample places Manual, Plane, Depth, Mesh, and Camera steps on a vertical consent ladder and recalculates utility, privacy, and friction in real time. Place / Measure / Inspect presets plus sliders for task detail, scene motion, occlusion need, recognition need, consent threshold, and derived data strength change whether `optional: depth-sensing` is enough or the route advances to `required after consent: camera-access`. Moving the canvas probe updates the explanation log for the chosen permission route.

制作に使えそうな技術メモProduction note

実装するときは、`navigator.xr.requestSession("immersive-ar", { optionalFeatures: [...] })` で derived data を先に試し、camera-access は object recognition や camera texture effect が本当に必要な操作にだけ遅延させるのが扱いやすいです。Depth は `getDepthInMeters()` 風の点問い合わせ、Mesh は surface の coarse geometry、Layers は permission prompt や privacy indicator と干渉しにくい DOM overlay / composition layer の見せ方を検討します。サンプル内の ladder score は簡易式ですが、実アプリでは失敗率、補正回数、ユーザーの明示操作、ログ保持期間を入力にできます。

In implementation, first try derived data through `navigator.xr.requestSession("immersive-ar", { optionalFeatures: [...] })`, and delay camera-access until object recognition or camera-texture effects are truly needed. Depth can act like point queries through `getDepthInMeters()`, Mesh can provide coarse surface geometry, and Layers can shape DOM overlays or composition layers that avoid fighting permission prompts and privacy indicators. The sample's ladder score is a simple model, but a real app can feed it with failure rate, correction count, explicit user actions, and log retention period.

サンプルデータの可能性と組み合わせSample data potential and combinations

今日のサンプルからは、scenario、slider 値、選ばれた route、privacy / utility / friction、probe 座標、feature descriptor 候補、短い decision log が取れます。これを家具配置、建築採寸、展示ガイド、現場点検、倉庫ナビ、AI object detection、redaction policy、権限説明 UI と組み合わせると、どのタスクで camera-access を正当化できるかを事前に比較できます。後で実機 WebXR に接続するなら、ladder の各段を `isSessionSupported` と optional feature の成功/失敗ログに差し替えます。

Today's sample produces scenario, slider values, selected route, privacy / utility / friction, probe coordinates, candidate feature descriptors, and a short decision log. Combined with furniture placement, architectural measuring, exhibition guides, field inspection, warehouse navigation, AI object detection, redaction policies, or permission explanation UI, it can compare which tasks justify camera-access before asking for it. When connected to real WebXR hardware later, each ladder step can be replaced with `isSessionSupported` and optional-feature success/failure logs.
