今日の重要トピックKey topics today

  1. Plane Detection は immersive AR session で plane-detection feature を要求し、XRFrame.detectedPlanes から取得する。 Plane detection is negotiated for immersive AR and read from XRFrame.detectedPlanes.
  2. XRPlane.lastChangedTime は polygon 等の属性更新の時刻であり、planeSpace の pose 変化は含まれない。 lastChangedTime tracks attributes, not plane-space pose changes.
  3. plane が detectedPlanes から消えたら、アプリ側の台帳から除外する。 Missing planes should be removed from the app ledger.
  4. polygon と semanticLabel は実環境の情報になり得るため、粒度低減・量子化・非公開が privacy の選択肢になる。 Geometry and labels require deliberate privacy choices.

注目事例と何が面白いかNotable example and why it matters

Immersive Web の公式 plane-detection sample は平面データを使った JavaScript の hit test と Anchors を結びます。一方、仕様は polygon の属性更新と pose の更新を明確に別扱いにしています。本命ではこの見落としやすい差を、geometry / pose / removed の receipt として個別に操作できるようにしました。

The official sample combines plane data, hit testing, and anchors; this prototype makes geometry, pose, and removal independent receipts.

制作に使えそうな技術メモProduction note

実装では requestSession('immersive-ar', {requiredFeatures:['plane-detection']}) を試し、各 XRFrame の detectedPlanes を前 frame の Map と比較します。新規 plane は lastChangedTime と polygon をキャッシュし、時刻が進んだものだけ再メッシュします。ただし getPose(plane.planeSpace, referenceSpace) は毎 frame 求め、null なら描画を保留します。

Diff detectedPlanes for identity and geometry, but query plane poses every frame and tolerate null poses.

サンプルデータの可能性と組み合わせSample data potential and combinations

俯瞰メモBird's-eye memo

plane detection は部屋をそのまま取り込む API ではなく、変化する近似形状を渡す契約です。描画の効率だけでなく、何を更新とみなし、どの形状まで公開するかを設計に含めると、AR はより説明可能になります。

Plane detection is a contract for changing approximations, so update semantics and disclosure belong in the design.
