今日の重要トピックKey topics today

  1. Mesh Detection は immersive AR で mesh-detection feature を交渉し、XRFrame.detectedMeshes から読む。 Mesh detection is negotiated for immersive AR and read from XRFrame.detectedMeshes.
  2. XRMesh の vertices / indices と lastChangedTime は形状の更新を示し、meshSpace の pose は別途毎 frame 求める。 Geometry revisions and mesh-space pose updates are distinct.
  3. detectedMeshes から消えた identity の GPU/CPU cache はアプリ側で解放する。 Disappearing mesh identities require cache cleanup.
  4. 提案段階の Mesh Detection は対応差を前提に、hit-test 等の縮退導線を設計する。 The proposal needs capability-aware fallbacks.

注目事例と何が面白いかNotable example and why it matters

Immersive Web の公式 Mesh Detection sample は取得した mesh を JavaScript 側の hit test と Anchors に結びます。ここで重要なのは、面らしく見えるものを一度だけ取得するのではなく、形状バッファと座標 pose が別々に変わることです。本命はその差を geometry / pose / removed の receipt として個別に操作できます。

The official sample links detected meshes with hit testing and anchors; the main prototype separates geometry, pose, and removal receipts.

表現・インタラクションのアイデアExpression and interaction idea

mint は追跡中の mesh、amber は topology の改訂、移動は geometry を変えない pose receipt として見せます。派生では high / mid / low の信頼度の窓で place、preview、block を切り替え、精密さの見た目ではなく許可する行為を変えます。

Color separates tracking, topology revisions, and pose-only motion; the derivative maps confidence to allowed actions.

制作に使えそうな技術メモProduction note

実機では requestSession('immersive-ar', {requiredFeatures:['mesh-detection']}) を試し、XRFrame.detectedMeshes を前 frame の Map と比較します。新規または lastChangedTime が進んだ mesh だけ vertices / indices を再アップロードし、getPose(mesh.meshSpace, referenceSpace) は毎 frame 求めます。null pose は古い座標を真実として描かず、保留状態にします。

Diff mesh identities and geometry revisions, but query mesh-space pose every frame and tolerate null poses.

サンプルデータの可能性と組み合わせSample data potential and combinations

頂点数、三角形数、更新頻度、pose 欠落、配置を許可した confidence window を匿名ログにすれば、展示AR・保守支援・室内ナビで何を環境形状に任せるか比較できます。深度、画像認識、音声案内と組み合わせる際も、mesh を確定した真実ではなく入力の一つとして扱えます。

Anonymized revision and confidence logs can compare mesh policy across guidance, exhibits, and operational AR.

俯瞰メモBird's-eye memo

環境メッシュは部屋の完成モデルではなく、変化する近似へのアクセスです。更新を無差別に再描画するより、何が形状改訂で何が座標変化かを分け、信頼度に応じて許可する操作を狭めると、AR の約束を説明しやすくなります。

An environment mesh is access to a changing approximation, so revision semantics and action policy should be explicit.

今日のミニ試作候補Today's mini prototype candidate

本命 `Mesh Revision Ledger Lab` を実装しました。何が動くか: mesh の検出、vertices / indices の改訂、pose のみの移動、追跡集合からの除外を別 receipt として操作できます。次に足すなら実機 XRFrame の geometry diff と再アップロード計測です。派生 `Mesh Confidence Window` も実装しました。何が動くか: high / mid / low の信頼度で配置・preview・block を切り替え、decision をコピーできます。次に足すなら実際の深度品質、アンカー生成、確認UIの統合です。

The main operates mesh lifecycle receipts; the derivative gates placement by a confidence window and exports the decision.
