今日の重要トピックKey topics today

  1. WebXR Device API の `isSessionSupported(mode)` は XR 体験を広告してよいかを事前確認する API で、仕様上は device selection UI や他の XR アプリへの干渉を起こさない軽い問い合わせとして扱われる。 The WebXR Device API treats `isSessionSupported(mode)` as a preflight query for whether XR should be advertised, and the spec frames it as a lightweight check that should not trigger device-selection UI or interfere with other XR apps.
  2. `immersive-ar` は AR Module が追加する session mode で、互換ハードウェアでは `immersive-vr` と同じ immersive session の仕組みを使いながら現実世界との合成を意図する。 `immersive-ar` is a session mode added by the AR Module; on compatible hardware it uses the same immersive-session machinery as `immersive-vr` while intending real-world blending.
  3. MDN の `requestSession()` は session feature ごとの user consent と Permissions-Policy 要件を整理しており、`hit-test` や `depth-sensing` は `xr-spatial-tracking` の policy 影響を受ける。 MDN's `requestSession()` documentation summarizes user-consent and Permissions-Policy requirements per session feature; features such as `hit-test` and `depth-sensing` are affected by `xr-spatial-tracking`.
  4. Immersive Web の report / samples は、モード別 support と session 開始後の情報を切り分けて見せているため、公開サイト側でも demo list ではなく診断パネルの UX 参考として有用。 The Immersive Web report and samples separate mode support from information available after session start, making them useful UX references for diagnostic panels rather than archive cards.
  5. `isSessionSupported()` が true でも、user activation、exclusive device 使用中、強すぎる `requiredFeatures`、privacy copy 不足で `requestSession()` が失敗しうるため、結果表示は確定判定ではなく launch readiness として扱う。 Even when `isSessionSupported()` returns true, `requestSession()` may still fail due to user activation, exclusive device use, strict `requiredFeatures`, or insufficient privacy messaging, so the result should be shown as launch readiness rather than a final guarantee.

制作に使えそうな技術メモProduction note

`isSessionSupported()` は `XRSessionInit` を受け取らないので、モード可否と feature 可否を分けて扱う必要があります。実装では `navigator.xr` の存在確認、`isSessionSupported("inline")`、`isSessionSupported("immersive-ar")`、`isSessionSupported("immersive-vr")` を独立した Promise として扱い、`SecurityError` などの exception name も UI に残します。実 `requestSession()` を試す画面では、`requiredFeatures` を最小にし、`hit-test`、`anchors`、`depth-sensing`、`dom-overlay`、`hand-tracking` は体験成立に必須なものだけ required に昇格する設計がよいです。

`isSessionSupported()` does not accept `XRSessionInit`, so mode support and feature support should be modeled separately. Implementation should treat `navigator.xr` presence and each of `isSessionSupported("inline")`, `isSessionSupported("immersive-ar")`, and `isSessionSupported("immersive-vr")` as independent promises, preserving exception names such as `SecurityError` in the UI. For screens that call real `requestSession()`, keep `requiredFeatures` minimal and only promote features such as `hit-test`, `anchors`, `depth-sensing`, `dom-overlay`, and `hand-tracking` to required when the experience truly depends on them.
