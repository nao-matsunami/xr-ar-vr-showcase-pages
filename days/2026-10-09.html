注目事例と何が面白いかNotable example and why it matters

Immersive Web の WebGPU samples は WebXR session を WebGPU で描画する最小入口として使え、WebXR-WebGPU Binding 側では `XRGPUBinding.createProjectionLayer()` のような考え方が確認できます。Meta Browser 149.1 の WebGPU space-warp layers と、Meta の WebXR Space Warp 説明は、projection layer、depth、motion vector、foveation を別々ではなく同じ起動前交渉 row として扱う動機になります。面白いのは、`対応しているか` だけでなく、どの不足がどの fallback へ落ちたかを後から replay できる点です。

Immersive Web WebGPU samples are a compact entry point for rendering WebXR sessions with WebGPU, while WebXR-WebGPU Binding work exposes concepts such as `XRGPUBinding.createProjectionLayer()`. Meta Browser 149.1 WebGPU space-warp layer support and Meta's WebXR Space Warp docs motivate treating projection layers, depth, motion vectors, and foveation as one startup negotiation row. The interesting part is not just whether support exists, but replaying which missing capability caused which fallback.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `WebGPU XR Capability Negotiation Board` は、session target、WebGPU readiness、XRGPUBinding confidence、depth / motion vector、policy / consent を動かし、`webgpu-space-warp-candidate`、`webgpu-projection-layer`、`webgl-projection-fallback` などの route を作ります。派生サンプル `Feature Fallback Route Replayer` は、その route を7フレームに展開し、feature 欠落・policy・GPU pressure・depth gap がどこで fallback や block を生むかを見ます。

The main sample, `WebGPU XR Capability Negotiation Board`, lets you tune session target, WebGPU readiness, XRGPUBinding confidence, depth / motion vector, and policy / consent, then produces routes such as `webgpu-space-warp-candidate`, `webgpu-projection-layer`, and `webgl-projection-fallback`. The derivative `Feature Fallback Route Replayer` expands that route across seven frames and shows where missing features, policy pressure, GPU pressure, or depth gaps create fallback or blocking behavior.

制作に使えそうな技術メモProduction note

実機版では `navigator.gpu`、`navigator.xr?.isSessionSupported()`、`requestSession()` の required / optional feature、Permissions-Policy、Depth Sensing、WebXR Layers、WebXR-WebGPU Binding の結果を同じ JSON row に入れます。今日の row は `xrSessionMode`、`webgpuAdapter`、`xrGpuBinding`、`projectionLayer`、`fixedFoveation`、`depthOrMotionVector`、`spaceWarpCandidate`、`policyConsent` を候補列にしました。

On device, `navigator.gpu`, `navigator.xr?.isSessionSupported()`, `requestSession()` required / optional features, Permissions-Policy, Depth Sensing, WebXR Layers, and WebXR-WebGPU Binding outcomes should be saved into one JSON row. Today's row uses `xrSessionMode`, `webgpuAdapter`, `xrGpuBinding`, `projectionLayer`, `fixedFoveation`, `depthOrMotionVector`, `spaceWarpCandidate`, and `policyConsent` as candidate columns.

今日のミニ試作候補Today's mini prototype candidate

本命として採用した候補は `WebGPU XR Capability Negotiation Board` です。何が動くか: WebGPU、XRGPUBinding、projection layer、depth / motion vector、policy / consent をスライダーで動かし、起動前 route、coverage、missing fields、risk を JSON row として出します。次に足すなら、実 `navigator.gpu` / `navigator.xr` probe を実行して row を自動生成します。派生として `Feature Fallback Route Replayer` も実装しました。何が動くか: requested feature と pressure 値から7フレーム分の fallback / block / stable を再生します。次に足すなら、1本目の export JSON を直接読み込み、requiredFeatures / optionalFeatures ごとの retry queue を表示します。

The selected main prototype is `WebGPU XR Capability Negotiation Board`. What it does: sliders tune WebGPU, XRGPUBinding, projection layer, depth / motion vector, and policy / consent, then export pre-start route, coverage, missing fields, and risk as a JSON row. Next addition: run real `navigator.gpu` / `navigator.xr` probes and generate the row automatically. The derivative `Feature Fallback Route Replayer` was also implemented. What it does: replays seven frames of fallback / block / stable behavior from a requested feature and pressure values. Next addition: directly load the first sample's export JSON and show a retry queue per required / optional feature.
