今日の重要トピックKey topics today

  1. WebXR DOM Overlays Module Working Draft 2024-09-24 は、immersive session 中に単一の DOM root を overlay として表示し、XR 入力が overlay と交差した時に `beforexrselect` を発火する流れを定義しています。 The WebXR DOM Overlays Module Working Draft dated 2024-09-24 defines displaying a single DOM root as an overlay during immersive sessions and firing `beforexrselect` when XR input intersects the overlay.
  2. `beforexrselect` は cancelable で、`preventDefault()` すると通常の `selectstart` / `selectend` / `select` が抑止されます。AR の配置 UI では、DOM ボタン操作と world anchor 操作を分離する基礎になります。 `beforexrselect` is cancelable, and calling `preventDefault()` suppresses normal `selectstart`, `selectend`, and `select` events. This is the basis for separating DOM button interaction from world-anchor interaction in AR placement UI.
  3. 同 draft は cross-origin content への入力時に pose や gamepad data を制限する考え方を含みます。overlay 内 iframe や外部 UI を使う場合は、入力ログを過剰に取らない設計が必要です。 The same draft includes limiting pose and gamepad data during interaction with cross-origin content. If iframes or external UI are used inside an overlay, input logging must avoid over-collecting data.
  4. WebXR Device API 2026-03-16 CRD の session / input source / select event model は、overlay 側の DOM event と XR 側の select event を別系統として扱う前提になります。 The WebXR Device API CRD dated 2026-03-16 provides the session, input source, and select event model that lets DOM overlay events and XR select events be treated as separate routes.
  5. Anchors Module と Hit Test Module の流れでは、hit-test から anchor を作った後も select 操作で再配置、警告、削除が起きます。今日の焦点は、その操作が overlay に吸われるべきか world に届くべきかの gate です。 In the Anchors and Hit Test flow, after a hit-test creates an anchor, later select actions may replace, warn, or delete it. Today's focus is the gate that decides whether that action is consumed by overlay UI or reaches the world.

注目事例と何が面白いかNotable example and why it matters

今日の注目は WebXR DOM Overlays Module の `beforexrselect` です。overlay 上に ray が当たった時、アプリは DOM event を処理しつつ XR の `select` を出すか止めるかを選べます。面白いのは、AR の「保存」「削除」「再配置」ボタンと、空間内 anchor そのものの選択が、同じトリガー入力を使っても別の経路として整理できる点です。UI の見た目ではなく、入力の所有権を明示する小さな runtime policy として使えます。

Today's notable point is `beforexrselect` in the WebXR DOM Overlays Module. When a ray intersects the overlay, an app can handle DOM events while deciding whether XR `select` should still fire. The interesting part is that AR buttons such as save, delete, and replace can share the same trigger input with spatial anchor selection while still being routed as separate paths. It is less about the overlay's appearance and more about a small runtime policy for input ownership.

表現・インタラクションのアイデアExpression and interaction idea

サンプルでは ray の位置、overlay type、anchor drift、`preventDefault()` の有無、cross-origin 風パネル、transient input source を切り替えます。canvas には DOM overlay root、embedded content 風の制限領域、world anchor、target ray、decision rail を描き、primary action が DOM click、auxiliary、suppressed、limited、world select のどれになるかを表示します。実 UI では overlay に触れた瞬間だけ anchor の hover ring を弱め、world に戻ったら anchor 操作を再度 armed にする表現が使えます。

The sample switches ray position, overlay type, anchor drift, `preventDefault()`, a cross-origin-like panel, and transient input source behavior. The canvas draws the DOM overlay root, embedded-content-like restricted region, world anchor, target ray, and decision rail, showing whether the primary action becomes a DOM click, auxiliary route, suppressed event, limited route, or world select. In a real UI, touching the overlay can dim the anchor hover ring, then re-arm anchor operations when the pointer returns to the world.

制作に使えそうな技術メモProduction note

実装では `requestSession('immersive-ar', { optionalFeatures: ['dom-overlay', 'anchors', 'hit-test'], domOverlay: { root } })` のように overlay root を明示します。root の `beforexrselect` handler で、ボタンやフォームなど DOM が所有する領域では `event.preventDefault()` を呼び、anchor 操作が必要な world 領域では XR の `select` を通します。cross-origin iframe 相当の領域では、仕様の privacy model に合わせ、pose / gamepad logging を limited として扱う adapter を挟むのが安全です。

In production, explicitly pass the overlay root, for example `requestSession('immersive-ar', { optionalFeatures: ['dom-overlay', 'anchors', 'hit-test'], domOverlay: { root } })`. In the root `beforexrselect` handler, call `event.preventDefault()` for DOM-owned regions such as buttons and forms, while allowing XR `select` to reach world regions that need anchor operations. For areas equivalent to cross-origin iframes, use an adapter that treats pose and gamepad logging as limited according to the privacy model.

俯瞰メモBird's-eye memo

ここまでの流れは、AR 配置の安定化から操作の所有権へ進みました。hit-test gate は置く前、anchor drift planner は置いた後、今日の DOM Overlay select gate はユーザーが何を操作しているかを分ける層です。この層があると、空間内の不安定な anchor に警告を出しながら、overlay の確認 UI を誤って world 操作として処理しない設計にできます。

The series has moved from AR placement stability into ownership of interaction. The hit-test gate handles pre-placement, the anchor drift planner handles post-placement, and today's DOM Overlay select gate separates what the user is operating. With this layer, an app can warn about unstable spatial anchors while avoiding accidental world operations when the user is confirming something in overlay UI.
