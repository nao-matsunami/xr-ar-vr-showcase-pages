今日の重要トピックKey topics today

  1. WebXR Raw Camera Access Module は `camera-access` feature descriptor、`XRView.camera`、`XRWebGLBinding.getCameraImage()` を定義し、immersive-ar の frame 同期カメラ画像を扱います。 The WebXR Raw Camera Access Module defines the `camera-access` feature descriptor, `XRView.camera`, and `XRWebGLBinding.getCameraImage()` for frame-synchronized immersive-ar camera images.
  2. `camera-access` は `xr-spatial-tracking` に加えて `camera` の permissions policy とユーザー同意が重要で、仕様上も高いプライバシー影響を持つ機能として扱われます。 `camera-access` depends on camera permissions policy in addition to `xr-spatial-tracking` and user consent, and the specification treats it as a high-privacy-impact capability.
  3. Raw Camera Access の explainer は、非同期の任意カメラ取得ではなく、表示 view と結びついた pose 同期画像を対象にしている点を強調しています。 The Raw Camera Access explainer emphasizes pose-synchronized imagery tied to the displayed view rather than arbitrary asynchronous camera capture.
  4. WebXR Device API の requiredFeatures / optionalFeatures は、必須機能の欠落で session 作成を止めるか、段階的拡張として縮退するかを分ける設計ポイントです。 WebXR Device API requiredFeatures and optionalFeatures separate session-blocking requirements from progressive enhancement fallback design.
  5. 今日の公開カードは外部デモではなく、このワークスペース内の `Raw Camera Access Gateboard` と `Camera Texture Alignment Probe` の2本です。 Today's public cards focus on the original workspace samples, `Raw Camera Access Gateboard` and `Camera Texture Alignment Probe`, not external demos.

注目事例と何が面白いかNotable example and why it matters

注目したのは Raw Camera Access の仕様が、普通の `getUserMedia()` 的なカメラ取得ではなく、AR 表示に使われる view と揃った frame 同期 texture を扱う点です。環境画像に直接触れるので、機能を使えるかどうかだけでなく、なぜ必要か、どの状態なら texture を使わず fallback するかを UI の主役にできます。

The notable point is that Raw Camera Access is not ordinary `getUserMedia()`-style capture; it is a frame-synchronized texture aligned to the AR display view. Because it directly exposes imagery from the user's environment, the UI should foreground not only availability but why the app needs it and when it should fall back instead of using the texture.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Raw Camera Access Gateboard` は、session mode、required / optional feature、consent、frame age、view alignment を動かし、camera texture / defer texture / mask + fallback / session block の route を出します。派生サンプル `Camera Texture Alignment Probe` は、native camera が aligned、overscan、offset、missing の時に direct texture、crop texture、projection fallback、no camera のどれに回すかを視覚化します。

The main sample, `Raw Camera Access Gateboard`, lets you adjust session mode, required/optional feature choice, consent, frame age, and view alignment, then routes to camera texture, defer texture, mask + fallback, or session block. The derivative `Camera Texture Alignment Probe` visualizes whether aligned, overscan, offset, or missing native camera states should use direct texture, crop texture, projection fallback, or no camera.

制作に使えそうな技術メモProduction note

実機版では `navigator.xr.requestSession("immersive-ar", { requiredFeatures: ["camera-access"] })` の前に、用途説明と permissions policy の状態を確認する UI を置きます。`XRView.camera` は animation frame 中の view に紐づくため、古い frame や別 session の binding に渡す設計を避けます。texture は opaque として扱い、ピクセル前提の処理や保存は privacy filter と明示的な用途を先に通すべきです。

A device-backed version should place purpose explanation and permissions-policy checks before `navigator.xr.requestSession("immersive-ar", { requiredFeatures: ["camera-access"] })`. Because `XRView.camera` is tied to a view during the animation frame, avoid passing stale frames or a binding from another session. Treat the texture as opaque and gate pixel-level processing or persistence behind a privacy filter and explicit purpose.

今日のミニ試作候補Today's mini prototype candidate

本命として採用した候補は `Raw Camera Access Gateboard` です。何が動くか: session mode、camera-access の required / optional、同意、frame age、alignment を操作し、camera texture を使うか fallback するかを判定します。次に足すなら、実 `document.permissionsPolicy.allowsFeature("camera")` と `allowsFeature("xr-spatial-tracking")` を読んで gate に反映します。派生として `Camera Texture Alignment Probe` も実装しました。何が動くか: native camera の aligned / overscan / offset / missing を切り替え、crop texture と projection fallback の境目を表示します。次に足すなら、opaque texture を模した shader mask と hit-test anchor の commit 判定をつなぎます。

The selected main prototype is `Raw Camera Access Gateboard`. What it does: adjusts session mode, camera-access required/optional status, consent, frame age, and alignment, then decides whether to use the camera texture or fall back. Next addition: read real `document.permissionsPolicy.allowsFeature("camera")` and `allowsFeature("xr-spatial-tracking")` into the gate. The derivative `Camera Texture Alignment Probe` was also implemented. What it does: switches native camera between aligned, overscan, offset, and missing, then shows the boundary between crop texture and projection fallback. Next addition: connect an opaque-texture-style shader mask with hit-test anchor commit decisions.
