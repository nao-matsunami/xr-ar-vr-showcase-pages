今日の重要トピックKey topics today

  1. WebXR Layers は composition layer を compositor 側で提示し、アプリの更新頻度と表示を分けられます。 Composition layers separate compositor presentation from application update cadence.
  2. `XRCompositionLayer` には quality、`needsRedraw`、`destroy()` があり、更新・品質・寿命を別々に設計できます。 Quality, needsRedraw, and destroy separate update, fidelity, and lifetime decisions.
  3. Layers は immersive VR / AR session 用で、inline session では使えないため projection-layer fallback が必要です。 Layers require immersive sessions, so an inline-safe fallback matters.
  4. 公式 Layers Samples は layer type ごとの最小検証を提供し、実機差を切り分ける出発点になります。 Official samples isolate feature behavior for device testing.

注目事例と何が面白いかNotable example and why it matters

W3C Layers API は layer を compositor が提示できるため、毎フレーム texture を作り直す前提から離れられます。`needsRedraw` と quality を一つの『高画質か低画質か』ではなく、読むべき HUD は保持し、背景 media は低品質化または終了できる寿命設計へ変える点が面白いです。

Layers make lifetime choices possible: keep a readable HUD while degrading or ending less important media.

表現・インタラクションのアイデアExpression and interaction idea

本命は pin HUD、spatial note、media panorama の3層を content pressure と GPU budget で分類します。派生は保存 row を HUD pulse、thermal pressure、recovery ramp に通すため、熱・電力制約時でも『何を読ませ続けるか』を時間軸で比較できます。

The main ranks three layers; the derivative replays them through pulse, thermal, and recovery patterns.

制作に使えそうな技術メモProduction note

実装では `optionalFeatures: ['layers']` の結果を記録し、`XRCompositionLayer.needsRedraw`、redraw event、quality、texture size、GPU timestamp を layer 単位で収集します。Layers が不可の session、特に inline では projection layer または通常の canvas に戻し、`destroy()` は render state から外す手順と対にして扱います。

Log feature negotiation, redraw signals, quality, texture size, and GPU timestamps per layer; keep a projection or canvas fallback.

Lifecycle rows can connect captions, maps, remote annotations, 360 media, and installation visuals while preserving human review of fidelity tradeoffs.
