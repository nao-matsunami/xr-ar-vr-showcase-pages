今日の重要トピックKey topics today

  1. XRWebGLLayer.fixedFoveation はXRコンポジタが周辺を低解像度で描く度合いで、0から1の値を持つ。 fixedFoveation controls compositor peripheral resolution between 0 and 1.
  2. 対応しない端末では getter が null となり、設定は no-op なので、実行したふりをしないフォールバックが必要である。 Unsupported layers return null, requiring an honest fallback.
  3. 効果は次の XRFrame から反映され得るが、数値の解釈や刻みは user agent に委ねられる。 User agents determine the interpretation and granularity of levels.
  4. 固定フォービエーションは低コントラストな背景には向く一方、文字や細部を周辺へ置く用途には不向きである。 Foveation suits low-contrast backgrounds better than edge text.
  5. 負荷対策は解像度だけでなく、周辺の装飾、地図、字幕を中心品質へ寄せる優先度設計と組み合わせる。 Performance policy should also prioritize content placement and simplification.

注目事例と何が面白いかNotable example and why it matters

WebXR Device API の fixedFoveation は、中心を高品質に保ちながら周辺の描画解像度を下げてGPU負荷を抑えるための compositor 側の値です。MDN は背景のような低コントラストなテクスチャには有用だが、文字や精細画像には不向きと整理しています。本命では数値設定、端末の対応可否、周辺へ何を置くかを別々の receipt とし、公式資料を参考にしつつ公開の中心は自作の操作可能な検証に置きます。

The main prototype separates the compositor setting, support state, and content-placement policy.

表現・インタラクションのアイデアExpression and interaction idea

本命は 0.00、0.33、0.67、未対応を選ぶと、中心／周辺の表現とHUD方針が変わります。派生は calm / busy / critical を選び、装飾粒子を薄める、地図を内側へ寄せる、重要指示だけを残す順に変化します。品質低下を単なるぼかしとして隠すのでなく、コンテンツの役割を組み替えるインタラクションにします。

The two prototypes turn peripheral quality into visible content-priority decisions.

制作に使えそうな技術メモProduction note

実機ではWebGLの baseLayer を得た後に fixedFoveation を読み、null なら未対応として扱います。値は0〜1ですが、UAが連続値をどのように解釈するかは保証されず、変更は次のXRFrameから反映されます。まず低・中・高の粗い段階で比較し、HUDや字幕は周辺へ固定配置しないこと、未対応時には scene complexity や viewport scale といった別の負荷対策へ落とすことが実装しやすいです。

Read null defensively, use coarse levels, protect central UI, and provide a non-foveation fallback.

サンプルデータの可能性と組み合わせSample data potential and combinations

この2本は、設定値、対応可否、周辺の扱い、可読性方針だけを receipt として残します。展示なら音響の密度や背景の粒子を視線周辺で調整でき、作業ARなら警告と手順を中心品質へ寄せられます。視線追跡を使う場合も、視線そのものを保存せず、UIを中心保護に切り替えたという判断だけを運用ログへ送る設計にできます。

Policy receipts can drive exhibition, work-AR, and gaze-aware layouts without retaining gaze traces.

俯瞰メモBird's-eye memo

フォービエーションは「画質を落とす」機能ではなく、どの情報を利用者の確かな視野に置き続けるかを選ぶ機能です。性能が苦しいときほど、周辺の華やかさを守るより、中心の意味・安全・読める指示を守る優先順位が体験の信頼を決めます。

Foveation is a choice about which information remains dependable in the user's view.
