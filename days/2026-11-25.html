今日の重要トピックKey topics today

  1. WebXR Device API は immersive session を transient activation 内で開始し、XRSession の frame loop を session 終了まで扱う流れを定義する。 WebXR session startup is user-activated and its frame loop is session-scoped.
  2. XRSession.visibilityState は document の visibilityState と別物で、visible / visible-blurred / hidden を持つ。 XR visibility is distinct from document visibility.
  3. hidden では XR の requestAnimationFrame callback と input controller 処理が止まり、visible-blurred では frame が間引かれ input が処理されない場合がある。 Hidden and blurred states change both cadence and input policy.
  4. XRFrame.getViewerPose() は session frame callback 内で読むため、可視性変化をまたぐ古い観測を現在の pose や操作確認に転用しない。 Viewer poses are frame observations, not durable permission to commit an action.

注目事例と何が面白いかNotable example and why it matters

W3C WebXR Device API は、ユーザーの transient activation で session を始め、session ごとの frame loop を動かす流れを示します。MDN の visibilityState 解説が特に重要なのは、headset 上の表示状態がページ自体の可視性とは一致しないこと、hidden では frame callback が実行されず input も扱われないことを明確にしている点です。公式資料は挙動の根拠として参照し、公開アーカイブには自作の2本だけを載せます。

Official material distinguishes session visibility from document visibility; this archive publishes original interaction studies, not an external-demo list.

表現・インタラクションのアイデアExpression and interaction idea

本命 Visibility Pose Conductor は visible / visible-blurred / hidden を切り替え、点として描く fresh pose、input の可否、frame cadence の意味を一枚の舞台にします。派生 Re-entry Intent Gate は、focus を失う前の配置 intent を復帰時に自動実行せず、fresh frame の後にもう一度確認へ戻す小さな状態機械です。

The main conducts pose and input policy by visibility; the derivative makes re-entry a renewed-confirmation path.

制作に使えそうな技術メモProduction note

実装では session.addEventListener('visibilitychange', ...) で visibilityState を読むだけでなく、hidden / visible-blurred へ移った時点で連続操作・haptic・確定待ちを保留します。render callback 内で frame.getViewerPose(referenceSpace) を読み、null や state 変化後の stale pose で配置・anchor 作成を確定しません。visible 復帰後は最初の fresh frame で候補を再評価し、ユーザーの再確認を待ちます。

Listen for visibility changes, hold commitments, obtain a fresh pose only inside a frame callback, then re-evaluate and reconfirm after return.

サンプルデータの可能性と組み合わせSample data potential and combinations

保存するなら pose や映像ではなく、visibility の遷移、input の hold / confirm、復帰までの時間、再評価の成否だけを receipt にします。展示では明滅ではなく音量・粒子密度を状態に結び、業務 XR では安全な中断理由に、教育では frame lifecycle の観察に転用できます。11月23日の参照空間回復と11月24日の anchor receipt を、同じ再確認 UI に束ねられます。

State-only receipts can connect recovery, anchors, art cues, and operational safety without retaining poses or imagery.

俯瞰メモBird's-eye memo

XR がいったん見えなくなったとき、アプリに必要なのは「続ける」意志よりも、いま誰に何が見え、何が観測できるかを切り分ける静けさです。可視性は描画最適化の信号であると同時に、操作の根拠を更新する境界です。復帰を自動実行にしないだけで、空間の不確かさを利用者に押しつけない体験へ近づきます。

Visibility is both a rendering signal and a boundary for action authority; re-entry should restore choice, not silently execute it.
