今日の重要トピックKey topics today

  1. WebXR Hit Test Module は `XRTransientInputHitTestResult` に `inputSource` と `results` を持たせ、transient input の hit-test 結果を入力源ごとに束ねます。 The WebXR Hit Test Module gives `XRTransientInputHitTestResult` both `inputSource` and `results`, grouping transient hit-test results by input source.
  2. 同モジュールの `requestHitTestSourceForTransientInput()` は `profile`、`entityTypes`、`offsetRay` を受け取り、frame ごとに `getHitTestResultsForTransientInput()` で結果を読む設計です。 `requestHitTestSourceForTransientInput()` accepts `profile`, `entityTypes`, and `offsetRay`, then `getHitTestResultsForTransientInput()` reads per-frame results.
  3. WebXR Device API は transient input を、screen pointer や `transient-pointer` のように短時間だけ active input sources に入る入力として説明しています。 The WebXR Device API describes transient input as short-lived active input sources, such as screen pointers or `transient-pointer` inputs.
  4. Permissions Policy は `xr-spatial-tracking` を WebXR の policy-controlled feature として扱い、iframe では `allow` 属性と observable policy の差を起動前に見る価値があります。 Permissions Policy treats `xr-spatial-tracking` as a WebXR policy-controlled feature, making iframe `allow` attributes and observable policy useful launch probes.
  5. 今日の公開カードは外部デモではなく、このワークスペース内の `Transient Hit Group Router` と `Iframe Policy Allow Matrix` の2本です。 Today's public cards focus on the original workspace samples, `Transient Hit Group Router` and `Iframe Policy Allow Matrix`, not external demos.

注目事例と何が面白いかNotable example and why it matters

注目したのは、通常の hit-test result ではなく transient input hit-test result が `XRInputSource` ごとの束として返る点です。タップ、視線 intent、補助 pointer が同じ frame に重なった時、単に最初の hit を使うのではなく、どの inputSource のどの results を commit したかを ledger 化できます。Immersive Web Samples の通常 hit-test は reticle 配置の基礎として参考にしつつ、今日の中心はこのワークスペース内で作った grouped result router です。

The interesting point is that transient input hit-test results come back as groups per `XRInputSource`, not just as ordinary hit-test results. When a tap, gaze intent, and auxiliary pointer overlap in one frame, a ledger can record which inputSource and which results were committed instead of blindly using the first hit. The regular Immersive Web hit-test sample remains useful background for reticle placement, but today's focus is the grouped result router built in this workspace.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Transient Hit Group Router` は、profile、inputSource group 数、results 数、pose age、grouping confidence、hit-test feature、`xr-spatial-tracking` policy、同一 frame dedupe を動かし、`COMMIT TRANSIENT HIT`、`PATCH WITH LAST HIT`、`HOLD RETICLE`、`BLOCK SOURCE` を出します。派生サンプル `Iframe Policy Allow Matrix` は、親ページで iframe `allow` 属性を組み替え、`iframe.permissionsPolicy` が読める場合は observable policy を比較します。

The main sample, `Transient Hit Group Router`, lets you adjust profile, inputSource group count, result count, pose age, grouping confidence, hit-test feature, `xr-spatial-tracking` policy, and same-frame dedupe, then routes to `COMMIT TRANSIENT HIT`, `PATCH WITH LAST HIT`, `HOLD RETICLE`, or `BLOCK SOURCE`. The derivative `Iframe Policy Allow Matrix` changes iframe `allow` attributes from the parent page and compares observable policy when `iframe.permissionsPolicy` is available.

制作に使えそうな技術メモProduction note

実機版では `requestSession("immersive-ar", { requiredFeatures: ["hit-test"] })` の後に `requestHitTestSourceForTransientInput({ profile: "generic-touchscreen", offsetRay: new XRRay() })` を作り、XR frame 内で `frame.getHitTestResultsForTransientInput(source)` を読みます。戻り値は `XRTransientInputHitTestResult` の配列なので、`inputSource.targetRayMode`、`profiles`、`results.length`、各 result の `getPose(baseSpace)`、event timestamp を1行ずつ保存すると後日の replay に使えます。source は不要になった時に `cancel()` します。

A device-backed version should call `requestHitTestSourceForTransientInput({ profile: "generic-touchscreen", offsetRay: new XRRay() })` after `requestSession("immersive-ar", { requiredFeatures: ["hit-test"] })`, then read `frame.getHitTestResultsForTransientInput(source)` inside the XR frame. Because the return value is an array of `XRTransientInputHitTestResult`, saving `inputSource.targetRayMode`, `profiles`, `results.length`, each result's `getPose(baseSpace)`, and event timestamp as ledger rows makes later replay possible. Call `cancel()` when the source is no longer needed.

俯瞰メモBird's-eye memo

ここ数日のテーマは、AR の配置を「当たった / 当たらない」ではなく、policy、consent、camera frame、input event、pose、hit result を揃えた commit ledger として扱う方向に集約しています。今日の transient grouping で inputSource 単位の責任範囲が見えたので、次は anchor 作成、undo、restore、haptics を同じ source id にぶら下げると、実機デバッグと展示中の説明 UI が作りやすくなります。

Recent themes are converging on treating AR placement not as simply hit or miss, but as a commit ledger combining policy, consent, camera frame, input event, pose, and hit result. Today's transient grouping exposes responsibility per inputSource, so the next useful layer is hanging anchor creation, undo, restore, and haptics off the same source id for device debugging and exhibition-facing explanation UI.

今日のミニ試作候補Today's mini prototype candidate

本命として採用した候補は `Transient Hit Group Router` です。何が動くか: transient input profile、source group 数、results 数、pose age、confidence、policy を操作し、inputSource ごとの hit-test 結果を commit / patch / hold / block に分類します。次に足すなら、実 `requestHitTestSourceForTransientInput()` の結果を IndexedDB ledger に保存します。派生として `Iframe Policy Allow Matrix` も実装しました。何が動くか: iframe `allow` 属性を切り替え、親ページから見える observable policy と embed score を比較します。次に足すなら、親 / 子を別ファイル化し、GitHub Pages 上で same-origin と cross-origin 埋め込み差を実測します。

The selected main prototype is `Transient Hit Group Router`. What it does: adjusts transient input profile, source group count, result count, pose age, confidence, and policy, then classifies per-inputSource hit-test results into commit / patch / hold / block. Next addition: save real `requestHitTestSourceForTransientInput()` results into an IndexedDB ledger. The derivative `Iframe Policy Allow Matrix` was also implemented. What it does: toggles iframe `allow` attributes and compares parent-observable policy with an embed score. Next addition: split parent and child into separate files and measure same-origin versus cross-origin embed behavior on GitHub Pages.
