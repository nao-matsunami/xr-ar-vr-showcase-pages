今日の重要トピックKey topics today

  1. W3C WebXR Hit Test Module は `hit-test` feature descriptor、`entityTypes`、`offsetRay`、`XRHitTestSource`、`XRHitTestResult.getPose()` を整理しており、配置候補の入力モデルを作る基礎になります。 The W3C WebXR Hit Test Module defines the `hit-test` feature descriptor, `entityTypes`, `offsetRay`, `XRHitTestSource`, and `XRHitTestResult.getPose()`, forming the placement-candidate input model.
  2. Hit Test Module の説明では、ray が現実世界の geometry と交差した点と surface orientation を返すことが主目的で、床・壁・メッシュへの配置 UX と直結します。 The Hit Test Module frames the core purpose as ray intersection with real-world geometry plus surface orientation, directly supporting floor, wall, and mesh placement UX.
  3. WebXR Anchors Module は 2026-04-27 の Editor's Draft で、`anchors` feature、`XRAnchor.anchorSpace`、`XRFrame.createAnchor()`、`XRHitTestResult.createAnchor()`、persistent anchor の考え方を示しています。 The WebXR Anchors Module Editor's Draft dated 2026-04-27 describes the `anchors` feature, `XRAnchor.anchorSpace`, `XRFrame.createAnchor()`, `XRHitTestResult.createAnchor()`, and persistent anchors.
  4. MDN の `XRFrame.getHitTestResults()` は secure context と限定対応を明示し、実装では `requestHitTestSource()` を作って frame loop 内で結果を読む流れを確認できます。 MDN's `XRFrame.getHitTestResults()` page calls out secure context and limited support, while showing the production flow of creating a hit-test source and reading results inside the frame loop.
  5. Immersive Web Samples の hit-test / anchors ページは外部デモとして参照にとどめ、自作サンプルでは実機がなくても gate policy とログ payload を検証できる形にしました。 Immersive Web hit-test / anchors samples are used as reference demos only; today's original sample makes gate policy and log payload testable without a real device.

注目事例と何が面白いかNotable example and why it matters

今日の注目は、WebXR Hit Test Module と WebXR Anchors Module の接続点です。hit-test は ray と現実 geometry の交差結果を返し、anchors はその pose を環境に固定して追跡する仕組みを担います。面白いのは、`XRHitTestResult.createAnchor()` があるからといって即作成すればよいわけではなく、実際の UX では結果の傾き、距離、entity type、数フレームの安定度、ユーザーへの触覚/音 cue を見て「今は置いてよいか」を決める policy が必要になるところです。

Today's notable point is the connection between the WebXR Hit Test Module and WebXR Anchors Module. Hit testing returns intersections between a ray and real-world geometry, while anchors keep the resulting pose tracked relative to the environment. The interesting part is that `XRHitTestResult.createAnchor()` does not mean every result should be committed immediately; practical UX needs policy around surface tilt, distance, entity type, multi-frame stability, and tactile/audio cues before deciding whether placement is allowed.

表現・インタラクションのアイデアExpression and interaction idea

サンプルでは `entityTypes` を auto / plane / point / mesh で切り替え、`offsetRay`、surface tilt、target distance、tracking jitter、history window を操作します。canvas には疑似 ray、候補 entity、best result、履歴 centroid、commit ring、作成済み anchor を描きます。score が 72% 以上なら Commit で anchor を置け、低い場合は hold / reject として cue を変えるため、reticle が単なる点ではなく「置ける理由」を可視化する UI として扱えます。

The sample lets you switch `entityTypes` between auto / plane / point / mesh and adjust `offsetRay`, surface tilt, target distance, tracking jitter, and history window. The canvas draws the simulated ray, candidate entities, best result, history centroid, commit ring, and committed anchors. When the score is at least 72%, Commit places an anchor; otherwise the state becomes hold / reject with different cues, turning the reticle from a simple dot into UI that shows why placement is allowed.

制作に使えそうな技術メモProduction note

実機では `navigator.xr.requestSession('immersive-ar', { requiredFeatures: ['hit-test'], optionalFeatures: ['anchors', 'dom-overlay'] })` のように開始し、viewer space から `requestHitTestSource()` を作り、`XRSession.requestAnimationFrame()` 内で `frame.getHitTestResults(source)` を読む流れになります。anchor 作成は `hitTestResult.createAnchor()` または `frame.createAnchor(pose, space)` へ進みますが、frame の active 期間、feature policy / secure context、entity type の有無、persistent anchor の上限や削除を adapter 側で扱う必要があります。

On real devices, the flow is to request an `immersive-ar` session with `requiredFeatures: ['hit-test']` and optional anchors / DOM overlay as needed, create a hit-test source from viewer space, then read `frame.getHitTestResults(source)` inside `XRSession.requestAnimationFrame()`. Anchor creation proceeds through `hitTestResult.createAnchor()` or `frame.createAnchor(pose, space)`, but the adapter should handle frame active lifetime, feature policy / secure context, missing entity types, and persistent-anchor limits or deletion.
