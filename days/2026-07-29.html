今日の重要トピックKey topics today

  1. WebXR Device API の `isSessionSupported()` は `inline` 以外では `xr-spatial-tracking` Permissions-Policy にブロックされると `SecurityError` で reject されるため、XR CTA の表示設計にも policy 起因の失敗を織り込む必要がある。 For non-inline modes, the WebXR Device API rejects `isSessionSupported()` with `SecurityError` when `xr-spatial-tracking` Permissions-Policy blocks the document, so XR CTA design needs to account for policy-driven failure.
  2. MDN は `xr-spatial-tracking` directive が `navigator.xr.isSessionSupported()`、`requestSession()`、`devicechange` に影響し、既定 allowlist は `self` だと整理している。 MDN documents that the `xr-spatial-tracking` directive affects `navigator.xr.isSessionSupported()`, `requestSession()`, and `devicechange`, with a default allowlist of `self`.
  3. `requestSession()` は session feature ごとに user consent や Permissions-Policy の要件が異なり、`hit-test` や `depth-sensing` は `xr-spatial-tracking` の対象として扱われる。 `requestSession()` has different user-consent and Permissions-Policy requirements per session feature; `hit-test` and `depth-sensing` are covered by `xr-spatial-tracking`.
  4. Immersive Web の explainer は `requiredFeatures` が満たされないと session 作成を止め、`optionalFeatures` は使えれば有効化されるが欠けても session 作成を止めないという progressive enhancement の使い分けを明確にしている。 The Immersive Web explainer clarifies that missing `requiredFeatures` blocks session creation while missing `optionalFeatures` should not, making progressive enhancement a launch-time design tool.
  5. 実装上は `navigator.xr` の存在確認、`isSessionSupported()`、user activation 内の `requestSession()`、session 後の reference space / feature 使用失敗を、1 つの例外処理ではなく段階別ログとして扱うのがよい。 Implementation should treat `navigator.xr` presence, `isSessionSupported()`, user-activated `requestSession()`, and post-session reference-space/feature failures as staged logs rather than one generic catch block.

注目事例と何が面白いかNotable example and why it matters

今日の注目は派手なレンダリング API ではなく、`xr-spatial-tracking` と feature negotiation です。XR 体験は、デバイスがない、iframe やヘッダで policy が閉じている、ユーザー操作ではない、必須 feature が強すぎる、という複数の段階で失敗します。ここを UI とログで分けて扱うと、ユーザーには次に押すべき CTA や 2D fallback を出し、開発者にはどの gate で止まったかを明示できます。

Today's notable point is not a flashy rendering API but `xr-spatial-tracking` and feature negotiation. XR launch can fail because there is no device, policy blocks the document, the call lacks user activation, or required features are too strict. Separating these gates in UI and logs lets users see the right CTA or 2D fallback while developers see exactly where launch stopped.

表現・インタラクションのアイデアExpression and interaction idea

サンプルでは API、POLICY、INTENT、FEATURES、SESSION を横一列の gate として描き、失敗した段階だけ赤い経路に変えます。右側の slider で policy allowance、user activation、optional feature confidence、required feature strictness を変えると、中央の decision ring と fallback card が更新されます。`Probe browser` は `navigator.xr` の presence だけを実測し、`Simulate tap request` は実際の permission prompt を出さずに requestSession 結果ログを疑似生成します。

The sample draws API, POLICY, INTENT, FEATURES, and SESSION as a horizontal gate pipeline, turning only the failing stage red. Sliders adjust policy allowance, user activation, optional feature confidence, and required feature strictness, which updates the decision ring and fallback card. `Probe browser` only checks `navigator.xr` presence, while `Simulate tap request` creates a requestSession-style log without showing a real permission prompt.

制作に使えそうな技術メモProduction note

実装では `requiredFeatures` を最小にし、`hit-test`、`anchors`、`depth-sensing`、`dom-overlay` のような feature は、体験の成立条件でない限り `optionalFeatures` に寄せます。`isSessionSupported()` は `XRSessionInit` を受け取らないため、session mode の可否と feature 可否を混同しないことが重要です。例外は `SecurityError`、`NotAllowedError`、`NotSupportedError` などを gate 名に変換して、iframe 埋め込み、user activation、feature strictness のどこを直すべきか出します。

Keep `requiredFeatures` minimal, and put features like `hit-test`, `anchors`, `depth-sensing`, and `dom-overlay` in `optionalFeatures` unless they are essential. Since `isSessionSupported()` does not take `XRSessionInit`, do not confuse session-mode support with feature support. Map exceptions such as `SecurityError`, `NotAllowedError`, and `NotSupportedError` into gate names so the UI can point to iframe policy, user activation, or feature strictness.
