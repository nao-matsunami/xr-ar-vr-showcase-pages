今日の重要トピックKey topics today

  1. persistent handle は origin 内の persistent anchor を識別する値であり、再配置の成功を保証しない。 A persistent handle is identity, not placement proof.
  2. restore が object を返しても trackedAnchors と getPose() を観測するまで復元を確定しない。 Restore resolution is not a tracked pose.
  3. 一時的な pose null は hold にし、re-hit の retry budget を消費しない。 Null poses should hold rather than retry.
  4. restore miss では既存 marker を残し、再配置は識別子ごとに一度だけ許可する。 A restore miss needs a bounded re-hit.

注目事例と何が面白いかNotable example and why it matters

Immersive Web の Hit Test with Anchors は、表面上の hit と空間固定を結ぶ最小例です。Anchors Module は persistent handle を origin 内で管理する一方、追跡位置が一時的に不明な frame と、もう追跡されない状態を分けます。本命はこの非対称性を restore 成功ではなく evidence の積み上げとして可視化します。

制作に使えそうな技術メモProduction note

immersive-ar session で anchors を required / optional feature として交渉し、XRAnchor.requestPersistentHandle() の解決値を保存します。次回は XRSession.restorePersistentAnchor(uuid) の object 解決、frame.trackedAnchors の所属、frame.getPose(anchor.anchorSpace, referenceSpace) の可否を同一 receipt に記録します。pose null は hold、restore reject は再 hit の候補ですが、UUID 単位の retry budget を設けます。

Persist the handle, then require restoration, tracked membership, and a usable pose before commitment.

Evidence receipts can be correlated with environment, device, and content confidence.
