今日の重要トピックKey topics today

  1. WebXR の requiredFeatures は開始に必須の条件で、満たせない場合は session を作成しない。 Required features form a hard session-start gate.
  2. optionalFeatures は利用できれば有効化されるが、不在でも session 作成を止めない。 Optional features enable progressive enhancement.
  3. immersive session の requestSession は通常 user activation の中で呼ぶ必要があり、isSessionSupported は成功予約ではない。 Support probes do not reserve immersive sessions.
  4. XRReferenceSpace の reset は tracking origin の不連続を示し、以前の pose と fresh frame を混ぜない設計が必要になる。 Reference-space resets require fresh-frame evaluation.

注目事例と何が面白いかNotable example and why it matters

WebXR Device API は requiredFeatures と optionalFeatures を分け、前者が利用できなければ session 作成を拒否し、後者は使えれば有効にする契約を示します。公式 samples には input、hit-test、framebuffer / viewport scaling などが揃い、同じ機能でも『成立に必要か、表現を育てる追加か』を分離する見方ができます。外部デモは根拠として参照し、公開アーカイブには自作試作だけを置きます。

The specification's required/optional split is a practical interaction-design contract, not just API syntax.

制作に使えそうな技術メモProduction note

immersive session の requestSession は user activation に結び付け、isSessionSupported の結果だけで開始成功を約束しません。requiredFeatures は本当に無ければ体験が破綻するものへ限定し、optionalFeatures は取得結果を実際に試してから使います。reference space の reset を受けたら、変換を反映するまで古い pose、hit-test、anchor 候補を現在の commit に流用しない方針が安全です。

Request inside activation, keep required features minimal, and re-evaluate spatial evidence after reset.

サンプルデータの可能性と組み合わせSample data potential and combinations

feature receipt には session mode、feature の要求区分、結果、fallback を残し、空間画像や生の pose は保存しない設計が扱いやすいです。展示なら required / optional を植物の根と花に対応させ、業務 UI なら許可・失敗・代替経路の説明に、教育なら probe と request の違いを示す教材にできます。Reset Ribbon の freshness 状態は、11月26日の input source 消失後の操作再開判定とも組み合わせられます。

Small capability and freshness receipts can support installation, operational UI, and teaching without retaining spatial data.
