今日の重要トピックKey topics today

  1. W3C WebXR Gamepads Module Level 1 は XR input source の `gamepad` と `xr-standard` mapping を定義し、XR controller の button / trigger / thumbstick / touchpad 状態を WebXR 側から扱う前提を整理している。 The W3C WebXR Gamepads Module Level 1 defines `gamepad` on XR input sources and the `xr-standard` mapping, establishing how button, trigger, thumbstick, and touchpad state can be handled from WebXR.
  2. Gamepad API は output controls として haptic actuator / vibration actuator を定義し、ユーザーエージェントが利用可能な gamepad の haptic effect 再生を指示するモデルを示している。 The Gamepad API defines output controls such as haptic actuators and vibration actuators, with a user-agent-mediated model for playing haptic effects on available gamepads.
  3. MDN の `XRInputSource` は `gamepad`、`targetRaySpace`、`gripSpace`、`profiles`、`handedness` を入口として説明しており、実 controller の feedback を入力ソース単位で考える助けになる。 MDN's `XRInputSource` page explains `gamepad`, `targetRaySpace`, `gripSpace`, `profiles`, and `handedness`, which helps frame feedback per input source.
  4. Immersive Web Samples の Controller State / Input Tracking / Input Profiles は、XRInputSource の状態表示や profile ベースの controller 扱いを確認する公式デモ入口として引き続き有用です。 Immersive Web Samples such as Controller State, Input Tracking, and Input Profiles remain useful official demo entry points for inspecting XRInputSource state and profile-based controller handling.
  5. 今日の実装では実 actuator がないブラウザでも同じ decision payload を見られるようにし、実機では `pulse()` または `playEffect()` を試す二段構えにしました。 Today's implementation keeps the same decision payload visible when no real actuator exists, while trying `pulse()` or `playEffect()` on environments that expose haptics.

注目事例と何が面白いかNotable example and why it matters

今日の注目は、Immersive Web Samples の Controller State と、WebXR Gamepads Module が整理する `XRInputSource.gamepad` の扱いです。XR の入力は select / squeeze だけでなく、button value、axis、profile、handedness、そして haptic actuator の有無まで含めて体験設計に影響します。特に AR の anchor 保存では、保存成功、保存拒否、ドリフト、近接警告が同時に起きるため、全部を別々に鳴らすのではなく、短く一貫した feedback cue にする必要があります。

Today's notable reference is the Immersive Web Controller State sample together with the WebXR Gamepads Module's model for `XRInputSource.gamepad`. XR input is not only select / squeeze; button values, axes, profiles, handedness, and haptic actuator availability all affect interaction design. For AR anchor saving, save success, rejection, drift, and proximity warnings can happen at the same time, so they should be mixed into one compact, consistent feedback cue instead of being emitted independently.

表現・インタラクションのアイデアExpression and interaction idea

サンプルでは canvas 上の照準位置と 4 つのイベント強度から、触覚キューの priority、duration、intensity、decision を毎フレーム計算します。Save / Warning / Conflict のプリセットで、保存成功が優先される状態、ドリフト警告が勝つ状態、拒否と成功がぶつかる状態を切り替えられます。Mix pulse は 1 回分の decision を出し、Event burst は cooldown によって連続 pulse が抑制される様子を見せます。

The sample computes haptic priority, duration, intensity, and decision every frame from a canvas cursor position and four event weights. Save / Warning / Conflict presets switch between states where save confirmation wins, drift warning wins, or rejection and confirmation conflict. Mix pulse emits one decision, while Event burst shows how cooldown suppresses repeated pulses.

制作に使えそうな技術メモProduction note

実装時は XR frame loop 内で `session.inputSources` を走査し、`inputSource.gamepad` の button / axis 値を読む層と、アプリ側の semantic event を作る層を分けます。触覚出力は `gamepad.hapticActuators?.[0]?.pulse(intensity, duration)` を優先し、環境によっては `vibrationActuator.playEffect()` を試します。ただし haptic support は不揃いなので、同じ payload から色、音、UI 状態も生成できるようにし、cooldown、priority、最大 duration を明示するのが扱いやすいです。

In production, iterate `session.inputSources` in the XR frame loop and separate the layer that reads `inputSource.gamepad` button / axis values from the layer that creates semantic app events. Prefer `gamepad.hapticActuators?.[0]?.pulse(intensity, duration)` for haptic output, and try `vibrationActuator.playEffect()` where available. Because haptic support is uneven, generate color, audio, and UI state from the same payload, with explicit cooldown, priority, and maximum duration.

今日のサンプルからは、event weight、priority、decision、duration、intensity、cooldown hold、support probe、queue order を取れます。前日の pose history / anchor haptics と組み合わせると、保存直前の confidence と保存後の feedback を一本化できます。さらに Web Audio、controller profile、左右 handedness、展示 UI、作業現場の危険通知、教育向け step feedback、AI が判定した placement quality とつなぐと、触覚を単なる振動ではなく状態説明の圧縮チャンネルとして使えます。

Today's sample yields event weights, priority, decision, duration, intensity, cooldown holds, support probe results, and queue order. Combined with yesterday's pose-history / anchor-haptics sample, it can unify pre-save confidence and post-save feedback. Adding Web Audio, controller profiles, handedness, exhibit UI, field-safety warnings, learning-step feedback, or AI placement-quality scoring turns haptics from mere vibration into a compact state-explanation channel.
