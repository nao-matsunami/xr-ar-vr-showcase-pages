今日の重要トピックKey topics today

  1. WebXR Device API は session support 確認、transient activation、`requestSession()`、XR animation frame loop という基本 flow を明示しており、layer 復旧もこの frame loop の中で扱う必要があります。 The WebXR Device API defines the basic flow of checking session support, waiting for transient activation, calling `requestSession()`, and running an XR animation frame loop, so layer recovery belongs inside that loop.
  2. MDN の `XRQuadLayer` は `layers` feature が必要で、`XRWebGLBinding.createQuadLayer()` または `XRMediaBinding.createQuadLayer()` から作成し、`session.updateRenderState()` の layers に渡す流れを示しています。 MDN's `XRQuadLayer` notes that the `layers` feature is required, quad layers are created with `XRWebGLBinding.createQuadLayer()` or `XRMediaBinding.createQuadLayer()`, and they are presented through `session.updateRenderState()` layers.
  3. `XRQuadLayer` の `redraw` event は layer resource lost や compositor が layer を再投影できない時の再描画 cue として扱えるため、再描画・延期・再作成の分岐が必要です。 `XRQuadLayer`'s `redraw` event can be treated as a cue for lost resources or compositor reprojection failure, requiring branches for redraw, defer, and rebuild.
  4. Immersive Web Layers Samples には projection / quad / equirect / media / destroy layer / layer-vs-non-layer / layer hit test などがあり、layer の表現品質と lifecycle を横断して確認できます。 The Immersive Web Layers Samples cover projection, quad, equirect, media, destroy layer, layer-vs-non-layer, and layer hit test examples, making them useful references for quality and lifecycle checks.
  5. 今日の公開カードは外部デモではなく、このワークスペース内で作った `Layer Redraw Recovery Console` と `Layer Proxy Density Tuner` の2本です。 Today's public cards focus on the original workspace samples `Layer Redraw Recovery Console` and `Layer Proxy Density Tuner`, not external demos.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Layer Redraw Recovery Console` は redraw 発生頻度、texture age、frame budget pressure、viewer motion、layer kind、resources lost、static content を操作し、`CLEAN`、`REDRAW NEXT FRAME`、`DEFER REDRAW`、`REBUILD LAYER` に分岐します。派生サンプル `Layer Proxy Density Tuner` は layer UI 上の操作数、proxy padding、pointer jitter、layer distance、layout、gaze input を動かし、proxy を広げる、target をまとめる、layout を止める、準備完了を判定します。

The main sample, `Layer Redraw Recovery Console`, adjusts redraw frequency, texture age, frame-budget pressure, viewer motion, layer kind, resource loss, and static-content state, then routes to `CLEAN`, `REDRAW NEXT FRAME`, `DEFER REDRAW`, or `REBUILD LAYER`. The derivative `Layer Proxy Density Tuner` adjusts control count, proxy padding, pointer jitter, layer distance, layout, and gaze input, then decides whether to expand proxies, merge targets, block the layout, or proceed.

制作に使えそうな技術メモProduction note

実機版では `XRSession.requestAnimationFrame()` の loop 内で layer ごとの dirty flag、last redraw time、texture age、estimated redraw cost、viewer pose delta を記録します。`redraw` event が来たら即座に canvas を描き直すだけでなく、static layer なら予算の低い frame へ延期し、resource lost 相当なら `XRWebGLBinding` または `XRMediaBinding` から layer を作り直して `session.updateRenderState({ layers })` に戻します。quad layer 上のボタンは projection layer 側の透明 mesh / reticle proxy と対応表を持たせ、layout 変更時に proxy bounds を再計算します。

A device-backed version should record per-layer dirty flags, last redraw time, texture age, estimated redraw cost, and viewer-pose delta inside the `XRSession.requestAnimationFrame()` loop. When a `redraw` event arrives, do more than repaint immediately: static layers can defer to a cheaper frame, while resource-loss cases should recreate the layer through `XRWebGLBinding` or `XRMediaBinding` and put it back into `session.updateRenderState({ layers })`. Buttons on a quad layer should keep a mapping to transparent meshes or reticle proxies in the projection layer, recalculating proxy bounds whenever layout changes.

今日のミニ試作候補Today's mini prototype candidate

本命として採用した候補は `Layer Redraw Recovery Console` です。何が動くか: redraw rate、texture age、budget、motion、layer kind、resource lost を操作し、clean、redraw、defer、rebuild を判定します。次に足すなら、実 canvas の再描画時間と `redraw` event 時刻を IndexedDB に保存して、日別の layer health log にします。派生として `Layer Proxy Density Tuner` も実装しました。何が動くか: control 数、padding、pointer jitter、距離、layout、gaze input を操作し、proxy 拡張、target 統合、layout block を判定します。次に足すなら、1本目の layer rebuild 時に proxy bounds を再同期し、古い proxy を自動で無効化します。

The selected main prototype is `Layer Redraw Recovery Console`. What it does: adjusts redraw rate, texture age, budget, motion, layer kind, and resource loss, then classifies clean, redraw, defer, or rebuild routes. Next addition: save real canvas redraw times and `redraw` event timestamps to IndexedDB as a daily layer-health log. The derivative `Layer Proxy Density Tuner` was also implemented. What it does: adjusts control count, padding, pointer jitter, distance, layout, and gaze input, then classifies proxy expansion, target merging, or layout blocking. Next addition: resync proxy bounds whenever the first sample rebuilds a layer and automatically invalidate stale proxies.
