今日の重要トピックKey topics today

  1. WebXR Layers は compositor の native refresh と異なる解像度を使い、文字などの可読性を独立に保てます。 Layers can preserve legibility independently.
  2. quality は default / text-optimized / graphics-optimized を表し、追加処理が性能へ影響し得ます。 Quality is a compositor hint with a performance tradeoff.
  3. 書換え可能な layer 属性は XR animation frame callback の終端で compositor に送られ、次の presentation で適用されます。 Writable properties commit at frame end and apply on the next presentation.
  4. layers は immersive-vr / immersive-ar 向けの optional feature であり、inline session には対応しません。 Layers target immersive AR and VR sessions.

注目事例と何が面白いかNotable example and why it matters

Layers では、アプリの描画レートが compositor の native refresh に届かなくても、既存の描画を再投影して滑らかさを保てます。さらに writable な属性は rAF callback の終端で compositor に送られ、次に提示される frame で効きます。本命はこの『JS の値』『pending commit』『見えている値』の混同を避けるための小さな計器です。

Layers decouple application work from native compositor presentation; the main sample makes property-write, commit, and visible state distinct.

制作に使えそうな技術メモProduction note

実機では session を optionalFeatures: ['layers'] で要求し、XRWebGLBinding または対応 binding から layer を作ります。属性変更は XR frame timestamp、layer ID、quality、opacity、forceMonoPresentation、commit を送った frame、実際に観察した presentation frame と一緒に記録します。quality hint は追加処理を招くため、可読性が必要な層に絞ります。

Request layers as an optional feature and record property writes with frame timestamps and observed presentation; use costly quality hints selectively.
