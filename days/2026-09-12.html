今日の重要トピックKey topics today

  1. Chrome 147 のリリースノートでは、WebXR Plane Detection が `detectedPlanes` と `lastChangedTime` を通じて実世界の壁、床、テーブルなどの flat surface 情報を提供する点が紹介されています。 Chrome 147's release notes describe WebXR Plane Detection as exposing real-world flat surfaces such as walls, floors, and tables through `detectedPlanes` and `lastChangedTime`.
  2. Immersive Web の Plane Detection 仕様は `plane-detection` feature descriptor、`XRFrame.detectedPlanes`、`XRPlane.planeSpace`、`polygon`、`orientation`、`semanticLabel` を整理しています。 The Immersive Web Plane Detection specification defines the `plane-detection` feature descriptor plus `XRFrame.detectedPlanes`, `XRPlane.planeSpace`, `polygon`, `orientation`, and `semanticLabel`.
  3. Plane Detection は Hit Test の単発結果よりも広い面の状態を扱える一方、平面の更新時刻、polygon の揺れ、semantic label の信頼度、Depth Sensing との一致をアプリ側で見る必要があります。 Plane Detection can reason about broad surfaces beyond single hit-test results, but applications still need to inspect update age, polygon jitter, semantic label confidence, and agreement with depth sensing.
  4. 昨日の Depth Sensing confidence gate から一歩進め、今日は depth が示す距離と plane が示す surface を同じ placement ledger に載せる設計にしました。 Building on yesterday's Depth Sensing confidence gate, today's design puts depth distance and plane surface state into the same placement ledger.
  5. 今日の公開カードは外部デモではなく、このワークスペース内で作った `Plane Detection Lifecycle Ledger` と `Plane Label Placement Router` の2本です。 Today's public cards focus on the original workspace samples `Plane Detection Lifecycle Ledger` and `Plane Label Placement Router`, not external demos.

注目事例と何が面白いかNotable example and why it matters

今日の注目は Chrome 147 の WebXR Plane Detection と、Immersive Web の Plane Detection 仕様 / explainer です。`plane-detection` feature が有効な AR session では、`XRFrame.detectedPlanes` から `XRPlane` の集合を読み、`planeSpace`、`polygon`、`orientation`、`semanticLabel`、`lastChangedTime` を配置判断に使えます。面白いのは、Hit Test がその瞬間の交点を返すのに対し、Plane Detection は surface の寿命や更新差分を扱える点です。公式情報は参照として使い、公開カードの中心はこのワークスペース内で作った平面ライフサイクル台帳と semantic 配置 router にしました。

Today's notable references are Chrome 147's WebXR Plane Detection note and the Immersive Web Plane Detection specification / explainer. In an AR session with the `plane-detection` feature enabled, `XRFrame.detectedPlanes` exposes a set of `XRPlane` objects whose `planeSpace`, `polygon`, `orientation`, `semanticLabel`, and `lastChangedTime` can guide placement decisions. The interesting distinction is that hit testing returns an intersection for the current moment, while plane detection exposes surface lifetime and update deltas. The official material is used as reference, while the public cards center on the original workspace plane lifecycle ledger and semantic placement router.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Plane Detection Lifecycle Ledger` は plane feature、semantic label、orientation、plane age、polygon area、normal drift、depth agreement、hit-test support、session active を操作し、`COMMIT PLANE`、`PATCH PLANE`、`HOLD PLANE`、`BLOCK PLANE` に分岐します。派生サンプル `Plane Label Placement Router` は配置したい object intent と detected label、面積、傾き、depth confidence、freshness、retarget tolerance を合わせ、floor、table、wall、reticle preview のどこに置くかを選びます。

The main sample, `Plane Detection Lifecycle Ledger`, adjusts plane feature availability, semantic label, orientation, plane age, polygon area, normal drift, depth agreement, hit-test support, and session activity, routing to `COMMIT PLANE`, `PATCH PLANE`, `HOLD PLANE`, or `BLOCK PLANE`. The derivative sample, `Plane Label Placement Router`, combines object intent with detected label, area, tilt, depth confidence, freshness, and retarget tolerance to choose between floor, table, wall, or reticle preview placement.

制作に使えそうな技術メモProduction note

実機版では `navigator.xr.requestSession('immersive-ar', { requiredFeatures: ['plane-detection'] })` または optional feature で session を開始し、各 frame で `frame.detectedPlanes` を読む構成にします。`XRPlane.lastChangedTime` を前回値と比較して geometry 更新を検出し、`planeSpace` の pose と `polygon` の面積 / normal drift を ledger row にします。`semanticLabel` は床、壁、テーブルなどの初期 route に使えますが、Depth Sensing の confidence や Hit Test の一致が弱い場合は配置確定ではなく preview / patch に落とす方が安全です。

A device-backed version can start an AR session with `navigator.xr.requestSession('immersive-ar', { requiredFeatures: ['plane-detection'] })` or the same descriptor as an optional feature, then read `frame.detectedPlanes` each frame. Compare `XRPlane.lastChangedTime` with the previous value to detect geometry updates, and log `planeSpace` pose plus polygon area and normal drift as ledger rows. `semanticLabel` can seed routes such as floor, wall, and table, but placement should fall back to preview or patch when depth confidence or hit-test agreement is weak.

俯瞰メモBird's-eye memo

ここ数日の流れは policy、camera、hit-test、anchors、layers、depth から plane へ進み、AR placement の材料がほぼ揃ってきました。Plane Detection は配置の文脈を与え、Hit Test は一点の確度を与え、Depth Sensing は現実遮蔽と距離の裏付けを与え、Anchors は持続性を与えます。今日の2本は、その中の plane を「広い面が見えた」という事実ではなく「どの用途へ渡せる surface か」として扱うための足場です。

The recent sequence has moved from policy, camera, hit testing, anchors, layers, and depth into planes, bringing together most ingredients for AR placement. Plane Detection provides placement context, Hit Test provides point-level confidence, Depth Sensing supports occlusion and distance evidence, and Anchors provide persistence. Today's two samples treat planes not merely as detected broad surfaces, but as surfaces that must be routed to the right use.

今日のミニ試作候補Today's mini prototype candidate

本命として採用した候補は `Plane Detection Lifecycle Ledger` です。何が動くか: plane feature、label、orientation、age、area、normal drift、depth agreement、hit-test support を操作し、commit、patch、hold、block を判定します。次に足すなら、実機の `frame.detectedPlanes` から plane id / polygon / lastChangedTime を IndexedDB に保存し、9月7日の anchor replay bridge へ handoff します。派生として `Plane Label Placement Router` も実装しました。何が動くか: object intent と detected label、面積、傾き、depth confidence、freshness、retarget tolerance から配置先を選びます。次に足すなら、1本目の plane score を2本目の retarget tolerance と anchor handoff policy に自動反映します。

The selected main prototype is `Plane Detection Lifecycle Ledger`. What it does: adjusts plane feature, label, orientation, age, area, normal drift, depth agreement, and hit-test support, then classifies commit, patch, hold, or block. Next addition: save real `frame.detectedPlanes` plane id / polygon / lastChangedTime rows into IndexedDB and hand them off to the September 7 anchor replay bridge. The derivative `Plane Label Placement Router` was also implemented. What it does: chooses a placement target from object intent, detected label, area, tilt, depth confidence, freshness, and retarget tolerance. Next addition: automatically map the first sample's plane score into the second sample's retarget tolerance and anchor handoff policy.
