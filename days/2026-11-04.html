今日の重要トピックKey topics today

  1. Depth Sensing は immersive XR session の depth-sensing feature と深度 type / usage / format の組合せで交渉する。 Depth sensing is negotiated with feature, type, usage, and format preferences.
  2. XRWebGLDepthInformation の raw depth は rawValueToMeters でメートル換算し、normDepthBufferFromNormView を通して座標を対応させる。 Raw depth needs meter conversion and normalized-view coordinate mapping.
  3. 深度情報は animation frame 中だけアクセスでき、取得できない・古い・境界に近い値を確定した遮蔽として扱わない。 Missing, stale, and boundary-adjacent depth should not become certain occlusion.
  4. 公式の GPU / CPU depth sample は提案中の機能であり、対応可否と縮退導線を先に設計する。 Depth proposals need capability-aware fallbacks.

注目事例と何が面白いかNotable example and why it matters

Immersive Web の公式 sample には CPU で深度を読むものと、projection layer で簡易遮蔽を行うものがあります。面白いのは、深度が単なる衝突判定ではなく、表示物を現実の奥へ退かせるレンダリング入力になる点です。本命はこの判断を depth 値・仮想物の深度・margin の receipt に分け、境界で即座に表示/非表示を反転させません。

Official samples show CPU depth access and simple projection-layer occlusion; the main prototype exposes the margin decision rather than making depth binary.

表現・インタラクションのアイデアExpression and interaction idea

mint の物体は表示可能、amber は深度境界の保留、red は遮蔽または stale depth による停止として示します。派生は同じ配置マーカーを、fresh なら commit、aging なら preview + confirm、stale なら block に遷移させます。深度の精度を数値だけで見せず、ユーザーに許す行為を変える表現です。

Color encodes show, hold, and stop; the derivative turns depth age into different allowed actions.

制作に使えそうな技術メモProduction note

実機では immersive-ar の optionalFeatures に depth-sensing を置き、depthSensing の usagePreference / dataFormatPreference を指定して session.depthUsage と depthDataFormat を確認します。XRWebGLBinding.getDepthInformation(view) は XR animation frame 内で呼び、rawValueToMeters と normDepthBufferFromNormView を shader に渡します。値が null、座標が未対応、または時刻差が大きいときは、遮蔽を断定せずフェード・保留・再取得に落とします。

Negotiate depth sensing, access it inside the XR animation frame, pass conversion data to the shader, and degrade safely for absent or stale depth.

サンプルデータの可能性と組み合わせSample data potential and combinations

本日の receipt は環境深度、仮想物深度、margin、capture の鮮度、最終 action を持ちます。匿名化した集計なら、展示ARの説明札、遠隔支援の注意領域、ゲームの遮蔽物、カメラ映像や空間音響の演出で、どの安全策が視覚的なちらつきや誤配置を減らすか比較できます。深度を恒久的な室内モデルとして保存せず、用途に必要な判定ログだけに絞る設計にもつながります。

Margin, age, and action receipts can evaluate safe depth policy without retaining a persistent room model.

俯瞰メモBird's-eye memo

深度は現実の正解画像ではなく、特定時刻・特定viewで得た測定です。遮蔽が少し不安定でも、保留やフェードを明示すれば、誤って現実物を貫通して見せるより体験の約束を保ちやすくなります。XRでは見た目の即応性と測定の不確かさを同じUIで扱うことが重要です。

Depth is a time- and view-bound measurement, so explicit uncertainty can be more trustworthy than brittle occlusion.
