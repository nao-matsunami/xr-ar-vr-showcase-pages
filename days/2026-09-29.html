今日の重要トピックKey topics today

  1. WebXR Device API は XRView ごとの viewport を描画先 framebuffer の矩形として扱い、実装側は frame ごとにその範囲へ描画します。 The WebXR Device API treats each XRView viewport as a rectangle in the target framebuffer, and applications render into that rectangle every frame.
  2. WebXR Layers API Level 1 では projection layer の sub image や texture 情報が layer 描画の単位になり、前日の attachment size audit と自然につながります。 In WebXR Layers API Level 1, projection-layer sub images and texture data become the unit of layer rendering, connecting naturally to yesterday's attachment-size audit.
  3. MDN の WebXR rendering guide は XR frame callback の時間予算と viewport 描画の流れを整理しており、crop guard を軽い row にする理由になります。 MDN's WebXR rendering guide explains XR frame callback budgets and viewport rendering flow, which is why crop guards should be lightweight rows.
  4. foveation や viewport の端寄りは UI、reticle、space warp tile の見え方に影響するため、体験品質ログとして保存する価値があります。 Foveation and edge-biased viewports affect UI, reticles, and space-warp tiles, so they are worth preserving as experience-quality logs.
  5. 今日の公開カードは外部デモではなく、自作の `XR Viewport Crop Guard Logger` と `Crop Row Foveation Replayer` の2本です。 Today's public cards are the original workspace samples `XR Viewport Crop Guard Logger` and `Crop Row Foveation Replayer`, not external demos.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `XR Viewport Crop Guard Logger` は viewport の幅、高さ、offset、foveation を操作し、`commit-viewport`、`expand-guard`、`foveation-hold`、`projection-fallback` を出します。派生サンプル `Crop Row Foveation Replayer` はその JSON row を貼り付け、tile ごとに `full-rate`、`lower-rate`、`guard-band`、`fallback` を再判定します。

The main sample, `XR Viewport Crop Guard Logger`, lets you change viewport width, height, offset, and foveation, then emits `commit-viewport`, `expand-guard`, `foveation-hold`, or `projection-fallback`. The derivative `Crop Row Foveation Replayer` accepts that JSON row and reclassifies tiles into `full-rate`, `lower-rate`, `guard-band`, or `fallback`.

制作に使えそうな技術メモProduction note

実装では `XRWebGLLayer.getViewport(view)` または Layers API の sub image 取得直後に、x / y / width / height と texture size、foveation、frame timestamp を最小 row に保存します。XR frame callback 内では判定を軽くし、詳細な tile policy は後段の replay 側に寄せると frame budget を守りやすいです。

In production, store x / y / width / height, texture size, foveation, and frame timestamp immediately after `XRWebGLLayer.getViewport(view)` or layer sub-image retrieval. Keep the XR frame callback classification light, and move detailed tile policy into a replay stage to protect the frame budget.
