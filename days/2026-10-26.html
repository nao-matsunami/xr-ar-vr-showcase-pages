今日の重要トピックKey topics today

  1. XRHitTestResult.createAnchor() は hit result に結びついた anchor を非同期で作成する。 Hit-test anchors are asynchronous.
  2. Promise 解決後でも anchor の属性は trackedAnchors に現れるまで確定扱いにしない。 Resolution is not tracked observation.
  3. getPose(anchorSpace) が null の frame は新しい placement の根拠にせず hold へ送る。 A null pose should not commit placement.
  4. restore miss 時の re-hit は、既存 marker を残したまま一度だけ許可する。 Re-hit needs a duplicate guard.

注目事例と何が面白いかNotable example and why it matters

Immersive Web の Hit Test with Anchors は、表面 hit と空間固定を結ぶ基本例です。Anchors explainer は、Promise が解決しても anchor が fully materialized ではなく、tracked anchors に現れて初めて属性が有効になる可能性を明記します。本命ではこの境界を UI の preview と commit にそのまま反映しました。

制作に使えそうな技術メモProduction note

immersive-ar session では hit-test と anchors を feature negotiation し、active XRFrame 中の XRHitTestResult.createAnchor() を使います。Promise 解決後は frame.trackedAnchors と frame.getPose(anchor.anchorSpace, referenceSpace) を確認して初めて placement を確定します。pose null や untracked は既存 visual を hold し、re-hit へ進む場合も marker ID ごとに一度だけ許可します。

Create in an active frame, then commit only after tracked membership and a usable pose.
