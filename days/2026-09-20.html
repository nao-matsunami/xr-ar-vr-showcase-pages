今日の重要トピックKey topics today

  1. WebXR Device API の 2026-06-09 Candidate Recommendation Draft は session lifecycle、`XRRenderState.layers`、`passthroughFullyObscured` など、実行時の表示契約を考える手がかりになります。 The 2026-06-09 Candidate Recommendation Draft of the WebXR Device API gives useful hooks for runtime display contracts, including session lifecycle, `XRRenderState.layers`, and `passthroughFullyObscured`.
  2. WebXR Layers API Level 1 は `XRProjectionLayer`、`XRQuadLayer`、`XRCylinderLayer`、`XREquirectLayer`、`XRWebGLBinding` の生成を整理しており、表示 fallback を contract として記録しやすい領域です。 WebXR Layers API Level 1 describes creation flows for `XRProjectionLayer`, `XRQuadLayer`, `XRCylinderLayer`, `XREquirectLayer`, and `XRWebGLBinding`, making display fallback suitable to record as a contract.
  3. MDN の `XRWebGLBinding` は secure context / experimental / limited availability とされ、layer を前提にしすぎず projection mesh や screen fallback を残す必要があります。 MDN marks `XRWebGLBinding` as secure-context, experimental, and limited availability, so layer-first designs still need projection mesh and screen fallback routes.
  4. Immersive Web proposal samples は depth sensing、plane detection、mesh detection などを扱っており、認識系 row と表示系 row を分けて保存する設計の参考になります。 The Immersive Web proposal samples cover depth sensing, plane detection, mesh detection, and related features, which helps separate recognition rows from display rows.
  5. 今日の公開カードは外部デモではなく、自作の `Scene Contract Readiness Ledger` と `Passthrough Obscuration Budget Dial` の2本です。 Today's public cards are the original workspace samples `Scene Contract Readiness Ledger` and `Passthrough Obscuration Budget Dial`, not external demos.

注目事例と何が面白いかNotable example and why it matters

9月19日は layer runtime capability と space stability を分けて記録しました。今日はその続きとして、表示 layer だけでなく depth、plane、anchor の readiness をまとめ、最終的に `world-locked-layer`、`occlusion-aware-mesh`、`reticle-preview-only`、`screen-fallback-row` のどれで scene を扱うかを contract として選びます。WebXR の実装差は単なる対応/未対応ではなく、session は始まるが layer が弱い、anchor はあるが depth が薄い、といった混合状態になりやすいので、状態を contract row にしておくのが面白いところです。

September 19 split layer runtime capability from space stability. Today continues from there by combining not only display-layer readiness but also depth, plane, and anchor readiness, then selecting whether the scene should use `world-locked-layer`, `occlusion-aware-mesh`, `reticle-preview-only`, or `screen-fallback-row`. WebXR differences are rarely just supported versus unsupported; sessions may start while layers are weak, or anchors may exist while depth is thin. Turning that mixed state into a contract row is the interesting part.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Scene Contract Readiness Ledger` は intent、depth confidence、plane stability、anchor confidence、layer readiness、motion pressure を操作し、選ばれた scene contract と各 sensor row の理由を表示します。派生サンプル `Passthrough Obscuration Budget Dial` は overlay size、opacity、depth trust、real-world priority から視界遮蔽の debt を計算し、`passthroughFullyObscured` を true にしてよい場面か、薄い preview / feather mask に戻すべき場面かを試します。

The main sample, `Scene Contract Readiness Ledger`, lets you adjust intent, depth confidence, plane stability, anchor confidence, layer readiness, and motion pressure, then shows the selected scene contract and the reason for each sensor row. The derivative `Passthrough Obscuration Budget Dial` computes an obscuration debt from overlay size, opacity, depth trust, and real-world priority, then tests whether `passthroughFullyObscured` should be true or whether the UI should return to a thin preview / feathered mask.

制作に使えそうな技術メモProduction note

`navigator.xr.requestSession()` の feature negotiation と、session 開始後の `XRRenderState.layers` / `XRWebGLBinding` / depth / plane / anchor の実測を別 row に分けると、失敗時の説明がかなり楽になります。`passthroughFullyObscured` は強い hint なので、没入 video のように本当に現実視界を覆う場面だけ true にし、AR 配置や dashboard では depth trust と real-world priority を見て feather / hold に戻す判定を挟むのがよさそうです。

Separating `navigator.xr.requestSession()` feature negotiation from runtime measurements for `XRRenderState.layers`, `XRWebGLBinding`, depth, planes, and anchors makes failures easier to explain. `passthroughFullyObscured` is a strong hint, so it should only become true when content really covers the real world, such as immersive video. For AR placement or dashboards, it is better to inspect depth trust and real-world priority before falling back to feather or hold routes.

俯瞰メモBird's-eye memo

9月中旬の流れは、実空間認識 row から表示 row へ進んでいます。depth / plane / mesh / anchor は「何が見えているか」、feature negotiation / layer runtime / scene contract は「どう出してよいか」です。今日の contract row を入れると、体験側の判断が `API対応状況` ではなく `この frame でユーザーに見せてよい表現` に近づきます。

The mid-September thread is moving from real-world recognition rows to display rows. Depth / plane / mesh / anchor describe what is visible; feature negotiation / layer runtime / scene contract describe how it may be shown. Adding today's contract row moves the experience decision away from plain API support and toward what expression is safe to show to the user in this frame.
