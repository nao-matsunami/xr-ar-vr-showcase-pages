表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Depth Motion Vector Budget Console` は depth usage、depth age、motion px、projection lead、hole ratio を操作し、depth plane、motion plane、reprojection guard を重ねます。派生サンプル `Space Warp Recovery Queue` は、本命 row が崩れた時に、detect-miss、disable / clamp motion vector、refresh depth、trim payload、resume / hold の frame queue を再生します。体験としては、XR の滑らかさを `魔法の補間` として隠すのではなく、どの補助データを信じて、どこから full render に戻すかを操作できるようにしています。

The main sample, `Depth Motion Vector Budget Console`, lets you manipulate depth usage, depth age, motion pixels, projection lead, and hole ratio while overlaying a depth plane, motion plane, and reprojection guard. The derivative sample, `Space Warp Recovery Queue`, replays a frame queue when the main row breaks down: detect miss, disable / clamp motion vectors, refresh depth, trim payload, then resume or hold. As an experience, it makes smooth XR less like hidden interpolation magic and more like an inspectable choice about which auxiliary data to trust and when to fall back to full rendering.

制作に使えそうな技術メモProduction note

保存する row は画像・深度 texture そのものではなく、`depthUsage`、`depthAgeMs`、`motionPx`、`projectionLeadMs`、`holeRatio`、`depthCoverage`、`motionVectorQuality`、`stability`、`compositorBudget`、`payloadKb`、`route` に絞りました。W3C Depth Sensing では `gpu-optimized` / `cpu-optimized`、data format、`matchDepthView`、`depthActive` の扱いが重要なので、実機版では `depthActive === false`、古い depth frame、`matchDepthView` false の時に queue 側へ落とすのが良さそうです。

The row stores derived values rather than images or depth textures: `depthUsage`, `depthAgeMs`, `motionPx`, `projectionLeadMs`, `holeRatio`, `depthCoverage`, `motionVectorQuality`, `stability`, `compositorBudget`, `payloadKb`, and `route`. In the W3C Depth Sensing spec, `gpu-optimized` / `cpu-optimized`, data formats, `matchDepthView`, and `depthActive` matter. On-device, it should drop into the queue when `depthActive === false`, the depth frame is stale, or `matchDepthView` is false.

サンプルデータの可能性と組み合わせSample data potential and combinations

今日の row は、Quest Browser / WebXR 実機検証で `なぜ Space Warp を止めたか`、`何フレームで復帰したか`、`depth と motion vector のどちらが原因か` を説明するログに向いています。映像や深度画像を保存しないため、デバッグ用にも展示 QA 用にも軽いです。AI と組み合わせるなら、session 後に row の時系列を読ませ、risk debt の上位要因、comfort-first と performance-first の差、payload を削るべき frame を要約させると便利です。

Today's rows are well suited for Quest Browser / WebXR device testing logs that explain why Space Warp was stopped, how many frames recovery took, and whether depth or motion vectors caused the issue. Because they avoid saving video or depth imagery, they stay lightweight for debugging and installation QA. With AI, summarize the row timeline after a session and ask for the largest risk-debt factors, differences between comfort-first and performance-first policies, and the frames where payload should be trimmed.

今日のミニ試作候補Today's mini prototype candidate

本命として採用した候補は `Depth Motion Vector Budget Console` です。何が動くか: depth usage、depth age、motion px、projection lead、hole ratio から depthCoverage、motionVectorQuality、stability、compositorBudget、payloadKb、route を計算し、depth / motion / reprojection guard を重ねます。次に足すなら、実 `XRWebGLDepthInformation` / `XRGPUDepthInformation` の depth timestamp と motion-vector row を IndexedDB へ保存します。派生として `Space Warp Recovery Queue` も実装しました。何が動くか: budget、depth age、motion miss、payload、policy から frame ごとの detect / clamp / refresh / trim / resume を再生します。次に足すなら、1本目の export row を直接 import し、comfort-first と performance-first の差を実 frame timestamp で比較します。

The selected main prototype is `Depth Motion Vector Budget Console`. What it does: computes depthCoverage, motionVectorQuality, stability, compositorBudget, payloadKb, and route from depth usage, depth age, motion pixels, projection lead, and hole ratio, then overlays depth / motion / reprojection guards. Next addition: save real `XRWebGLDepthInformation` / `XRGPUDepthInformation` depth timestamps and motion-vector rows into IndexedDB. The derivative `Space Warp Recovery Queue` was also implemented. What it does: replays detect / clamp / refresh / trim / resume per frame from budget, depth age, motion miss, payload, and policy. Next addition: import the first sample's export row directly and compare comfort-first and performance-first policies over real frame timestamps.
