今日の重要トピックKey topics today

  1. DOM Overlay は immersive session で単一の DOM 要素を透明背景の2D操作面として重ねる機構である。 DOM Overlay presents one DOM element as a transparent 2D control surface in immersive sessions.
  2. dom-overlay は feature と domOverlay.root を伴って要求し、表示はXR描画やパススルーより前面になる。 It is requested with the feature and a domOverlay root and is composited above XR content.
  3. DOM操作に対する XR の選択は beforexrselect で抑止でき、同じ入力を二重に確定させない。 beforexrselect prevents one DOM interaction from committing an XR selection too.
  4. クロスオリジンの重なりでは pose と gamepad が制限され、select を送らない保護が定義される。 Cross-origin overlay content limits pose/gamepad data and cancels selection.
  5. visibilityState の visible-blurred と hidden では、フレーム頻度・pose精度・入力を通常前提にしない。 Blurred and hidden visibility states require a degraded-frame and input plan.

注目事例と何が面白いかNotable example and why it matters

DOM Overlays は、没入セッション中に一つのDOM要素を透明な2D面として表示するための仕様です。これはワールド固定のUIではなく、設定、説明、確認のような画面固定の操作面に向きます。本命では、透明部分を通る world target、overlay が消費する操作、クロスオリジン境界を別の receipt に分け、見た目の重なりを操作権限の重なりにしない設計を試します。

DOM Overlay is a screen-relative control surface, not world-relative UI; the main prototype separates pass-through, DOM-owned, and protected inputs.

制作に使えそうな技術メモProduction note

実機では requestSession の requiredFeatures または optionalFeatures に dom-overlay を入れ、domOverlay:{root: element} を渡します。overlay 内の操作で world selection を起こしたくない場合は beforexrselect を listen して preventDefault します。XRSession の visibilitychange では visible-blurred を低頻度・入力なしの状態として扱い、hidden では poseを読んだり音を鳴らしたりせず、end と同じ停止処理へ流します。

Request dom-overlay with a root, prevent XR select for overlay-owned actions, and treat blurred/hidden as explicit degraded states.

サンプルデータの可能性と組み合わせSample data potential and combinations

両試作の receipt は、入力の宛先、XR側へ渡したか、visibilityState、停止したメディアだけを保存します。展示では壁面の説明パネルと空間作品の操作衝突を検証でき、業務ARでは確認UIと設置操作を切り分けられます。カメラ映像やAIの説明を足す場合も、生の視線・姿勢・ゲームパッド列を記録せず、意思決定の境界だけを監査可能にできます。

Routing and handoff receipts support exhibits and operational AR without retaining raw pose or controller histories.

俯瞰メモBird's-eye memo

XRのUIは「目の前に出せる」ことと「空間の対象を操作できる」ことを同じにしない方が強くなります。DOM Overlayは情報を読みやすくしますが、最前面であるぶん入力・プライバシー・可視性の境界を設計する責任も増えます。状態変化を演出ではなく契約として可視化すると、端末差の大きいXRでも安全に拡張できます。

Frontmost UI improves readability but makes input, privacy, and visibility boundaries first-class design contracts.
