今日の重要トピックKey topics today

  1. `needsRedraw` は layer を次の XR animation frame で再描画すべきことを示します。 needsRedraw asks for next-frame rendering.
  2. リソース喪失や再投影不能時、non-projection layer には redraw event が発火し得ます。 Redraw events can expose lost resources.
  3. `isStatic` は needsRedraw が true の時だけ描画する最適化の意図を表せます。 Static layers can draw only on demand.
  4. WebGPU-backed layer は submit 完了と compositor が texture を使い終える時点を区別する必要があります。 WebGPU texture submission and release are distinct.

注目事例と何が面白いかNotable example and why it matters

Layers 仕様では `needsRedraw` は次の XR frame での再描画要求です。ここで大事なのは、要求を受けた事実と GPU に描画を submit して compositor が読める状態にした事実は別、という点です。本命はこの間を receipt にして、単なる品質スライダーでは見えない失敗点を扱います。

A redraw request and a completed compositor handoff are separate facts; the main sample makes that boundary visible.

表現・インタラクションのアイデアExpression and interaction idea

静的 pin HUD、更新の多い route map、ambient panorama を同じ queue に置きます。resource loss や GPU submit 遅延を切り替えると、読ませ続ける HUD は redraw を予約し、背景は延期または fallback へ回る様子を比較できます。派生はその receipt を8 frame の handoff timeline に変換します。

Three layer roles reveal which content must redraw and which can defer; the derivative turns the receipt into a timeline.

制作に使えそうな技術メモProduction note

実機では `XRCompositionLayer.needsRedraw` と redraw event を layer ID、XR frame timestamp、描画開始・GPU submit・fence/queue 完了、subimage viewport と同じ row に残します。`isStatic` は redraw 時にだけ書き込み、WebGPU の texture は compositor が使い終える前に再利用・破棄しないようにします。

Record redraw signals, frame timestamps, submit/completion, and subimage viewport together; do not reuse textures before compositor release.
