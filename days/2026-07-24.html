今日の重要トピックKey topics today

  1. WebXR DOM Overlays Module は、没入セッション中に単一 DOM 要素を透明背景の 2D overlay として表示し、DOM pointer/click と XR input を同じ画面上で扱う前提を整理している。 The WebXR DOM Overlays Module describes showing a single DOM element as a transparent 2D overlay during an immersive session, where DOM pointer/click handling and XR input share the same screen.
  2. `beforexrselect` は DOM overlay 上で primary action が発生したとき、必要なら `preventDefault()` で `selectstart` / `selectend` / `select` を抑止できるため、UI 操作とワールド配置の二重発火を防ぐ要になる。 `beforexrselect` can call `preventDefault()` when a primary action intersects the DOM overlay, suppressing `selectstart`, `selectend`, and `select` to avoid duplicate UI and world actions.
  3. WebXR Hit Test Module の transient input hit test は `requestHitTestSourceForTransientInput()` と `getHitTestResultsForTransientInput()` で、画面タップや一時入力源ごとの hit 結果を扱える。 The WebXR Hit Test Module's transient input hit testing uses `requestHitTestSourceForTransientInput()` and `getHitTestResultsForTransientInput()` for per-transient-input hit results.
  4. WebXR Device API の input explainer は、画面上の interaction point から target ray を生成し、select intent を input source ごとに統一して扱う考え方を説明している。 The WebXR Device API input explainer describes target rays generated from screen interaction points and a unified select intent across input sources.
  5. WebXR Input Profiles は `XRInputSource.profiles` の整合性と fallback を扱う一次情報で、hand、controller、touchscreen を同じ選択ゲートに通す設計の前提になる。 WebXR Input Profiles provide the conformance and fallback basis behind `XRInputSource.profiles`, useful when routing hand, controller, and touchscreen input through one selection gate.

注目事例と何が面白いかNotable example and why it matters

今日の注目は WebXR DOM Overlays Module の `beforexrselect` と、Hit Test Module の transient input hit test です。AR で画面上に DOM UI を載せると、同じタップが UI の pointer/click とワールド側の `select` / hit test の両方として解釈される可能性があります。公式仕様は、overlay の交差領域で XR select を抑止する手段と、一時入力源ごとの hit test 結果を分ける手段を用意しており、配置 UI や設定パネルを安全に同居させる上で面白い接点です。

Today's notable intersection is `beforexrselect` from the WebXR DOM Overlays Module and transient input hit testing from the Hit Test Module. When a DOM UI sits over AR content, the same tap can be interpreted both as a DOM pointer/click and as a world `select` plus hit test. The specs provide one mechanism to suppress XR select on overlay regions and another to group hit test results by transient input source, which is a useful design point for placement UIs and settings panels.

表現・インタラクションのアイデアExpression and interaction idea

DOM overlay の panel を、ワールド上の透明な安全領域として見せる表現を試しました。ステージ上でドラッグ/タップすると、head 側から伸びる transient touch ray、hit した plane/object、UI によって抑止された select、二重発火リスクが色で切り替わります。`UI strict`、`World first`、`Audit trail` の mode により、同じ入力でも UI 優先、配置優先、監査優先の設計差が見えます。

The sample treats the DOM overlay panel as a transparent safety region over the world. Dragging or tapping the stage shows a transient touch ray from the viewer, the hit plane or object, suppressed selects, and duplicate-action risk with color changes. `UI strict`, `World first`, and `Audit trail` reveal how the same input changes under UI-first, placement-first, and logging-first policies.

制作に使えそうな技術メモProduction note

実装では、DOM overlay の interactive region を hit map として持ち、`beforexrselect` で抑止した interaction と `XRFrame.getHitTestResultsForTransientInput()` の結果を同じ event queue に記録すると調査しやすそうです。透明な説明文は pass-through、button や slider は block、確認済みの placement area は world select へ通す、という粒度で扱うと誤配置を減らせます。hand / controller / touchscreen は `XRInputSource.profiles` を見て threshold を変えつつ、最後は同じ gate function に通す設計が保守しやすいです。

A practical implementation can keep an interactive-region hit map for the DOM overlay, then log interactions suppressed by `beforexrselect` beside results from `XRFrame.getHitTestResultsForTransientInput()`. Transparent explanatory text can pass through, buttons and sliders can block, and confirmed placement regions can route to world select. Hand, controller, and touchscreen inputs can tune thresholds from `XRInputSource.profiles` while still sharing one gate function.
