今日の重要トピックKey topics today

  1. WebXR Depth Sensing Module は `depth-sensing` feature descriptor と CPU / GPU access を定義し、CPU 側では `getDepthInMeters(x, y)` により normalized view coordinates の距離を読む。 The WebXR Depth Sensing Module defines the `depth-sensing` feature descriptor and CPU/GPU access; CPU access reads distance in normalized view coordinates through `getDepthInMeters(x, y)`.
  2. Depth Sensing は物理接触、occlusion、非視覚的な環境把握に使えるが、inline XR device は depth-sensing を support 可能な device として扱ってはいけない。 Depth Sensing can support physical interaction, occlusion, and non-visual environment awareness, but the inline XR device must not be treated as capable of supporting the feature.
  3. WebXR Mesh Detection Module は 2026-02-02 の Draft Community Group Report で、`mesh-detection`、`XRFrame.detectedMeshes`、`XRMesh.vertices` / `indices` / `semanticLabel` / `lastChangedTime` を定義している。 The WebXR Mesh Detection Module Draft Community Group Report dated 2026-02-02 defines `mesh-detection`, `XRFrame.detectedMeshes`, and `XRMesh.vertices`, `indices`, `semanticLabel`, and `lastChangedTime`.
  4. Mesh Detection は環境の 3D surface を露出するため、仕様上も polygon の vertex 数削減、座標 quantization、小さすぎる mesh の非公開化などの privacy mitigation が重要になる。 Mesh Detection exposes 3D surfaces from the user's environment, so privacy mitigations such as reducing polygon vertex count, quantizing coordinates, and hiding too-small meshes are important.
  5. Raw Camera Access は最も露出度が高い経路として扱い、今日の公開カードでは raw pixels そのものではなく、Depth / Mesh で代替できるかを判断する自作 sampler を中心にした。 Raw Camera Access remains the highest-exposure route; today's public card focuses on an original sampler that decides whether Depth or Mesh can replace raw pixels.

注目事例と何が面白いかNotable example and why it matters

今日の注目は、Raw Camera Access の前段に Depth Sensing と Mesh Detection を置くと、AR アプリが必要とする環境理解をかなり限定できる点です。Depth Sensing は view 上の点に対する距離、Mesh Detection は tracked surface の polygon と semanticLabel を返すため、背景画像そのものを読まずに、物体配置、occlusion、近接警告、床や壁への吸着を作れます。一方で mesh も部屋の構造を露出するため、Raw Camera より軽いとはいえ、頂点数、座標精度、label の粒度を調整する gate が必要です。

Today's notable point is that placing Depth Sensing and Mesh Detection before Raw Camera Access can sharply narrow the environmental data an AR app needs. Depth Sensing provides distance at points in the view, while Mesh Detection provides tracked-surface polygons and semantic labels, enabling placement, occlusion, proximity warnings, and wall/floor snapping without reading background images. Meshes still expose room structure, so even though they are lighter than raw camera pixels, they need gates for vertex count, coordinate precision, and label granularity.

表現・インタラクションのアイデアExpression and interaction idea

今日のサンプルでは、未来的な AR scan view の中に depth sample grid、mesh polygon、raw camera crop pressure、移動可能な point probe を重ねました。Depth / Mesh / Hybrid を切り替え、sample density、mesh quantization、raw camera pressure、scene motion、surface complexity を動かすと、privacy risk、utility、route、decision が変化します。canvas をクリックまたはドラッグすると probe が移動し、近い depth 値を読みながら、raw pixels を読むべきか、depth + mesh で十分かを観察できます。

The sample layers a depth-sample grid, mesh polygons, raw-camera crop pressure, and a movable point probe inside a futuristic AR scan view. Switching Depth, Mesh, or Hybrid and adjusting sample density, mesh quantization, raw camera pressure, scene motion, and surface complexity changes privacy risk, utility, route, and decision readouts. Clicking or dragging the canvas moves the probe, letting you observe the nearest depth value while deciding whether raw pixels are necessary or depth plus mesh is enough.

制作に使えそうな技術メモProduction note

実装方針としては、まず `requestSession("immersive-ar", { optionalFeatures: ["depth-sensing", "mesh-detection"] })` のように環境理解を optional に寄せ、必要な体験だけ required に上げる設計が扱いやすそうです。Depth は normalized view coordinate の sampler として UI の照準や object placement に使い、Mesh は `detectedMeshes` の `lastChangedTime` を見て変化した面だけ再評価します。privacy policy では mesh vertices の quantization、semanticLabel の whitelist、細かすぎる mesh の削除、depth sampling density の制限を raw camera request より前の gate にします。

A practical implementation could start with `requestSession("immersive-ar", { optionalFeatures: ["depth-sensing", "mesh-detection"] })`, keeping environment understanding optional unless a specific experience needs it as required. Use Depth as a normalized-view-coordinate sampler for reticles and object placement, and use Mesh Detection by checking `detectedMeshes` and reevaluating only surfaces whose `lastChangedTime` changed. A privacy policy can gate raw camera requests behind mesh-vertex quantization, semantic-label whitelists, removal of overly detailed meshes, and depth-sampling-density limits.

サンプルデータの可能性と組み合わせSample data potential and combinations

このサンプルからは、probe 座標、nearest depth、depth sample count、mesh count、quantization level、raw camera pressure、privacy risk、utility、route decision、event log が取れます。家具配置、展示会場ガイド、倉庫ピッキング、店舗棚前の AR 説明、AI 物体検出、WebGPU compute mask、Body Tracking の redaction policy と組み合わせると、画像を読まずに成立する体験と、画像が本当に必要な体験を分けて評価できます。特に depth / mesh / label だけで UI の吸着と occlusion が成立するなら、raw camera は診断や明示操作時だけに絞れます。

The sample produces probe coordinates, nearest depth, depth sample count, mesh count, quantization level, raw camera pressure, privacy risk, utility, route decision, and an event log. Combining this with furniture placement, exhibition guides, warehouse picking, retail shelf overlays, AI object detection, WebGPU compute masks, or body-tracking redaction policies would separate experiences that work without image access from those that truly need images. If depth, mesh, and labels are enough for snapping and occlusion, raw camera access can be limited to diagnostics or explicit user actions.
