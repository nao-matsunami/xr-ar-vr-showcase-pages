今日の重要トピックKey topics today

  1. WebXR Anchors Module の 2026-04-27 Editor's Draft は、`XRFrame.trackedAnchors` を各 frame でまだ tracked な anchor の集合として扱い、`getPose(anchor.anchorSpace, referenceSpace)` が unlocatable になる frame もあり得ると整理しています。 The 2026-04-27 WebXR Anchors Module Editor's Draft treats `XRFrame.trackedAnchors` as the per-frame set of anchors still tracked, while allowing frames where `getPose(anchor.anchorSpace, referenceSpace)` is unlocatable.
  2. `XRAnchor.delete()` は anchor を tracked set から取り除き、削除後の `anchorSpace` 参照は `InvalidStateError` になるため、UI 側の mesh / DOM row / persistent handle を同時に片付ける必要があります。 `XRAnchor.delete()` removes an anchor from the tracked set, and accessing `anchorSpace` after deletion can raise `InvalidStateError`, so UI meshes, DOM rows, and persistent handles need coordinated cleanup.
  3. `restorePersistentAnchor(uuid)` は persistent map に uuid がない場合や session が終了している場合に `InvalidStateError` で reject されるため、復元 UI は成功前提ではなく失敗キューを持つべきです。 `restorePersistentAnchor(uuid)` rejects with `InvalidStateError` when the UUID is absent from the persistent map or the session has ended, so restore UI should keep a failure queue instead of assuming success.
  4. MDN の `XRFrame.trackedAnchors` は Limited availability / experimental で、HTTPS secure context が必要な API として説明されており、公開サンプルは実 API がない環境でも状態遷移を観察できる形が有効です。 MDN marks `XRFrame.trackedAnchors` as limited availability and experimental, requiring a secure context, making simulated state-transition samples useful on non-XR devices.
  5. Immersive Web の anchors sample は `frame.trackedAnchors.has(anchor)` と `frame.getPose(anchor.anchorSpace, referenceSpace)` で scene object の visible / remove を切り替える基本パターンを示しています。 The Immersive Web anchors sample demonstrates the basic loop of `frame.trackedAnchors.has(anchor)` and `frame.getPose(anchor.anchorSpace, referenceSpace)` to toggle scene object visibility or removal.

注目事例と何が面白いかNotable example and why it matters

今日の注目は、単体 anchor の復元 UI ではなく、`trackedAnchors` の集合差分から復旧キューを作る考え方です。Immersive Web の anchors sample は、tracked set から消えた anchor の scene object を外し、pose が取れない frame では visible を落とす基本形を示しています。面白いのは、この処理を描画だけで終わらせず、unlocatable が何 frame 続いたか、persistent handle があるか、delete 済みかを並べると、復元・再 hit-test・mesh 削除の判断に変換できる点です。

Today's notable idea is building a recovery queue from `trackedAnchors` set differences instead of only offering single-anchor restore UI. The Immersive Web anchors sample removes scene objects when anchors leave the tracked set and hides them when pose lookup fails. The useful extension is turning those rendering states into decisions: how many frames were unlocatable, whether a persistent handle exists, and whether delete has already been called.

表現・インタラクションのアイデアExpression and interaction idea

サンプルでは 3 つの anchor を地図風 canvas に置き、frame を進めるたびに tracked、unlocatable、not in set、deleted を切り替えます。リングが実 pose、点線が unlocatable / lost、細い線が元 pose からの drift です。右側には recovery queue と JSON payload を出し、`restore selected` と `delete selected` で復元失敗や削除後の集合変化を観察できます。実演出では、空間内の物体を消す前に queue row を点滅させ、操作の理由を operator UI に残すと運用向きになります。

The sample places three anchors on a map-like canvas and changes tracked, unlocatable, not-in-set, and deleted states as frames advance. Rings show current poses, dashed rings show unlocatable or lost states, and thin lines show drift from the original pose. The side panel exposes the recovery queue and JSON payload, while `restore selected` and `delete selected` demonstrate restore failure and deletion set changes. In a production display, queue rows can blink before spatial objects disappear, leaving an operator-visible reason.

制作に使えそうな技術メモProduction note

実装では、前 frame の `trackedAnchors` と現在 frame の `trackedAnchors` を比較し、消えた anchor は scene mesh を remove、集合に残っているが `getPose()` が null の anchor は `unlocatableFrames++` にします。`unlocatableFrames` が短ければ hold、長ければ persistent handle restore または re-hit-test replace に送ります。`delete()` 後は `anchorSpace` を読まないために、アプリ側の anchor record に `deletedAtFrame` を持たせるのが安全です。復元失敗は promise rejection を UI queue に残し、同じ uuid を連打しない cooldown を入れます。

In production, compare the previous frame's `trackedAnchors` with the current frame. Anchors that disappeared remove scene meshes; anchors still in the set but returning null from `getPose()` increment `unlocatableFrames`. Short gaps hold pose, while longer gaps enter persistent-handle restore or re-hit-test replacement. After `delete()`, keep `deletedAtFrame` in the app record so code does not read `anchorSpace`. Promise rejections from restore should remain in a UI queue with cooldown to avoid repeatedly hitting the same UUID.
