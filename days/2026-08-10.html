今日の重要トピックKey topics today

  1. WebXR Anchors Module は `persistentAnchors`、`restorePersistentAnchor(uuid)`、`deletePersistentAnchor(uuid)`、`requestPersistentHandle()` を定義し、永続 anchor の復元と削除を session の通常フローに置いている。 The WebXR Anchors Module defines `persistentAnchors`, `restorePersistentAnchor(uuid)`, `deletePersistentAnchor(uuid)`, and `requestPersistentHandle()`, making persistent-anchor restore and deletion part of normal session flow.
  2. WebXR Plane Detection Module は `detectedPlanes`、`polygon`、`orientation`、`semanticLabel`、`initiateRoomCapture()` を定義し、復元失敗後の再 hit / 再配置候補を作る材料になる。 The WebXR Plane Detection Module defines `detectedPlanes`, `polygon`, `orientation`, `semanticLabel`, and `initiateRoomCapture()`, giving useful material for re-hit and re-placement after restore failure.
  3. Plane Detection の privacy guidance は polygon の detail reduction、座標の丸め、小さすぎる plane の非公開化に触れており、復元ログは raw geometry ではなく粗い理由・スコアへ圧縮するのがよい。 Plane Detection privacy guidance discusses polygon detail reduction, coordinate quantization, and hiding overly small planes, so restore logs should be compressed into coarse reasons and scores instead of raw geometry.
  4. WebXR DOM Overlays Module の `beforexrselect` は DOM UI 操作中の WebXR select 系イベント抑止に使えるため、復旧パネル操作と world anchor 操作の二重発火を避ける設計に向く。 The WebXR DOM Overlays Module's `beforexrselect` can suppress WebXR select events during DOM UI interaction, helping avoid duplicate recovery-panel and world-anchor actions.
  5. Immersive Web の proposal samples は plane detection with anchors や depth / mesh の実装例を公開しているが、今日の公開カードは外部デモではなく自作の運用タイムラインにした。 Immersive Web proposal samples expose plane detection with anchors and depth / mesh examples, but today's public card is the original operations timeline rather than an external demo.

注目事例と何が面白いかNotable example and why it matters

今日の注目は、persistent anchor の復元失敗を単なるエラー表示ではなく、現場で扱える運用データにすることです。Anchors 仕様は永続 handle、復元、削除の API を用意していますが、復元できない理由や、誰がどの anchor を直したかまではアプリ側の責任です。Plane Detection は再配置候補を出せる一方で、privacy guidance では polygon detail の削減が重要になります。DOM Overlay の `beforexrselect` は、復旧 UI を押したつもりが world anchor も選択される二重発火を抑える発想として面白いです。

Today's notable idea is turning persistent-anchor restore failure from a simple error into field-operable data. The Anchors spec provides persistent handles, restore, and deletion APIs, but the application has to explain why restore failed and who corrected which anchor. Plane Detection can provide replacement candidates, while its privacy guidance makes polygon-detail reduction important. DOM Overlay's `beforexrselect` is useful because recovery UI actions should not also trigger world-anchor selection.

制作に使えそうな技術メモProduction note

実装時は `requestPersistentHandle()` で保存した UUID と、次回 session の `persistentAnchors` を突き合わせ、`restorePersistentAnchor(uuid)` の成功・失敗を structured log にします。失敗理由は仕様から直接得られない可能性が高いため、tracking confidence、room capture の更新時刻、quota 使用量、ユーザー削除履歴、DOM overlay 操作中かどうかを合わせて推定します。ログに残すのは UUID の短縮 ID、semantic label、粗い pose band、score、reason、operator、action 程度にし、plane polygon や camera frame は保存しない前提が扱いやすいです。

In implementation, compare UUIDs saved from `requestPersistentHandle()` with the next session's `persistentAnchors`, then record success or failure from `restorePersistentAnchor(uuid)` as structured logs. Failure reasons may not be directly exposed by the specification, so infer them from tracking confidence, room-capture update time, quota usage, user deletion history, and whether DOM overlay interaction was active. Keep shortened UUIDs, semantic labels, coarse pose bands, scores, reasons, operators, and actions; avoid persisting plane polygons or camera frames.
