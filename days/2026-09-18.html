MDN の `XRSystem.requestSession()` と `XRSession.enabledFeatures` は、実際に付与された optional feature を session 開始後に確認する実装上の入口になります。 MDN's `XRSystem.requestSession()` and `XRSession.enabledFeatures` are practical entry points for checking which optional features were actually granted after session startup.
  3. Anchors Module は `anchors` feature、`frame.trackedAnchors`、persistent handle を扱い、前日までの ghost replay row と直結します。 The Anchors Module covers the `anchors` feature, `frame.trackedAnchors`, and persistent handles, connecting directly to the recent ghost replay rows.

注目事例と何が面白いかNotable example and why it matters

前日までは ghost replay row を IndexedDB に保存し、semantic history へ渡すところまで進めました。今日はその手前にある `そもそも実機でどの feature が使えるのか` を row 化しました。WebXR は required feature が欠けると session 作成自体が失敗し、optional feature は欠けても session が続く可能性があります。この差分をログに残すと、後続の anchor / mesh / plane / depth row が、実測 row なのか fallback row なのかを説明できます。

The previous day stored ghost replay rows in IndexedDB and handed them to semantic history. Today captures the step before that: which features can actually be negotiated on the device. WebXR can reject session creation when required features are missing, while optional features may be absent without blocking the session. Logging that difference explains whether later anchor / mesh / plane / depth rows are device-backed measurements or fallback rows.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Immersive AR Feature Negotiation Logger` は hit-test、anchors、dom-overlay、plane-detection、mesh-detection、depth-sensing を選び、strictness に応じて required / optional に分けます。Probe Support は `navigator.xr.isSessionSupported("immersive-ar")` を試し、Start AR Session は `requestSession()` と `enabledFeatures` を使える範囲で実行します。派生サンプル `Feature Row Fallback Policy Replayer` は export JSON を strict / balanced / forgiving policy で再判定し、launch confirmed / optional gaps / fallback row / block を比較します。

The main sample, `Immersive AR Feature Negotiation Logger`, selects hit-test, anchors, dom-overlay, plane-detection, mesh-detection, and depth-sensing, then splits them into required / optional features according to strictness. Probe Support calls `navigator.xr.isSessionSupported("immersive-ar")`, and Start AR Session uses `requestSession()` plus `enabledFeatures` where available. The derivative `Feature Row Fallback Policy Replayer` imports exported JSON and compares strict / balanced / forgiving policies across launch confirmed, optional gaps, fallback rows, and blocked routes.

制作に使えそうな技術メモProduction note

実装では、`requiredFeatures` に入れる機能を最小化し、失敗しても体験を続けられる機能は `optionalFeatures` に寄せます。session が開始できた場合は `session.enabledFeatures` を読み、optional 欠落を row に保存します。depth-sensing は `depthSensing` 設定、dom-overlay は `domOverlay.root` が必要になるため、feature list だけでなく feature 固有の init も row に含めると後で再現しやすくなります。

In production, keep `requiredFeatures` minimal and move features that can gracefully degrade into `optionalFeatures`. If a session starts, read `session.enabledFeatures` and save optional gaps in the row. Because depth-sensing needs `depthSensing` preferences and dom-overlay needs `domOverlay.root`, it is useful to save feature-specific initialization details as well as the feature list.

今日のミニ試作候補Today's mini prototype candidate

本命として採用した候補は `Immersive AR Feature Negotiation Logger` です。何が動くか: selected feature を required / optional に分け、`isSessionSupported` と `requestSession` を試し、`enabledFeatures` または fallback confidence から negotiation row を作って JSON export できます。次に足すなら、row を IndexedDB に保存し、9月17日の ghost replay logger が起動する時に session context として自動で読み込みます。派生として `Feature Row Fallback Policy Replayer` も実装しました。何が動くか: 1本目の export JSON または preset を読み込み、strict / balanced / forgiving policy で launch confirmed / optional gaps / fallback row / block を再判定します。次に足すなら、policy の結果を anchor / mesh / plane row の trust score 初期値へ渡します。

The selected main prototype is `Immersive AR Feature Negotiation Logger`. What it does: splits selected features into required / optional lists, tries `isSessionSupported` and `requestSession`, creates negotiation rows from `enabledFeatures` or fallback confidence, and exports JSON. Next addition: save rows to IndexedDB and let the September 17 ghost replay logger automatically load them as session context. The derivative `Feature Row Fallback Policy Replayer` was also implemented. What it does: imports the main sample's exported JSON or presets, then re-routes launch confirmed / optional gaps / fallback row / block with strict / balanced / forgiving policies. Next addition: feed policy results into initial trust scores for anchor / mesh / plane rows.
