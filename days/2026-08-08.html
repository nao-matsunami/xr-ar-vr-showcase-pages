今日の重要トピックKey topics today

  1. WebXR Plane Detection Module は `XRFrame.detectedPlanes`、`XRPlane.orientation`、`XRPlane.polygon`、`XRPlane.semanticLabel` に加え、対応環境では `XRSession.initiateRoomCapture()` を定義している。 The WebXR Plane Detection Module defines `XRFrame.detectedPlanes`, `XRPlane.orientation`, `XRPlane.polygon`, `XRPlane.semanticLabel`, and, where supported, `XRSession.initiateRoomCapture()`.
  2. Plane Detection の privacy guidance は、polygon の detail reduction、座標の rounding / quantization、小さすぎる plane の除外を明示している。 Plane Detection privacy guidance explicitly mentions polygon detail reduction, coordinate rounding or quantization, and removing planes that are too small or too detailed.
  3. WebXR Anchors Module は tracked anchors と persistent anchors の概念を持ち、永続保存は origin ごとの上限や UA による削除可能性を考慮する必要がある。 The WebXR Anchors Module includes tracked anchors and persistent anchors, so persistent saves must account for per-origin limits and user-agent deletion.
  4. Raw Camera Access は `camera-access` feature descriptor と `xr-spatial-tracking` / `camera` permissions policy を必要とするため、plane / anchor で済む配置では最後の手段に寄せたい。 Raw Camera Access requires the `camera-access` feature descriptor plus `xr-spatial-tracking` and `camera` permissions policy, so placement flows that can work with planes and anchors should keep camera pixels as the last resort.
  5. Immersive Web の proposal samples では Plane Detection with Anchors を確認できるが、今日の公開カードは外部デモではなく自作の room capture save gate にした。 Immersive Web proposal samples show Plane Detection with Anchors, while today's public card remains the original room capture save gate sample.

注目事例と何が面白いかNotable example and why it matters

今日の注目は、Plane Detection の `initiateRoomCapture()` と Anchors の persistent anchor をつなぐ前に、どの情報を保存してよいかを UI として明示する点です。公式 proposal sample は plane detection と anchors の組み合わせを確認するのに便利ですが、実際の展示や店舗では、部屋スキャン後に得た plane polygon をそのまま保存するのではなく、semantic label、orientation、粗い頂点数、再ローカライズ時の drift だけで保存判断をしたい場面があります。サンプルでは wall / floor / table / shelf の plane を模し、量子化と privacy load を見ながら session anchor、persistent anchor、recapture、manual fallback を切り替えます。

Today's notable point is making the save decision visible before connecting Plane Detection `initiateRoomCapture()` to persistent Anchors. The official proposal sample is useful for checking plane detection plus anchors, but in exhibitions or retail setups it is often better not to save room-captured plane polygons directly. Instead, the app can decide from semantic labels, orientation, coarse vertex counts, and relocalization drift. The sample simulates wall / floor / table / shelf planes and switches between session anchor, persistent anchor, recapture, and manual fallback while showing quantization and privacy load.

表現・インタラクションのアイデアExpression and interaction idea

サンプルは、候補 anchor を canvas 上で動かし、Scan room ボタンで room capture の更新を疑似発生させる小さな判断盤です。Exhibit / Retail / Desk の preset、semantic confidence、polygon quantization、persistence need、environment sensitivity、relocalization noise を変えると、保存すべき anchor の種類と fallback が変わります。All / Wall / Floor の filter は orientation gate として働き、壁面展示や床置き家具で同じ room capture 結果をどう読み替えるかを試せます。

The sample is a compact decision board where the candidate anchor moves on the canvas and the Scan room button simulates a room-capture update. Exhibit / Retail / Desk presets plus semantic confidence, polygon quantization, persistence need, environment sensitivity, and relocalization noise change the anchor policy and fallback. The All / Wall / Floor filter works as an orientation gate, making it possible to test how the same room-capture result is interpreted for wall exhibitions or floor-placed furniture.

制作に使えそうな技術メモProduction note

実装では `navigator.xr.requestSession("immersive-ar", { optionalFeatures: ["plane-detection", "anchors"] })` から始め、room capture が必要な設置フローだけ `initiateRoomCapture()` の呼び出し UI を出すのが扱いやすいです。`detectedPlanes` からは raw polygon を保存せず、面積帯、orientation、semanticLabel、頂点数の量子化値、lastChangedTime 由来の変化頻度だけをログに残す構成にすると、後から privacy review しやすくなります。persistent anchor は保存価値、再配置コスト、環境の機微度を gate にかけ、低信頼なら session anchor のままにします。

For implementation, start with `navigator.xr.requestSession("immersive-ar", { optionalFeatures: ["plane-detection", "anchors"] })` and only show an `initiateRoomCapture()` control for setup flows that need room capture. From `detectedPlanes`, avoid storing raw polygons; keep area bands, orientation, semanticLabel, quantized vertex counts, and a change-frequency value derived from `lastChangedTime` to simplify later privacy review. Persistent anchors should be gated by save value, repositioning cost, and environment sensitivity, while low-confidence placements remain session anchors.

サンプルデータの可能性と組み合わせSample data potential and combinations

今日のサンプルからは、候補 anchor の座標、選択 plane、orientation filter、semantic confidence、量子化頂点数、privacy load、save score、drift、room capture 回数、fallback を取れます。展示会場の設営ログ、店舗棚の定点 UI、建築レビューの注釈、AI ラベル付け前の低露出 gate、管理画面の設置チェックリストと組み合わせると、どの配置だけを永続保存し、どれを当日セッション限定にするかを説明しやすくなります。実機ログでは plane polygon の生データを避け、集計値と判断結果だけを保存するのがよさそうです。

Today's sample yields candidate-anchor coordinates, selected plane, orientation filter, semantic confidence, quantized vertex count, privacy load, save score, drift, room-capture count, and fallback. Combined with exhibition setup logs, fixed retail shelf UI, architectural review annotations, a low-exposure gate before AI labeling, or an admin setup checklist, it clarifies which placements deserve persistence and which should remain session-only. On hardware, it would be better to avoid raw plane polygons and store only aggregate values plus the resulting decision.
