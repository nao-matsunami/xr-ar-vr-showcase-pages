今日の重要トピックKey topics today

  1. WebXR の描画は XRSession.requestAnimationFrame() の callback ごとに XRFrame を受けて更新する。 The XR frame callback is the unit of spatial evidence.
  2. window の requestAnimationFrame と XRSession の frame loop は交換可能ではなく、XR frame の状態を一単位として扱う。 Window and XR animation loops are not interchangeable.
  3. visibility change や reference-space の変化の後は、古い空間証拠をそのまま commit しない。 Fresh evidence matters after lifecycle changes.
  4. フレーム予算を超える時は pose を使い回すのではなく、新しい詳細の確定を保留し品質を落とす。 Defer detail before reusing stale poses.

注目事例と何が面白いかNotable example and why it matters

WebXR Device API の通常の流れは session を作り、XRSession.requestAnimationFrame() ごとに XRFrame を受けて入力・pose・描画を更新するものです。MDN は window と XRSession の animation frame を交換可能と見なさないよう注意しています。これは性能の話だけではなく、『どの空間証拠を一緒に確定してよいか』を示す境界でもあります。公式 samples は参照として使い、公開アーカイブには外部デモでなく自作試作だけを置きます。

The XR callback is a useful boundary for both rendering and spatial commitment.

表現・インタラクションのアイデアExpression and interaction idea

本命 Frame Freshness Studio は pose と hit-test の frame 番号を分け、同じ新鮮な frame で揃った時だけ配置を commit します。reference space reset や片方だけの更新では、体験を止めずに pending を見せます。派生 Render Budget Metronome は、予算超過時に古い pose を流用するのではなく、追加する詳細を保留または縮小するリズムを棒グラフにしました。

One prototype guards spatial commitment; the other guards detail commitment.

制作に使えそうな技術メモProduction note

実装では一つの XR frame callback の中で getViewerPose、hit-test 結果、入力の起点を束ね、参照空間と時刻を receipt として持たせます。visibilitychange、reset、input source の消失後は fresh frame まで confirm 操作を保留します。描画が重い場合は XRSession の次 frame を必ず予約しつつ、解像度、粒子数、postFX を段階的に下げます。

Bundle spatial evidence per callback, then degrade optional visual detail before compromising freshness.

サンプルデータの可能性と組み合わせSample data potential and combinations

frame 番号、reference-space epoch、品質 tier、commit / hold の理由は、実空間の画像や生 pose を残さずに扱える軽い運用ログです。展示では pending を音の間や淡い光にし、業務 UI では位置確定の説明責任にし、AI 推論では入力 frame と結果 frame の差を見せられます。11月27日の feature contract と合わせれば、feature の許可から実行中の品質制御までを一つの receipt にできます。

Small receipts connect a privacy-conscious log to installation, operational UI, and AI timing.
