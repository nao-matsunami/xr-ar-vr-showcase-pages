今日の重要トピックKey topics today

  1. WebXR Anchors Module は persistent anchor を origin ごとの UUID map として扱い、`persistentAnchors`、`restorePersistentAnchor(uuid)`、`deletePersistentAnchor(uuid)` を定義しています。 The WebXR Anchors Module models persistent anchors as an origin-scoped UUID map and defines `persistentAnchors`, `restorePersistentAnchor(uuid)`, and `deletePersistentAnchor(uuid)`.
  2. `XRFrame.trackedAnchors` はその frame で追跡中の anchor set を返すため、restore の promise 解決だけでなく frame 内で実際に追跡されているかを別に見る必要があります。 `XRFrame.trackedAnchors` returns the anchor set tracked in that frame, so restore should be verified separately from promise resolution.
  3. Anchors Module は native anchor が一時的に unlocatable になる場合や、最終的に tracking を失う場合を許容しており、復元失敗時の re-hit / visual fallback 設計が必要です。 The Anchors Module allows native anchors to become temporarily unlocatable or permanently stop tracking, making re-hit and visual fallback paths important after restore failure.
  4. WebXR Hit Test Module は transient input hit-test の結果を `inputSource` ごとに group 化するため、保存 ledger から再配置する時も source id と hit confidence を残す価値があります。 The WebXR Hit Test Module groups transient input hit-test results by `inputSource`, so saved ledgers should preserve source id and hit confidence for later replacement placement.
  5. 今日の公開カードは外部デモではなく、このワークスペース内の `Anchor Re-hit Replay Bridge` と `Anchor UUID Retention Budget` の2本です。 Today's public cards focus on original workspace samples, `Anchor Re-hit Replay Bridge` and `Anchor UUID Retention Budget`, not external demos.

The Immersive Web hit-test-with-anchors sample is useful as a baseline for creating anchors from hit results, but the public cards center on the two original workspace samples for cross-day replay and retention budgeting.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Anchor Re-hit Replay Bridge` は、保存 row、restore latency、pose drift、新しい hit confidence、anchor map load、UUID の有無、tracked anchor の有無を動かし、`RESTORE`、`RE-HIT CREATE`、`HOLD VISUAL`、`BLOCK` を出します。派生サンプル `Anchor UUID Retention Budget` は、persistent anchor 数、soft cap、最古 anchor の age、restore 成功率、re-hit confidence から、保持、削除予定、保存停止を分類します。

The main sample, `Anchor Re-hit Replay Bridge`, adjusts saved rows, restore latency, pose drift, new hit confidence, anchor map load, UUID presence, and tracked-anchor presence, then routes to `RESTORE`, `RE-HIT CREATE`, `HOLD VISUAL`, or `BLOCK`. The derivative `Anchor UUID Retention Budget` classifies keep, prune-soon, or stop-saving decisions from persistent anchor count, soft cap, oldest anchor age, restore success rate, and re-hit confidence.

制作に使えそうな技術メモProduction note

実機版では保存 row に source id、event type、hit confidence、pose matrix、persistent UUID、作成経路、promise settle time を入れます。次回 session で `session.persistentAnchors` に UUID があるか見て `restorePersistentAnchor(uuid)` を試し、復元後は `frame.trackedAnchors` と `frame.getPose(anchor.anchorSpace, referenceSpace)` で確認します。復元が遅い、untracked、drift が大きい、または UUID が消えた場合だけ transient hit-test source を作り直し、十分な hit result から `XRHitTestResult.createAnchor()` へ回します。map 圧が高い場合は `deletePersistentAnchor(uuid)` を明示的に使い、hit-test source は不要になったら `cancel()` します。

A device-backed version should store source id, event type, hit confidence, pose matrix, persistent UUID, creation route, and promise settle time in each row. In the next session, check whether the UUID appears in `session.persistentAnchors`, try `restorePersistentAnchor(uuid)`, then verify the restored anchor with `frame.trackedAnchors` and `frame.getPose(anchor.anchorSpace, referenceSpace)`. Only recreate the transient hit-test source when restore is slow, untracked, drifting, or the UUID disappeared, then route a confident hit result to `XRHitTestResult.createAnchor()`. When map pressure is high, explicitly call `deletePersistentAnchor(uuid)`, and call `cancel()` for hit-test sources that are no longer needed.
