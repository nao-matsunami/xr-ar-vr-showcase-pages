今日の重要トピックKey topics today

  1. WebXR Device API の 2026-06-09 Candidate Recommendation Draft は、`XRInputSource`、transient input、`XRInputSourceEvent`、`inputsourceschange`、input profiles を仕様上の中心として整理しています。 The WebXR Device API Candidate Recommendation Draft dated 2026-06-09 centers `XRInputSource`, transient input, `XRInputSourceEvent`, `inputsourceschange`, and input profiles.
  2. Immersive Web の input explainer は、すべての input source が `targetRaySpace` を持ち、`XRFrame.getPose(inputSource.targetRaySpace, referenceSpace)` の戻り値は tracking lost などで `null` になり得るため検査が必要だと説明しています。 The Immersive Web input explainer states that every input source has `targetRaySpace`, and that `XRFrame.getPose(inputSource.targetRaySpace, referenceSpace)` must be checked because it can return `null` during tracking loss.
  3. MDN の WebXR input 解説は、screen input が transient input source として `selectstart`、`select`、`selectend` を発生させる流れを示し、pointer と XR input の橋渡しを理解しやすくしています。 MDN's WebXR input guide explains how screen input can become a transient input source that emits `selectstart`, `select`, and `selectend`, which clarifies the bridge between pointer and XR input.
  4. Immersive Web Samples の Input Selection は、`selectstart` / `selectend` / `select` を購読し、`targetRaySpace` の pose から scene hit test を行う最小の公式実装例として参照しやすいです。 Immersive Web's Input Selection sample is a compact official reference for subscribing to `selectstart`, `selectend`, and `select`, then using `targetRaySpace` pose for scene hit testing.
  5. WebXR Gamepads Module は、button、trigger、thumbstick、touchpad data を `XRInputSource.gamepad` に載せる前提を定義しており、profile 名や handedness と semantic action を分ける設計が重要です。 The WebXR Gamepads Module defines how button, trigger, thumbstick, and touchpad data are exposed through `XRInputSource.gamepad`, making it important to separate profile labels, handedness, and semantic actions.

制作に使えそうな技術メモProduction note

`select` event だけで確定処理を組むと、pose が取れない frame や transient source の寿命を見落としやすくなります。`selectstart` で候補を保持し、`select` で pose と confidence を再確認し、`selectend` でキャンセルや縮小演出を閉じる三段構えが扱いやすいです。gamepad 側は profile 名を UI ラベルに使い、アプリ内部は `select`、`grab`、`turn-left`、`confirm` のような semantic action に変換してから扱うと、デバイス差の影響を小さくできます。

If confirmation is built only around the `select` event, it is easy to miss frames where no pose is available or where a transient source has already disappeared. A practical pattern is to hold a candidate on `selectstart`, re-check pose and confidence on `select`, and close cancellation or scale effects on `selectend`. For gamepad input, use profile names for UI labels, but convert to app-internal semantic actions such as `select`, `grab`, `turn-left`, and `confirm` before business logic.
