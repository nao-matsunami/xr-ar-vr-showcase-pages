今日の重要トピックKey topics today

  1. WebXR Layers は immersive VR / AR session の composition layer を扱い、projection layer は常に利用可能です。 WebXR Layers manages composition layers for immersive sessions.
  2. `depth-sorted-layers` を要求すると projection / quad / cylinder layer は配列順でなく深度に基づき表示されます。 depth-sorted-layers changes projection, quad, and cylinder ordering to depth-based ordering.
  3. Layer は texture を毎 frame 更新する必要がなく、更新要求と可読性を分けて予算化できます。 Texture refresh can be budgeted separately from layer presentation.
  4. 公式 Layers Samples は quad、cylinder、depth、space warp などを小さな機能単位で検証しています。 Official samples isolate layer behavior into small feature-focused pages.

注目事例と何が面白いかNotable example and why it matters

Layers API は text や map を高解像度の別 layer に置き、compositor がアプリ更新より高い頻度で提示できる余地を作ります。最新草案の `depth-sorted-layers` は配列順だけに依存しないため、UI を『先に描いた順』ではなく『空間内でどう読ませるか』として設計できる点が面白いです。

Layers let essential text or maps live at a separate resolution, while depth-sorted-layers makes presentation a spatial decision rather than only an array-order decision.

制作に使えそうな技術メモProduction note

実装時は `requestSession('immersive-vr', { optionalFeatures: ['layers', 'depth-sorted-layers'] })` の成否を記録し、実 layer の `needsRedraw` と `redraw` event を row に残します。`depth-sorted-layers` は全 layer に一律ではなく projection / quad / cylinder に関係する点、inline session では Layers が使えない点も fallback 条件にします。

Record session feature outcomes, needsRedraw, and redraw events; keep the layer-type and inline-session constraints in the fallback route.

サンプルデータの可能性と組み合わせSample data potential and combinations

Priority, depth, content delta, budget, and verdict can join captions, maps, cameras, audio installations, and operational HUD logs.
