注目事例と何が面白いかNotable example and why it matters

9月18日は feature negotiation、9月19日は layer readiness、9月20日は scene contract を別々の row として扱いました。今日はそれらを session context として merge し、IndexedDB に保存してから frame logger の初期 trust に渡す流れを試します。WebXR の失敗は session 開始時だけでなく、開始後の layer、anchor、depth、plane の混合状態で起きるため、`開始できたか` だけではなく `どんな前提で開始したか` を保存するのが面白いところです。

September 18 treated feature negotiation, September 19 treated layer readiness, and September 20 treated scene contracts as separate rows. Today merges them as session context, stores the result in IndexedDB, and passes it into the frame logger as initial trust. WebXR failures do not only happen at session startup; they emerge from mixed runtime states across layers, anchors, depth, and planes. Saving not only whether startup succeeded but also what assumptions it started with is the interesting part.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Session Context Merge Store` は、session intent、feature coverage、layer readiness、contract score、TTL、privacy grain を操作し、merge route、context score、IndexedDB 保存、JSON export を更新します。派生サンプル `Initial Trust Score Replayer` は、その JSON を貼り付けるか seed export を使い、frame age、sensor drift、optional gaps、policy から `commit solid`、`guarded commit`、`preview only`、`block logger` を比較します。

The main sample, `Session Context Merge Store`, lets you adjust session intent, feature coverage, layer readiness, contract score, TTL, and privacy grain, then updates the merge route, context score, IndexedDB storage, and JSON export. The derivative sample, `Initial Trust Score Replayer`, accepts that JSON or a seed export and compares `commit solid`, `guarded commit`, `preview only`, and `block logger` from frame age, sensor drift, optional gaps, and policy.

制作に使えそうな技術メモProduction note

実装では、`requestSession()` 直後に `enabledFeatures` と layer probe を保存し、最初の `XRFrame` が来る前に context を読み出すと、後段の anchor / plane / mesh row に初期 trust を渡しやすくなります。privacy grain はここで落としておくのが扱いやすく、precise geometry を保存するより、coarse score、optional gap、selected contract、TTL だけを保存する方が replay と説明に向いています。

In a production version, save `enabledFeatures` and layer probes right after `requestSession()`, then read the context before the first `XRFrame` so downstream anchor / plane / mesh rows can receive initial trust. Privacy grain is easiest to reduce at this boundary. For replay and explanation, coarse scores, optional gaps, selected contracts, and TTL are often more useful than saving precise geometry.

俯瞰メモBird's-eye memo

9月中旬の蓄積は、認識 row、表示 row、保存 row の3層になってきました。今日の session context は、その3層をつなぐ小さな背骨です。WebXR では API 対応状況と体験の安全性が一致しないので、`どの条件でこの frame を信じたか` を後から読める形にしておくほど、デバッグにも UX 説明にも強くなります。

The mid-September archive is becoming three layers: recognition rows, display rows, and storage rows. Today's session context is a small backbone connecting those layers. In WebXR, API support and experiential safety do not always match, so keeping a readable record of `why this frame was trusted under these conditions` helps both debugging and UX explanation.

The selected main prototype is `Session Context Merge Store`. What it does: builds session context from feature coverage, layer readiness, contract score, TTL, and privacy grain, then saves it to IndexedDB and exports JSON. Next addition: automatically fill sourceRows from real `navigator.xr.requestSession("immersive-ar")` `enabledFeatures` and layer probes. The derivative `Initial Trust Score Replayer` was also implemented. What it does: reads contextScore and optional gaps from exported or seed JSON, then compares initial trust routes from frame age / drift / policy. Next addition: pass the route into the September 17 ghost replay logger as the trust floor for the first anchor row.
