今日の重要トピックKey topics today

  1. 2026年11月9日版 WebXR Device API は、trusted UI 操作中に XR session を hidden または visible-blurred とし、ページによる入力の観測を防ぐ。 Trusted UI requires an XR visibility and input boundary.
  2. hidden では XR requestAnimationFrame callback と input controller 処理が止まり、visible-blurred でも input はページへ渡されない。 Hidden and blurred sessions must not process XR input.
  3. XR visibility は document.visibilityState と独立し得るため、ページの可視性だけを XR の復帰条件にできない。 XR and document visibility are independent signals.
  4. XRInputSource の gamepad は frame ごとに in-place 更新される live object なので、変化比較には値の自前 cache が必要になる。 XR gamepad state is a live frame-updated object.
  5. Gamepad の haptic output は利用可能な actuator の capability を前提にし、未対応時は視覚的な確認へ落とす。 Haptics require capability-aware fallback.

注目事例と何が面白いかNotable example and why it matters

WebXR Device API の trusted environment は、ページが模倣も観測もできない browser / OS 側の操作面です。仕様はその最中に session を hidden または visible-blurred にし、入力から選択内容を推測する経路を塞ぎます。本命はこれを『演出を薄くする』話で終えず、frame、input、ページの次アクションを別々に切り替えられる自作実験にしました。

The main prototype treats trusted UI as a non-spoofable, non-observable input boundary rather than just a visual pause.

表現・インタラクションのアイデアExpression and interaction idea

本命 Trusted UI Input Curtain Lab は scene focused / trusted UI nearby / trusted UI focused を押して、視界の残り方、ray の停止、input の閉鎖を比べます。派生 Haptic Acknowledgement Router は committed select、preview、trusted UI 中、actuator 未対応を分け、確定していない候補に触覚を付けない設計を動かします。

The derivative only routes a short haptic acknowledgement after a committed selection and has explicit silent/fallback states.

制作に使えそうな技術メモProduction note

実装では session 作成時に visibilitychange を登録し、visible 以外で XR input による state 更新を止めます。hidden は frame が来ない前提で animation 依存の cleanup を書き、visible へ戻ったら capability と現在の state を再評価します。controller の gamepad は live object なので axes / buttons を plain values に copy して前 frame と比較し、haptic actuator がなければ視覚・音声など任意の安全な確認へ切り替えます。

Listen for visibility changes, stop input outside visible, cache gamepad values, and use an explicit non-haptic fallback.

サンプルデータの可能性と組み合わせSample data potential and combinations

再利用するなら visibility の遷移、intent が commit されたか、output が capability 不足で fallback したかだけの最小 receipt が有用です。展示の安全停止、遠隔支援の引き継ぎ、作業 UI の確認演出と組み合わせても、ユーザーが trusted UI で何を選んだかや、pose / gaze の連続値を記録せずに、設計上の摩擦だけを観測できます。

Minimal transition receipts can measure interaction friction without recording trusted choices, poses, or gaze.

俯瞰メモBird's-eye memo

XR の privacy はカメラ画像や room mesh だけの問題ではありません。browser がユーザーへ問いかける瞬間に、アプリが手の向きや controller の微小変化から答えを推測できるなら、入力の分離は破れます。visibility を performance hint としてだけ使わず、誰の UI が input を受け取るかを示す権限境界として扱うと、表現と安全性を同時に設計できます。

Visibility is also an authority boundary: it says whose UI may receive input.
