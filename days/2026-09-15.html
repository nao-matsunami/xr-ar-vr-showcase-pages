今日の重要トピックKey topics today

  1. WebXR Device API の 2026-06-09 Candidate Recommendation Draft は、session、frame、reference space、feature negotiation を扱う土台で、mesh / plane / anchor を同じ frame ledger に入れる時の前提になります。 The 9 June 2026 WebXR Device API Candidate Recommendation Draft is the baseline for sessions, frames, reference spaces, and feature negotiation when putting mesh / plane / anchor state into the same frame ledger.
  2. WebXR Mesh Detection Module は `mesh-detection` feature descriptor、`XRFrame.detectedMeshes`、`XRMesh.vertices`、`indices`、`lastChangedTime`、`semanticLabel` を定義し、plane より細かい実世界形状の使い道を示します。 The WebXR Mesh Detection Module defines the `mesh-detection` feature descriptor, `XRFrame.detectedMeshes`, `XRMesh.vertices`, `indices`, `lastChangedTime`, and `semanticLabel`, pointing to finer real-world geometry than planes can offer.
  3. Plane Detection Module は floor / wall / table などの安定した surface と `XRPlane.polygon` を返すため、anchor 作成の土台として mesh より落ち着いた候補になりやすいです。 The Plane Detection Module returns stable surfaces such as floor / wall / table plus `XRPlane.polygon`, making planes calmer anchor bases than dense meshes.
  4. Anchors Module は実世界に固定した pose を tracking し続ける仕組みなので、mesh の細部情報をそのまま anchor に使うより、plane / depth / mesh score を gate にしたほうが扱いやすいです。 The Anchors Module tracks poses fixed relative to the real world, so it is easier to gate anchor creation with plane / depth / mesh scores than to attach directly to mesh detail.
  5. 今日の公開カードは外部デモではなく、このワークスペース内で作った `Mesh Anchor Stability Ledger` と `Mesh Plane Semantic Conflict Gate` の2本です。 Today's public cards focus on the original workspace samples `Mesh Anchor Stability Ledger` and `Mesh Plane Semantic Conflict Gate`, not external demos.

注目事例と何が面白いかNotable example and why it matters

昨日は mesh を三角形 budget と plane 融合で使い分けました。今日はその mesh score を、9月13日に作った plane anchor handoff queue へ戻す流れにしました。Mesh Detection は細かい形状を返せる一方、三角形数、更新頻度、privacy reduction、semantic label の揺れに影響されます。Plane Detection はより粗いが安定した surface を返せるので、anchor は plane に、collision / occlusion は mesh に、最終確認は depth に、という分業が実装上の落としどころになります。

Yesterday routed meshes by triangle budget and plane fusion. Today feeds that mesh score back into the plane anchor handoff queue built on September 13. Mesh Detection can return fine geometry, but it is affected by triangle count, update churn, privacy reduction, and semantic label instability. Plane Detection is coarser but provides stable surfaces, so the practical split is: anchors from planes, collision / occlusion from meshes, and final confirmation from depth.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Mesh Anchor Stability Ledger` は mesh input、anchor intent、mesh fusion score、plane stability、triangle pressure、depth cross-check、anchor promise latency、frame budget spare、frame active を動かし、`COMMIT ANCHOR`、`PATCH WITH PLANE`、`HOLD RETICLE`、`BLOCK HANDOFF` に分けます。派生サンプル `Mesh Plane Semantic Conflict Gate` は plane label と mesh label、label confidence、pose overlap、normal agreement、depth support、privacy reduction、annotation risk を操作し、同じ surface として扱うか、anchor と occlusion の責務を分けるか、annotation を止めるかを判定します。

The main sample, `Mesh Anchor Stability Ledger`, adjusts mesh input, anchor intent, mesh fusion score, plane stability, triangle pressure, depth cross-check, anchor promise latency, frame budget spare, and frame activity, then routes to `COMMIT ANCHOR`, `PATCH WITH PLANE`, `HOLD RETICLE`, or `BLOCK HANDOFF`. The derivative sample, `Mesh Plane Semantic Conflict Gate`, adjusts plane label, mesh label, label confidence, pose overlap, normal agreement, depth support, privacy reduction, and annotation risk to decide whether a surface is shared, whether anchor and occlusion responsibilities should split, or whether annotations should be stopped.

制作に使えそうな技術メモProduction note

実機版では `navigator.xr.requestSession('immersive-ar', { optionalFeatures: ['mesh-detection', 'plane-detection', 'depth-sensing', 'anchors'] })` のように feature を交渉し、各 frame で `frame.detectedMeshes`、`frame.detectedPlanes`、depth information、anchor promise の状態を1行の ledger に保存します。`XRMesh.lastChangedTime` と `XRPlane.lastChangedTime` は geometry 更新の時刻として扱い、`meshSpace` / `planeSpace` の pose 変化とは分けて記録します。anchor 作成前に mesh score を見ると、同じ table label でも edge clutter が強い場合は `PATCH WITH PLANE` に落とせます。

A device-backed version can negotiate features with `navigator.xr.requestSession('immersive-ar', { optionalFeatures: ['mesh-detection', 'plane-detection', 'depth-sensing', 'anchors'] })`, then save `frame.detectedMeshes`, `frame.detectedPlanes`, depth information, and anchor promise state into one ledger row per frame. Treat `XRMesh.lastChangedTime` and `XRPlane.lastChangedTime` as geometry update times, separate from `meshSpace` / `planeSpace` pose changes. Checking the mesh score before anchor creation lets a table-labeled plane fall back to `PATCH WITH PLANE` when edge clutter is high.

俯瞰メモBird's-eye memo

9月前半の流れは、入力 ledger、camera / policy gate、hit-test、anchor、depth、plane、mesh へ進んできました。今日の整理で、mesh は単体の見た目ではなく `anchor 作成前の判断材料` になりました。実装の考え方は単純で、粗く安定した plane を配置の土台にし、細かい mesh を collision / occlusion の補助にし、depth で現実との一致を確認します。semantic label が食い違う時は、見た目を派手に続けるより、責務を分けるか ghost 表示に戻すほうがユーザーには納得しやすいです。

The first half of September moved through input ledgers, camera / policy gates, hit-test, anchors, depth, planes, and meshes. Today's step turns meshes from a visual artifact into an input for pre-anchor decisions. The implementation model is simple: use coarse stable planes for placement, fine meshes for collision / occlusion support, and depth to confirm real-world agreement. When semantic labels disagree, splitting responsibilities or returning to ghost display is easier for users to trust than continuing with a flashy placement.

The selected main prototype is `Mesh Anchor Stability Ledger`.
