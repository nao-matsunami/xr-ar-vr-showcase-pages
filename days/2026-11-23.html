今日の重要トピックKey topics today

  1. WebXR の hit-test は plane、point、mesh を対象にでき、結果は XRFrame ごとに得るため、単発の位置を即時確定しない設計が有効。 Hit tests can target planes, points, and meshes, so a single result need not become an immediate placement.
  2. hit-test は実験的で HTTPS と feature の有効化を必要とし、未対応機器では代替導線が必要。 Hit testing is experimental, secure-context-only, and needs a fallback.
  3. 参照空間はローカル座標系を定義するだけでなく、追跡ロストからの連続性・回復をアプリ設計に持ち込む。 Reference spaces make tracking-loss continuity and recovery an application concern.
  4. WebXR Layers はアプリの描画更新とは別に compositor が提示でき、状態変化時ほど軽い UI と明確な confirmation が重要になる。 Composition layers separate compositor presentation from app updates, making clear state changes important.

注目事例と何が面白いかNotable example and why it matters

MDN の requestHitTestSource() は plane、point、mesh を entityTypes として選べ、XRFrame から結果を得る流れを示します。面白いのは、これは「場所を一つ返す API」ではなく、毎フレームの観測を材料にする API だという点です。空間の揺れや対象種別を UI に出すと、利用者は“まだ候補”と“ここに置く”を区別できます。MDN の空間追跡ガイドも、参照空間を局所座標系と追跡断からの回復を考える基盤として説明しています。

Hit-test results are frame observations, not a mandate to commit a single location; reference spaces also require a recovery story.

表現・インタラクションのアイデアExpression and interaction idea

本命 Hit-test Confidence Garden は、クリックした位置を候補として動かし、連続性と面の確からしさから“ready / hold”を変えます。固定は緑になっても自動では起きません。派生 Reference Space Recovery Ribbon は tracking → limited → lost → relocalized を一本のリボンにし、lost では stale pose を使わず confirmation を止めることを可視化します。

The main keeps placement explicit; the derivative turns tracking loss and recovery into a visible state ribbon.

制作に使えそうな技術メモProduction note

実装では requestSession の optionalFeatures に hit-test を入れ、session と viewer/reference space を得て requestHitTestSource() を一度作成します。各 XRFrame で getHitTestResults() と getPose(referenceSpace) を読み、短い移動平均・対象種別・時間で候補を採点します。確定は利用者操作で行い、session 終了時に XRHitTestSource.cancel() を呼びます。未対応・拒否・追跡不安定時は 2D picker に同じ確定意図を移します。

Create one hit-test source, score per-frame poses briefly, commit only from explicit input, cancel it on session end, and preserve intent in a 2D fallback.

サンプルデータの可能性と組み合わせSample data potential and combinations

座標そのものを残さず、entity type、安定度、候補から確定までの時間、追跡状態遷移だけを匿名の receipt にできます。展示なら音の粒や光の密度を安定度に結び、教育なら“なぜ今は置けないか”の説明に、業務 UI なら確認待ちの根拠にできます。カメラ映像や room mesh を保存しないため、試作段階の観測ログを最小化できます。

Anonymous state receipts can drive installation cues, teaching prompts, and operational confirmations without retaining spatial imagery.

実機で plane / point / mesh の戻り方、参照空間の reset、移動中の候補の揺れ、session 終了時の cancel、同一地点への再配置を観察します。Layers を併用する場合は、layer の表示更新と hit-test UI の confirmation が視覚的に矛盾しないかも確認します。

Watch entity-type returns, resets, moving jitter, cleanup, relocation, and UI consistency when layers are present.

俯瞰メモBird's-eye memo

空間に物が“ぴたり”と置ける瞬間だけを見せると、現実の不確かさは隠れます。XR の信頼感は、精度を装うことではなく、候補・待機・再確認を静かに読めることから生まれます。Layer のように提示経路が高品質になっても、操作の根拠まで自動で高品質にはなりません。

Trust comes from legible candidate, waiting, and recovery states—not from pretending spatial certainty.
