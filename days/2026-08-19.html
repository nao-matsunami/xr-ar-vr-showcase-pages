今日の重要トピックKey topics today

  1. WebXR DOM Overlays Module は、overlay の DOM root に `beforexrselect` を発火し、`preventDefault()` で `selectstart` / `selectend` / `select` を抑止できる入力境界を定義しています。 The WebXR DOM Overlays Module defines an input boundary where `beforexrselect` fires on the overlay DOM root and `preventDefault()` can suppress `selectstart`, `selectend`, and `select`.
  2. MDN の `beforexrselect` ページは、この機能が experimental / limited availability であり、広いブラウザ互換を前提にしない検証が必要だと示しています。 MDN's `beforexrselect` page marks the feature as experimental and limited availability, so validation should not assume broad browser support.
  3. Immersive Web の Anchors Module では、`XRAnchor.delete()`、`requestPersistentHandle()`、`XRSession.restorePersistentAnchor()`、`deletePersistentAnchor()` が anchor lifecycle の基本操作になります。 The Immersive Web Anchors Module makes `XRAnchor.delete()`, `requestPersistentHandle()`, `XRSession.restorePersistentAnchor()`, and `deletePersistentAnchor()` core parts of the anchor lifecycle.
  4. WebXR Hit Test Module は `requestHitTestSourceForTransientInput()` と `getHitTestResultsForTransientInput()` を定義し、screen tap 由来の一時的な ray から再配置候補を得る流れを扱います。 The WebXR Hit Test Module defines `requestHitTestSourceForTransientInput()` and `getHitTestResultsForTransientInput()`, covering replacement candidates from screen-tap transient rays.
  5. DOM Overlay の説明資料では、DOM event と XR event は完全同期ではなく、非 event 型の controller pose / button state / transient input はアプリ側で重複排除する必要があると整理されています。 The DOM Overlay explainer clarifies that DOM events and XR events are not fully synchronized, and apps must deduplicate non-event controller pose, button state, and transient input when needed.

注目事例と何が面白いかNotable example and why it matters

今日の注目は、DOM Overlay の confirm/cancel UI を anchor lifecycle の操作キューとして使う考え方です。`beforexrselect.preventDefault()` は単にボタンと world select の二重発火を止めるだけでなく、`delete()`、persistent handle restore、re-hit-test replace のような戻しにくい操作を、overlay 上の明示的な確認に閉じ込める境界として使えます。面白いのは、空間内 anchor の hover や drift warning は world 側で続けながら、確定操作だけを DOM 側の取り消し可能な queue に逃がせる点です。

Today's notable idea is using DOM Overlay confirm/cancel UI as an operation queue for the anchor lifecycle. `beforexrselect.preventDefault()` is not only a way to stop duplicate button and world-select events; it can also fence hard-to-reverse operations such as `delete()`, persistent-handle restore, and re-hit-test replacement behind explicit overlay confirmation. The useful part is that world-side hover and drift warning can continue while commit operations move into an undoable DOM-side queue.

表現・インタラクションのアイデアExpression and interaction idea

サンプルでは pending anchor operation、confirm/cancel overlay、world anchor、target ray、hit-test quality、drift cm を同じ画面に置きました。confirm に ray が当たり、overlay gate が有効な時だけ commit に進みます。cancel なら rollback、world anchor に当たった時は drift が大きければ request confirm、小さければ inspect です。実演出では、confirm 中だけ anchor ring を固定色にし、world 側の select ray を点線にして、今は空間ではなく DOM が入力を所有していることを示すと分かりやすくなります。

The sample places the pending anchor operation, confirm/cancel overlay, world anchor, target ray, hit-test quality, and drift in one view. It commits only when the ray hits confirm while the overlay gate is active. Cancel rolls back; hitting the world anchor requests confirmation when drift is large and only inspects when drift is small. In a real scene, the anchor ring can freeze to a confirmation color and the world select ray can become dashed while DOM owns the input.

制作に使えそうな技術メモProduction note

実装では anchor 操作を即時実行せず、`{ type, anchorId, persistentHandle, hitTestSource, createdAtFrame }` のような queue item として持ちます。overlay root の `beforexrselect` で confirm/cancel 領域を検出したら `preventDefault()` し、DOM click 側で commit / rollback を行います。re-hit-test は `requestHitTestSourceForTransientInput()` の結果を候補として持ち、quality や entity type が閾値未満なら hold にします。persistent handle がない restore は UI 上では同じに見えても実行条件が違うため、payload で null を明示するのが安全です。

In production, keep anchor operations as queue items such as `{ type, anchorId, persistentHandle, hitTestSource, createdAtFrame }` instead of executing immediately. When the overlay root's `beforexrselect` detects confirm/cancel regions, call `preventDefault()` and let DOM click commit or roll back. For re-hit-test, hold the `requestHitTestSourceForTransientInput()` result as a candidate and keep the operation on hold if quality or entity type is below threshold. A restore without a persistent handle looks similar in UI but has different execution requirements, so the payload should make null explicit.
