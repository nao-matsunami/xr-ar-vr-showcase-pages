今日の重要トピックKey topics today

  1. WebXR Device API は `requestSession()` の後、セッションから `requestReferenceSpace()` を呼び出して `viewer`、`local`、`local-floor`、`bounded-floor` などの空間を取得する流れを定義しています。 The WebXR Device API defines the flow of obtaining `viewer`, `local`, `local-floor`, and `bounded-floor` spaces from an `XRSession` via `requestReferenceSpace()` after `requestSession()`.
  2. MDN の `requestReferenceSpace()` は Limited availability / experimental / secure context の API として説明され、`bounded-floor` は `XRBoundedReferenceSpace` と `boundsGeometry` を返す参照空間として整理されています。 MDN documents `requestReferenceSpace()` as limited availability, experimental, and secure-context-only, and describes `bounded-floor` as a reference space returned as `XRBoundedReferenceSpace` with `boundsGeometry`.
  3. MDN の bounded reference spaces ガイドは、`requestSession()` で `bounded-floor` を optional にしても、実際に境界空間を使うには `requestReferenceSpace("bounded-floor")` を呼び、失敗時に `local-floor` へ fallback する必要があると示しています。 MDN's bounded reference spaces guide notes that requesting `bounded-floor` as optional in `requestSession()` is not enough; apps still call `requestReferenceSpace("bounded-floor")` and fall back to `local-floor` when that fails.
  4. Immersive Web の teleportation sample は、床上の点をコントローラーで選び、`XRSession` の reference space を更新して視点移動する例として、テレポート UI の最小形を確認できます。 The Immersive Web teleportation sample demonstrates the smallest useful teleport UI: select a point on the floor with a controller, then update the session reference space.
  5. WebXR Layers API Level 1 は `XRQuadLayer` / `XRCylinderLayer` を `local`、`local-floor`、`unbounded`、`bounded-floor`、anchor space へ配置できる例を示しており、境界判定済みの UI 面を世界固定する発展先になります。 WebXR Layers API Level 1 shows `XRQuadLayer` and `XRCylinderLayer` in `local`, `local-floor`, `unbounded`, `bounded-floor`, or anchor space, which suggests a next step for world-locked safety panels after boundary checks.

注目事例と何が面白いかNotable example and why it matters

今日の注目は、テレポートを単なる移動操作ではなく、参照空間の可用性に応じて安全判定を切り替える UI として扱うことです。Immersive Web の teleportation sample は床の点を選んで reference space を更新する最小例です。一方で実運用では `bounded-floor` が返る端末ばかりではないため、MDN のガイドが示すように `requestReferenceSpace("bounded-floor")` 失敗時の fallback が必要です。面白いのは、境界ポリゴンが取れる場合は厳密に、取れない場合は保守半径で判断するだけでも、展示や安全配慮の説明がかなり明確になる点です。

Today's notable idea is treating teleportation not just as locomotion, but as UI that changes its safety check based on reference-space availability. The Immersive Web teleportation sample is the minimal example of selecting a floor point and updating the reference space. In real deployments, not every device returns `bounded-floor`, so the fallback path described by MDN is essential. The interesting part is that switching from exact boundary polygons to a conservative local-floor radius already makes installation and safety behavior much easier to explain.

表現・インタラクションのアイデアExpression and interaction idea

サンプルでは device profile、bounds preset、`local-floor` 時のガード半径を切り替え、キャンバスクリックでテレポート候補地点を置けます。`bounded-floor` が使える profile では境界ポリゴンの内外で許可 / 拒否を判定し、境界がない profile では原点からの距離で許可 / 注意 / 拒否を出します。実アプリでは、床 hit reticle の色、コントローラーの haptics、DOM Overlay の理由表示を同じ verdict に接続できます。

The sample lets you change device profile, bounds preset, and the local-floor guard radius, then place a teleport candidate by clicking the canvas. Profiles with `bounded-floor` use polygon containment for allow/block decisions, while profiles without bounds use distance from the local origin for allow/warn/block decisions. In a real app, the same verdict can drive reticle color, controller haptics, and DOM Overlay diagnostics.

制作に使えそうな技術メモProduction note

`requestSession(mode, { optionalFeatures: ["bounded-floor"], requiredFeatures: ["local-floor"] })` のように起動時は縮退を許し、セッション開始後に `session.requestReferenceSpace("bounded-floor")` を試します。失敗したら `local-floor`、さらに失敗したら `local` や `viewer` へ順に落とし、どの空間で動いているかをログに残します。`bounded-floor` では `boundsGeometry` を使って floor hit を判定し、`local-floor` では半径、障害物、利用者の向きなどを別途持つのが現実的です。

A production path can start permissively with `requestSession(mode, { optionalFeatures: ["bounded-floor"], requiredFeatures: ["local-floor"] })`, then call `session.requestReferenceSpace("bounded-floor")` after session start. If that fails, fall back to `local-floor`, then `local` or `viewer`, and log the active space. With `bounded-floor`, use `boundsGeometry` to test floor hits; with `local-floor`, keep a separate radius, obstacle, and orientation policy.

俯瞰メモBird's-eye memo

昨日までは起動前の feature negotiation、今日は起動後に `requestReferenceSpace()` がどこまで成立したかを扱いました。XR の体験品質は描画だけでなく、「どの空間で責任を持って動いているか」をユーザーに返せるかで大きく変わります。`bounded-floor`、`local-floor`、`viewer` を同じ移動 UI で扱うと、理想端末向けの体験とフォールバック体験の差分が見えるようになります。

Yesterday focused on pre-launch feature negotiation; today focuses on how far post-launch `requestReferenceSpace()` resolution succeeds. Handling `bounded-floor`, `local-floor`, and `viewer` inside the same locomotion UI makes the gap between ideal-device behavior and fallback behavior visible.
