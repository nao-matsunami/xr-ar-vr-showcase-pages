今日の重要トピックKey topics today

  1. W3C の WebXR Device API 最新公開版は 2026-06-09 の Candidate Recommendation Draft で、入力章には `XRInputSource`、transient input、`XRInputSourcesChangeEvent` がまとまっている。 The latest published W3C WebXR Device API is the 2026-06-09 Candidate Recommendation Draft, whose input chapter covers `XRInputSource`, transient input, and `XRInputSourcesChangeEvent`.
  2. WebXR Input Profiles は、既知ハードウェアの `XRInputSource` conformance 情報、registry、assets、helper library を扱う一次情報で、特定デバイス名への直書きを避けるための土台になる。 WebXR Input Profiles provides primary information for known hardware conformance, registries, assets, and helper libraries, reducing the need to hardcode device names.
  3. Motion Controllers library は、`XRInputSource.profiles` から最適 profile を探し、trigger / squeeze / thumbstick / button などの component 状態を `gamepad` から更新する設計を示している。 The Motion Controllers library shows how to find the best profile from `XRInputSource.profiles` and update trigger, squeeze, thumbstick, and button components from `gamepad` state.
  4. Input Profiles assets は CDN 経由の profile / model 取得を想定するため、asset が遅い、profile が generic に落ちる、unknown device になる場合の一時表示が必要になる。 Input Profiles assets are commonly fetched from a CDN, so apps need temporary visuals for slow assets, generic fallbacks, and unknown devices.
  5. 公式 input-profiles sample は controller model 表示の参照に有用だが、今日の公開カードでは外部デモではなく、ワークスペース内の binding watchdog サンプルを中心にした。 The official input-profiles sample is useful as a controller-model reference, but today's public card centers the workspace's original binding watchdog sample.

Today's notable reference is the combination of WebXR Input Profiles and Motion Controllers. It is not a flashy spatial demo, but it covers a practical core: finding the best profile from the ordered `XRInputSource.profiles` list, loading JSON profile data and asset paths, then mapping `gamepad.buttons` and `gamepad.axes` to trigger, squeeze, thumbstick, and other components. The interesting part is that controller visualization and action binding can be stabilized from the same profile data.

制作に使えそうな技術メモProduction note

`inputsourceschange` で MotionController を作成し、削除時に release する流れを基本にすると、session 中の controller 交換に耐えやすくなります。`fetchProfile()` 相当の処理は非同期なので、profile / asset が届くまで silhouette や ray-only 表示を先に出す設計が必要です。`updateFromGamepad()` 相当の component 更新では、button の `pressed` / `touched` / value と axes deadzone を action binding の前段に置き、trigger と squeeze が同時に入る場合は二重発火を抑制する層を挟むと安全です。

A robust implementation creates a MotionController on `inputsourceschange` and releases it when the source is removed, which makes controller swapping during a session easier to handle. Because `fetchProfile()`-style work is asynchronous, the app should render silhouettes or ray-only hints before profile and asset data arrive. In an `updateFromGamepad()`-style component update, button `pressed` / `touched` / value and axes deadzones should sit before action binding, with a suppression layer for simultaneous trigger and squeeze input.
