今日の重要トピックKey topics today

  1. WebXR Layers API Editor's Draft は 2026-08-11 版で、composition layer の利点として compositor rate、可読性、電力、レイテンシを整理し、`layers` feature descriptor、`XRWebGLBinding` / `XRMediaBinding`、`updateRenderState({ layers })` の流れを示しています。 The WebXR Layers API Editor's Draft dated 2026-08-11 summarizes composition-layer benefits around compositor-rate presentation, legibility, power, and latency, and shows the flow through the `layers` feature descriptor, `XRWebGLBinding` / `XRMediaBinding`, and `updateRenderState({ layers })`.
  2. Immersive Web の Layer Hit Test サンプルは、quad / cylinder / equirect / cube layer が projection layer に存在しないため直接 hit test できず、透明 placeholder を projection layer に置く workaround を実装しています。 Immersive Web's Layer Hit Test sample implements a workaround where transparent placeholders are placed in the projection layer because quad, cylinder, equirect, and cube layers cannot be hit tested directly when they are outside that projection layer.
  3. WebXR Hit Test Module は、hit test API が現実環境への raycast を扱い、アプリ側の仮想シーングラフに対する hit test は範囲外であることを明確にしています。 The WebXR Hit Test Module makes clear that hit testing targets real-world ray intersections, while hit testing the application's own virtual scene graph is out of scope.
  4. Projection Layer with Multiview サンプルは `OCULUS_multiview` / `OVR_multiview2` と `texture-array` を前提に、左右 eye の state change を減らす方向を示しています。 The Projection Layer with Multiview sample points toward reducing per-eye state changes by using `OCULUS_multiview` / `OVR_multiview2` together with `texture-array` projection layers.
  5. 昨日の layer destroy queue の次段階として、古い layer を外すだけでなく、表示 layer と選択 proxy の transform を同じ anchor / pose 更新単位で同期する必要があります。 As a next step after yesterday's layer destroy queue, it is not enough to remove old layers; visible layers and their selection proxies need to share the same anchor or pose update cadence.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Layer Hit Proxy Sync Lab` は、quad UI、curved menu、media panel の layer 種別、transparent plane / expanded guard / one-frame stale の proxy、X drift、depth、head jitter を操作し、疑似 select ray が proxy に当たるかを確認します。confidence が落ちると proxy select から confirm reticle、DOM overlay fallback へ切り替わります。派生サンプル `Projection Multiview Budget Meter` は、multiview extension、texture-array、view 数、scene complexity、MSAA samples を切り替え、draw route、state changes、GPU spare を表示します。

制作に使えそうな技術メモProduction note

実装では、composition layer の transform と projection layer 内 proxy mesh の transform を別々に持たず、同じ pose record から生成するのが安全です。proxy は layer より少し広げる余地がありますが、広げすぎると誤選択が増えるため、confidence、confirm reticle、fallback route をログに残します。multiview は `gl.getExtension('OCULUS_multiview')` または `gl.getExtension('OVR_multiview2')` と `createProjectionLayer({ textureType: 'texture-array' })` の組み合わせを前提にし、未対応時は per-eye redraw へ落とす判定を明示します。

In production, avoid maintaining independent transforms for a composition layer and its projection-layer proxy mesh; generate both from the same pose record. A proxy can be slightly expanded, but excessive expansion increases false selection, so confidence, confirm-reticle routing, and fallback reasons should be logged. Multiview should be treated as a combination of `gl.getExtension('OCULUS_multiview')` or `gl.getExtension('OVR_multiview2')` plus `createProjectionLayer({ textureType: 'texture-array' })`; when unsupported, route explicitly to per-eye redraw.

俯瞰メモBird's-eye memo

ここ数日の流れは feature negotiation、bounded space、可読性、haptics、layer lifecycle と進み、今日は layer と入力の接点に移りました。XR の UI は見えているだけでは不十分で、選択できる面と描画される面の時間差や座標差を小さく保つ必要があります。proxy drift を数値化しておくと、DOM Overlay、haptic confirmation、anchor recovery、destroy queue のどれへ進むべきかを一つの判定にできます。

Recent work moved through feature negotiation, bounded spaces, readability, haptics, and layer lifecycle; today shifts to the junction between layers and input. XR UI is not complete just because it is visible; the selectable surface and the rendered surface must stay close in time and coordinates. Quantifying proxy drift makes it possible to choose between DOM Overlay, haptic confirmation, anchor recovery, and destroy queue from a single verdict.

今日のミニ試作候補Today's mini prototype candidate

本命として採用した候補は `Layer Hit Proxy Sync Lab` です。何が動くか: layer 種別、proxy 種別、ずれ、奥行き、頭部 jitter を変え、疑似 select ray の hit / miss と fallback route を確認できます。次に足すなら、実際の `select` event、`XRInputSource.targetRaySpace`、anchor id、`session.updateRenderState()` 前後の transform ログを入れます。派生として `Projection Multiview Budget Meter` も実装しました。何が動くか: multiview extension と texture-array の有無から draw route、state changes、GPU spare を見積もります。次に足すなら、実 WebGL2 context の extension probe と、実機の frame timing / dropped frame ログを足します。

The selected main prototype is `Layer Hit Proxy Sync Lab`. What it does: change layer type, proxy type, drift, depth, and head jitter, then inspect simulated select-ray hit/miss and fallback routing. Next additions would be real `select` events, `XRInputSource.targetRaySpace`, anchor IDs, and transform logs before and after `session.updateRenderState()`. The derivative `Projection Multiview Budget Meter` was also implemented. What it does: estimate draw route, state changes, and GPU spare from multiview extension and texture-array availability. Next additions would be a real WebGL2 extension probe plus device frame timing and dropped-frame logs.
