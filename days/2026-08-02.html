今日の重要トピックKey topics today

  1. WebXR Gamepads Module Level 1 は 2025-07-07 の Working Draft で、`XRInputSource.gamepad` と `xr-standard` mapping の制約を整理している。 The WebXR Gamepads Module Level 1 Working Draft dated 2025-07-07 defines constraints for `XRInputSource.gamepad` and the `xr-standard` mapping.
  2. `xr-standard` では `buttons[0]` が primary trigger、`buttons[1]` が primary squeeze、`axes[2]` / `axes[3]` が primary thumbstick として扱われるため、action map の既定値を作りやすい。 In `xr-standard`, `buttons[0]` maps to the primary trigger, `buttons[1]` to primary squeeze, and `axes[2]` / `axes[3]` to the primary thumbstick, giving apps a useful default action map.
  3. WebXR Input Profiles / Motion Controllers は、profile matching、component enumeration、asset path、`updateFromGamepad()` による frame 更新を実装の単位として示している。 WebXR Input Profiles / Motion Controllers frame profile matching, component enumeration, asset paths, and `updateFromGamepad()` as practical implementation units.
  4. DOM Overlays Module の `beforexrselect` は、overlay UI 操作中に WebXR の `selectstart` / `selectend` / `select` を抑制できるため、DOM click と XR select の二重発火を避ける鍵になる。 The DOM Overlays Module `beforexrselect` event can suppress WebXR `selectstart` / `selectend` / `select` while users interact with overlay UI, avoiding duplicate DOM and XR actions.
  5. 公式サンプルや profile viewer は参照として有用だが、今日の公開カードでは、入力の優先順位そのものを触れる自作サンプルに絞った。 Official samples and profile viewers remain useful references, but today's public card focuses on the original interactive priority-matrix sample.

注目事例と何が面白いかNotable example and why it matters

今日の注目は、WebXR Gamepads Module の `xr-standard` mapping と、Input Profiles / Motion Controllers の component abstraction、さらに DOM Overlay の `beforexrselect` を一つの入力経路として並べて見ることです。個別には controller model 表示、button 読み取り、overlay UI 抑制という地味な機能ですが、実際の XR アプリでは「右 trigger の select」「左 squeeze の grab」「手の pinch」「thumbstick の移動」「DOM overlay の click」が同じ瞬間に衝突します。ここを優先順位表として見える化すると、入力バグの再現条件を言語化しやすくなります。

Today's notable thread is looking at the WebXR Gamepads Module `xr-standard` mapping, the Input Profiles / Motion Controllers component abstraction, and DOM Overlay `beforexrselect` as one input route. Individually these are quiet primitives, but real XR apps often receive right-trigger select, left-squeeze grab, hand pinch, thumbstick locomotion, and DOM overlay clicks at overlapping times. Visualizing that as a priority matrix makes input bugs easier to reproduce and discuss.

表現・インタラクションのアイデアExpression and interaction idea

今日のサンプルでは、左右 controller の trigger / squeeze、左右 thumbstick、hand pinch、tracking confidence、overlay coverage、deadzone を調整できます。中央の target に対して、select、grab、pinch、hover、teleport preview、strafe のどれが勝つかを毎フレーム再計算します。overlay coverage を上げて右側を指すと、`beforexrselect` による select 抑制が発生し、trigger が強くても world select が負ける様子を確認できます。

The sample exposes trigger/squeeze values for both controllers, left/right thumbstick axes, hand pinch, tracking confidence, overlay coverage, and deadzone. Each frame recomputes whether select, grab, pinch, hover, teleport preview, or strafe should win against the central target. Increasing overlay coverage while pointing at the right side demonstrates `beforexrselect` suppression, where a strong trigger input can still lose to overlay blocking.

制作に使えそうな技術メモProduction note

`XRInputSource.gamepad.mapping === "xr-standard"` のときだけ固定 index を信用し、それ以外は Input Profiles の component 情報へ寄せる設計がよさそうです。action binding の直前には deadzone、pressed / touched / value、tracking confidence、handedness、DOM overlay blocking を別々の gate として置き、最後に select / squeeze / pinch の duplicate suppression を走らせると事故が少ないです。DOM Overlay は DOM event と XR event の順序が同期されない前提で、ログや state machine を設計する必要があります。

A practical design should trust fixed indices only when `XRInputSource.gamepad.mapping === "xr-standard"`, and otherwise lean on Input Profiles component metadata. Before action binding, keep deadzone, pressed/touched/value, tracking confidence, handedness, and DOM overlay blocking as separate gates, then run duplicate suppression for select/squeeze/pinch. DOM Overlay code should assume DOM events and XR events are not synchronized in ordering.
