今日の重要トピックKey topics today

  1. WebXR Gamepads Module は XRInputSource に関連するボタン、トリガー、スティック、タッチパッドの値を扱うための仕様である。 The WebXR Gamepads Module exposes controller input associated with XRInputSource.
  2. 入力の value、pressed、touched は状態であり、アプリ側では preview と commit の閾値・解除条件を明示する必要がある。 Value, pressed, and touched are state; apps must define preview and commit rules.
  3. 入力源や実装によって gamepad や振動出力は利用できないため、未対応を成功扱いにしないフォールバックが必要である。 Gamepads and vibration output are optional, so fallbacks must be honest.
  4. 触覚は確認音を増やす用途より、方向・確定・境界警告を少数の区別できる合図として設計すると過剰通知を避けやすい。 Sparse directional, confirmation, and boundary cues avoid alert fatigue.
  5. 重要な停止や境界警告は触覚だけに依存せず、視覚・音・安全な操作中断を組み合わせる。 Critical warnings need visual, audio, and safe-stop paths as well as haptics.

注目事例と何が面白いかNotable example and why it matters

W3C の WebXR Gamepads Module は、XRInputSource に結び付く gamepad からボタン、トリガー、スティック、タッチパッドの状態を取得する土台です。公式 Controller State サンプルは入力を読み取る入口として有用ですが、本日の公開面は外部デモの一覧ではなく自作の判断実験に置きます。本命では value を 0.25 / 0.58 / 1.00 と変え、値そのものではなく preview と commit、さらに触覚が利用できたかを別々に表示します。

The main prototype turns raw input values into explicit preview, commit, and haptic-availability receipts.

表現・インタラクションのアイデアExpression and interaction idea

本命は軽い押下で ghost marker を見せ、閾値を越えたときだけ marker を確定する構成です。触覚を試す操作では、実機の actuator が見つかれば小さな要求を送り、見つからなければ画面の pulse に正直に落とします。派生は GUIDE、CONFIRM、WARNING をクリックして cue の残り予算を消費します。urgent では案内を抑え、境界警告の1枠を残すため、触覚を単なる装飾ではなく注意資源として扱えます。

One prototype gates a placement commit; the other reserves sparse tactile attention for critical cues.

制作に使えそうな技術メモProduction note

実機の XRFrame では inputSources を走査し、XRInputSource.gamepad が存在する入力源だけを読む設計にします。buttons の value / pressed / touched と targetRayMode、handedness、select 系イベントを混同せず、入力源ごとの短い状態機械にします。振動は Gamepad API 側の actuator が公開される場合だけ試行し、Promise の成功を体験の成功と見なさず、OS・端末・ブラウザの方針で出力されない前提にします。

Read only exposed gamepads, keep per-source state machines, and treat actuator results as capability evidence rather than guaranteed sensation.

サンプルデータの可能性と組み合わせSample data potential and combinations

この2本から再利用できるのは、入力強度そのものではなく、preview→commit、cue の種類、抑制理由、出力可否という小さな receipt です。作業ARなら固定手順の確定と危険域警告、展示なら方向案内と音のアクセント、遠隔支援なら通信遅延時に触覚を減らして画面表示を優先するポリシーに接続できます。個人の手の動きの生ログを保存せず判断だけを残せる点も扱いやすいです。

Decision receipts can support work AR, installations, and remote assistance without retaining raw hand-motion logs.

俯瞰メモBird's-eye memo

XR の入力はボタンの値だけでは体験の意図を表しません。押し込み、見通し、手の切替、解除、環境の安全性をまたいで初めて「実行してよい」状態になります。触覚もまた、鳴らせるかではなく、限られた注意をいつ残すかという設計です。少ない合図を明確な意味に結び、未対応なら静かに別の感覚へ渡すことが、端末差の大きいWebXRで信頼を作ります。

Input and haptics are intent and attention design, not merely hardware capability.
