今日の重要トピックKey topics today

  1. WebXR Layers API では getViewSubImage() が view ごとの XRWebGLSubImage を返し、opaque texture、viewport、imageIndex を描画単位にします。 In WebXR Layers API, getViewSubImage() returns a per-view XRWebGLSubImage, making opaque textures, viewport, and imageIndex the rendering unit.
  2. Layers の explainer は getSubImage() / getViewSubImage() が XR frame 中だけ有効な texture を返すことを示しており、保存すべきなのは texture 本体ではなく寸法や route の row です。 The Layers explainer shows that getSubImage() / getViewSubImage() return textures that are only valid during the XR frame, so the persisted data should be dimensions and routes, not the texture itself.
  3. MDN の fixedFoveation は 0 から 1 の範囲で compositor 側 foveation を扱い、端の解像度低下と GPU 負荷の tradeoff を説明します。 MDN fixedFoveation describes compositor-side foveation in a 0 to 1 range, framing the tradeoff between lower edge resolution and GPU load.
  4. 昨日の viewport crop guard と9月27日の attachment size audit をつなぐには、subimage row を同じ粒度で IndexedDB / JSON 化するのが扱いやすいです。 To connect yesterday's viewport crop guard with the September 27 attachment-size audit, subimage rows should be saved at the same IndexedDB / JSON granularity.
  5. 今日の公開カードは外部デモではなく、自作の `Subimage Viewport IndexedDB Bridge` と `Attachment Crop Merge Policy Replayer` の2本です。 Today's public cards are the original workspace samples `Subimage Viewport IndexedDB Bridge` and `Attachment Crop Merge Policy Replayer`, not external demos.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Subimage Viewport IndexedDB Bridge` は subimage scale、viewport scale、drift、foveation、attachment を動かし、`record-subimage-row`、`guarded-viewport-row`、`depth-only-row`、`projection-fallback-row` を出します。派生サンプル `Attachment Crop Merge Policy Replayer` はその JSON row を貼り付け、tile ごとに `native-submit`、`patch-crop`、`hold-depth`、`projection-fallback` を再判定します。

The main sample, `Subimage Viewport IndexedDB Bridge`, lets you change subimage scale, viewport scale, drift, foveation, and attachment availability, then emits `record-subimage-row`, `guarded-viewport-row`, `depth-only-row`, or `projection-fallback-row`. The derivative `Attachment Crop Merge Policy Replayer` accepts that JSON row and reclassifies each tile into `native-submit`, `patch-crop`, `hold-depth`, or `projection-fallback`.

制作に使えそうな技術メモProduction note

実装するなら XR frame callback 内で `getViewSubImage(layer, view)` または `baseLayer.getViewport(view)` の直後に、viewport、texture size、imageIndex、depth / motion attachment の有無、foveation、frame timestamp だけを保存します。opaque texture の pixel data を読もうとせず、後段の policy replay に必要な軽量 row へ変換する設計が安全です。

In production, save only viewport, texture size, imageIndex, depth / motion attachment presence, foveation, and frame timestamp immediately after `getViewSubImage(layer, view)` or `baseLayer.getViewport(view)` inside the XR frame callback. Do not try to read opaque texture pixel data; convert the result into lightweight rows needed by later policy replay.
