今日の重要トピックKey topics today

  1. WebXR Layers API Level 1 は `XRWebGLSubImage` に color texture、depth-stencil texture、motion vector texture を結び、`getSubImage()` / `getViewSubImage()` のタイミングと opaque texture の扱いを定義しています。 WebXR Layers API Level 1 connects color texture, depth-stencil texture, and motion-vector texture to `XRWebGLSubImage`, and defines `getSubImage()` / `getViewSubImage()` timing plus opaque texture handling.
  2. `space-warp` では depth-stencil と motion-vector texture が同じ寸法を持つ一方、color texture とは異なる寸法になり得るため、row にサイズを残す価値があります。 For `space-warp`, depth-stencil and motion-vector textures have the same dimensions, while those dimensions may differ from the color texture, so preserving sizes in a row is useful.
  3. motion vector texture または depth-stencil texture が frame 処理中に提出されない場合、その frame は space warp が無効だったように処理されるため、欠落は即座に route へ反映します。 If either the motion-vector texture or depth-stencil texture is not submitted during frame processing, that frame is processed as if space warp were disabled, so missing data should immediately affect routing.
  4. MDN の WebXR rendering 解説は XR frame callback の時間予算と dropped frame の問題を整理しており、attachment audit を frame pressure と合わせて見る根拠になります。 MDN's WebXR rendering guide explains XR frame callback budgets and dropped frames, which makes it useful to combine attachment audit rows with frame pressure.
  5. 今日の公開カードは外部デモではなく、自作の `XRWebGLSubImage Attachment Size Auditor` と `Warp Tile Coverage Import Mixer` の2本です。 Today's public cards are the original workspace samples `XRWebGLSubImage Attachment Size Auditor` and `Warp Tile Coverage Import Mixer`, not external demos.

注目事例と何が面白いかNotable example and why it matters

昨日は `redraw` event と XR frame timestamp を recovery row として保存しました。今日はその row に、実装で詰まりやすい `XRWebGLSubImage` の texture 寸法を足します。Layers API の space-warp では depth-stencil と motion-vector texture が同じ寸法で、color texture と違ってよいという重要な条件があります。ここを監査できると、warp を止めた理由が `イベント` だけでなく `提出した attachment の形` として説明できます。

Yesterday stored `redraw` events and XR frame timestamps as recovery rows. Today adds one of the implementation details that often causes trouble: `XRWebGLSubImage` texture dimensions. In the Layers API space-warp path, depth-stencil and motion-vector textures share dimensions, and those dimensions may differ from the color texture. Auditing that shape explains warp fallback not only as an event, but as the actual attachment contract submitted for a frame.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `XRWebGLSubImage Attachment Size Auditor` は color texture の幅と高さ、attachment scale、depth / motion vector の鮮度を操作し、`warp-ready`、`patch-then-submit`、`coarse-vector-warning`、`disable-space-warp` を出します。派生サンプル `Warp Tile Coverage Import Mixer` はその row JSON を貼り付け、32個の tile に coverage を分配して `use-vector`、`patch-vector`、`hold-depth`、`disable-warp` の混合を見ます。

The main sample, `XRWebGLSubImage Attachment Size Auditor`, lets you change color texture width and height, attachment scale, and depth / motion-vector freshness, then emits `warp-ready`, `patch-then-submit`, `coarse-vector-warning`, or `disable-space-warp`. The derivative `Warp Tile Coverage Import Mixer` accepts that row JSON, distributes coverage across 32 tiles, and shows the mix of `use-vector`, `patch-vector`, `hold-depth`, and `disable-warp`.

制作に使えそうな技術メモProduction note

実装では `getViewSubImage()` の直後に color width / height と depth-stencil width / height を row に入れ、motion vector が取れる場合は同じ frame id で availability を保存します。depth と motion の片方だけ欠けた frame は warp を継続せず、tile coverage の patch 判定へ渡すか、projection fallback に落とします。XR frame callback は時間予算が短いため、監査 row は最小フィールドで作り、後段の replay 側で詳細分類するのが扱いやすいです。

In production, store color width / height and depth-stencil width / height immediately after `getViewSubImage()`, and attach motion-vector availability to the same frame id when available. If either depth or motion is missing, do not continue warp; pass the row to tile coverage patching or fall back to projection. Because XR frame callbacks have a tight budget, keep audit rows minimal and perform detailed classification in a replay stage.
