今日の重要トピックKey topics today

  1. WebXR DOM Overlays Module は `beforexrselect` を定義し、DOM overlay 上の操作が XR の `selectstart` / `select` / `selectend` に重複して流れるのを抑える入口になります。 The WebXR DOM Overlays Module defines `beforexrselect`, giving applications an entry point for suppressing duplicate `selectstart` / `select` / `selectend` events when a DOM overlay owns an action.
  2. MDN の `beforexrselect` ページは 2026年時点で実装上の使いどころを整理しており、overlay container で `preventDefault()` する基本パターンを確認できます。 MDN's `beforexrselect` page explains the practical pattern of calling `preventDefault()` on an overlay container.
  3. MDN WebXR input guide は `targetRaySpace`、`gripSpace`、input source、profile を分けて説明しており、DOM と world の所有権を行単位に分ける設計に向いています。 MDN's WebXR input guide separates `targetRaySpace`, `gripSpace`, input sources, and profiles, which supports row-level ownership between DOM and world interactions.
  4. W3C WebXR Hand Input Module は articulated hand poses を Device API に足す仕様で、hand pinch が DOM overlay と world reticle のどちらを触ったかを confidence 付きで扱う理由になります。 The W3C WebXR Hand Input Module adds articulated hand poses to the Device API, motivating confidence-based routing between hand pinch, DOM overlay, and world reticle targets.
  5. 今日の公開カードは外部デモではなく、自作の `DOM Overlay Select Arbitration Logger` と `Hand Overlay Reach Envelope Router` の2本です。 Today's public cards are the original workspace samples `DOM Overlay Select Arbitration Logger` and `Hand Overlay Reach Envelope Router`, not external demos.

注目事例と何が面白いかNotable example and why it matters

9月22日は起動前後の `navigator.xr` probe を session context と trust floor にしました。今日はその次に、起動後の最初の UI 操作で起きやすい `DOM のボタンを押したつもりなのに XR world select も走る` 問題を扱います。DOM Overlay の `beforexrselect` は、DOM UI と XR world の所有権を入力シーケンスの前に分けられるので、frame logger に `なぜこの select を信じたか / 捨てたか` を残しやすいのが面白いところです。

September 22 turned the `navigator.xr` bootstrap probe into session context and a trust floor. Today moves to a common post-launch problem: the user intended to press a DOM button, but an XR world select may also fire. DOM Overlay's `beforexrselect` lets the app separate DOM UI and XR world ownership before the input sequence commits, which makes it easier for a frame logger to explain why a select was trusted or dropped.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `DOM Overlay Select Arbitration Logger` は input source、overlay hit、`beforexrselect` の状態、ray confidence、overlay opacity を操作し、`dom-consume`、`xr-select`、`dual-guard`、`drop` の arbitration row を出します。派生サンプル `Hand Overlay Reach Envelope Router` は hand joint confidence、pinch closure、pose jitter、intent zone を使い、hand pinch / controller / gaze を overlay UI、world reticle、preview、block に割り振ります。

The main sample, `DOM Overlay Select Arbitration Logger`, lets you adjust input source, overlay hit, `beforexrselect` state, ray confidence, and overlay opacity, then emits `dom-consume`, `xr-select`, `dual-guard`, or `drop` arbitration rows. The derivative sample, `Hand Overlay Reach Envelope Router`, uses hand joint confidence, pinch closure, pose jitter, and intent zone to route hand pinch / controller / gaze input into overlay UI, world reticle, preview, or block.

制作に使えそうな技術メモProduction note

実装では、DOM overlay の touchable 領域だけで `beforexrselect.preventDefault()` し、非インタラクティブなラベルや透明余白は pass-through にする方が、AR 空間の world select を不必要に塞ぎません。hand input は `XRHand` が取れる時だけを前提にせず、controller ray、screen transient、gaze select を同じ route schema に入れておくと、端末差があっても replay と説明が崩れにくくなります。

In production, call `beforexrselect.preventDefault()` only in touchable DOM overlay regions, while allowing non-interactive labels and transparent margins to pass through so AR world selection is not blocked unnecessarily. For hand input, do not assume `XRHand` is always present; placing controller rays, screen transient input, and gaze select into the same route schema keeps replay and explanation stable across devices.

試すならこれIf you try one thing

`DOM Overlay Select Arbitration Logger` で overlay hit を `button`、`beforexrselect` を `preventDefault` にして `Append event` を押すと、DOM が所有する select row が出ます。次に `beforexrselect` を `missing` に変えると `dual-guard` に落ち、同じ入力を DOM と XR world に二重 commit しないための guard が見えます。派生側では `edge between` と jitter 高めを試すと preview route に落ちます。

In `DOM Overlay Select Arbitration Logger`, set overlay hit to `button`, set `beforexrselect` to `preventDefault`, and press `Append event` to create a DOM-owned select row. Change `beforexrselect` to `missing` and it falls to `dual-guard`, showing how to avoid double-committing the same input to DOM and the XR world. In the derivative sample, try `edge between` with higher jitter to see the preview route.
