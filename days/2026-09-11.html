今日の重要トピックKey topics today

  1. W3C WebXR Depth Sensing Module の最新版は 2026-08-25 Working Draft で、`depth-sensing` feature、`depthSensing` session init、CPU / GPU usage、depth format preference、`matchDepthView` を整理しています。 The latest W3C WebXR Depth Sensing Module is the 2026-08-25 Working Draft, covering the `depth-sensing` feature, `depthSensing` session init, CPU / GPU usage, depth format preferences, and `matchDepthView`.
  2. Depth Sensing は real world geometry までの距離を XR device から得る拡張で、用途として occlusion、仮想物体と現実環境の物理反応、非視覚的な環境理解が挙げられています。 Depth Sensing extends WebXR with distance information to real-world geometry, with use cases including occlusion, physical interaction between virtual objects and the real environment, and non-visual environment awareness.
  3. `XRCPUDepthInformation` は `ArrayBuffer` と `getDepthInMeters()`、`XRWebGLDepthInformation` は depth texture を扱い、raw 値は `rawValueToMeters` で meter に変換します。 `XRCPUDepthInformation` exposes an `ArrayBuffer` and `getDepthInMeters()`, while `XRWebGLDepthInformation` exposes a depth texture; raw values are converted to meters through `rawValueToMeters`.
  4. `depthActive` が false の場合は depth data 取得を拒否する設計なので、アプリ側は pause / resume、frame age、view alignment、holes を見て fallback を用意する必要があります。 Because attempts to obtain depth data are rejected when `depthActive` is false, applications need fallbacks based on pause / resume state, frame age, view alignment, and depth holes.
  5. 今日の公開カードは外部デモではなく、このワークスペース内で作った `Depth Sensing Confidence Gate` と `Depth Occlusion Threshold Mixer` の2本です。 Today's public cards focus on the original workspace samples `Depth Sensing Confidence Gate` and `Depth Occlusion Threshold Mixer`, not external demos.

注目事例と何が面白いかNotable example and why it matters

今日の注目は WebXR Depth Sensing Module と、Immersive Web Samples の AR Depth Sensing GPU / CPU proposal sample です。仕様は `depth-sensing` を session feature として要求し、usage preference と data format preference によって CPU buffer か GPU texture かを選ぶ流れを示しています。面白いのは、depth が単なる見た目の mask ではなく、frame が active か、view と depth buffer が対応しているか、raw 値を meter に直せるか、privacy / performance 上 pause されていないかという運用判断を伴う点です。公式サンプルは depth 取得の基準として参照し、公開カードの中心はこのワークスペース内の信頼度ゲートと occlusion 閾値ミキサーにしました。

Today's notable references are the WebXR Depth Sensing Module and the AR Depth Sensing GPU / CPU proposal samples from Immersive Web Samples. The specification presents depth sensing as a session feature, with usage and data-format preferences selecting CPU buffers or GPU textures. The interesting part is that depth is not just a visual mask: it depends on whether the frame is active, the depth buffer matches the view, raw values can be converted to meters, and the feature has not been paused for privacy or performance reasons. The official samples are used as acquisition references, while the public cards center on the original workspace confidence gate and occlusion threshold mixer.

制作に使えそうな技術メモProduction note

実機版では `navigator.xr.requestSession('immersive-ar', { requiredFeatures: ['depth-sensing'], depthSensing: { usagePreference, dataFormatPreference, depthTypeRequest } })` を起点にし、session の `depthUsage`、`depthDataFormat`、`depthType`、`depthActive` をログに残します。CPU route では `XRFrame.getDepthInformation(view)` から `XRCPUDepthInformation.data` または `getDepthInMeters()` を使い、GPU route では `XRWebGLBinding.getDepthInformation(view)` の texture を shader へ渡す設計にします。`matchDepthView` が false の時や frame が古い時は、depthInfo の view と現在 view の差を補正するか、mask を1-2 frame 保持する fallback が必要です。

A device-backed version should start with `navigator.xr.requestSession('immersive-ar', { requiredFeatures: ['depth-sensing'], depthSensing: { usagePreference, dataFormatPreference, depthTypeRequest } })`, then log the session's `depthUsage`, `depthDataFormat`, `depthType`, and `depthActive`. The CPU route can use `XRFrame.getDepthInformation(view)` with `XRCPUDepthInformation.data` or `getDepthInMeters()`, while the GPU route should pass the texture from `XRWebGLBinding.getDepthInformation(view)` into a shader. When `matchDepthView` is false or the frame is old, the app should either compensate for the difference between depthInfo's view and the current view or hold the mask for one or two frames.

試すならこれIf you try one thing

`Depth Sensing Confidence Gate` で frame age を 180ms 近く、view alignment error を 45px 以上、または `matchDepthView` を off にすると `HOLD FRAME` に寄ります。depthActive を off、または usage を not enabled にすると `BLOCK DEPTH` になります。`Depth Occlusion Threshold Mixer` では virtual depth と real surface depth を近づけ、feather を増やすと `FEATHER EDGE`、holes と noise を増やすと `BIAS + HOLD` に変わります。

In `Depth Sensing Confidence Gate`, raise frame age toward 180ms, push view alignment above 45px, or turn `matchDepthView` off to move toward `HOLD FRAME`; turn off depthActive or set usage to not enabled to get `BLOCK DEPTH`. In `Depth Occlusion Threshold Mixer`, move virtual depth and real surface depth close together and increase feather for `FEATHER EDGE`; increase holes and noise to switch to `BIAS + HOLD`.
