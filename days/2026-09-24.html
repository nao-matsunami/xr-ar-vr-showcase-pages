注目事例と何が面白いかNotable example and why it matters

9月23日は DOM Overlay と XR world select の二重発火を arbitration row にしました。今日はその次の段階として、DOM Overlay の text field や button に残った focus を、いつ XR world reticle へ返してよいかを扱います。`beforexrselect` は action の衝突を止める入口ですが、実アプリでは keyboard intent、overlay state、visibility、ray confidence が揃わないと、復帰したつもりの select が DOM に残ったり world に二重 commit されたりします。そこを matrix と ledger にするのが今日の面白い点です。

September 23 turned duplicate DOM Overlay and XR world select events into arbitration rows. Today takes the next step: deciding when focus left on a DOM Overlay text field or button can safely return to the XR world reticle. `beforexrselect` is the entry point for stopping action collisions, but production apps also need keyboard intent, overlay state, visibility, and ray confidence. Without those, a supposedly recovered select can stay in DOM or double-commit to the world. Today's samples make that recovery visible as a matrix and ledger.

表現・インタラクションのアイデアExpression and interaction idea

本命サンプル `Overlay Focus Recovery Matrix` は focus owner、`beforexrselect`、`domOverlayState`、visibility、keyboard intent、ray confidence を操作し、`dom-focus`、`dom-action`、`world-resume`、`recover-focus`、`dual-guard`、`hold-hidden` を出します。派生サンプル `Pinch Gaze Intent Debounce Replayer` は hand pinch、gaze dwell、DOM hover が近いタイミングで発生した時に、`pinch-commit`、`gaze-commit`、`dom-suppress-xr`、`intent-merge`、`split-guard`、`preview-hold` のどれに落とすかを replay します。

The main sample, `Overlay Focus Recovery Matrix`, lets you adjust focus owner, `beforexrselect`, `domOverlayState`, visibility, keyboard intent, and ray confidence, then emits `dom-focus`, `dom-action`, `world-resume`, `recover-focus`, `dual-guard`, or `hold-hidden`. The derivative sample, `Pinch Gaze Intent Debounce Replayer`, replays nearby hand pinch, gaze dwell, and DOM hover events and classifies them as `pinch-commit`, `gaze-commit`, `dom-suppress-xr`, `intent-merge`, `split-guard`, or `preview-hold`.

制作に使えそうな技術メモProduction note

DOM Overlay を使う時は、単に `preventDefault()` したかどうかだけでなく、active element、keyboard composition、session visibility、`domOverlayState.type`、target ray pose の新鮮さを同じ row に保存すると、あとから replay しやすくなります。gaze と hand pinch が同時に来る端末では、数十 ms の debounce window を持ち、同一 target なら merge、別 target なら guard、DOM hover が強ければ XR select を suppress する、といった policy を JSON として持つと調整しやすいです。

When using DOM Overlay, record not only whether `preventDefault()` happened, but also the active element, keyboard composition, session visibility, `domOverlayState.type`, and target ray pose freshness in the same row. That makes later replay much easier. On devices where gaze and hand pinch can arrive together, keep a small debounce window: merge when they agree on the same target, guard when they point to different targets, and suppress XR select when DOM hover has strong ownership. Keeping that policy as JSON makes it tunable.

俯瞰メモBird's-eye memo

9月後半の流れは、起動前の trust、起動直後の session context、DOM Overlay の select arbitration、そして focus 復帰へ進んでいます。XR UI の難しさは `押す対象` だけでなく、DOM、world、hand、gaze、keyboard が短い時間窓で同じ intent を共有する点です。今日の2本は、その共有を `いつ返すか` と `どれを勝たせるか` に分け、後で実機ログに差し替えられる形にした部品です。

The late-September thread now runs from pre-launch trust to post-launch session context, DOM Overlay select arbitration, and focus recovery. XR UI is difficult not only because of what is pressed, but because DOM, world, hand, gaze, and keyboard can share the same intent in a short time window. Today's two samples split that problem into when to return ownership and which intent wins, while keeping the shape replaceable with real device logs later.
